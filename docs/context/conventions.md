# Conventions

`relay` contains almost no conventional source code — the artifacts are
markdown + JSON. The conventions below apply to those artifacts.

## Plugin / marketplace manifests

- `.claude-plugin/marketplace.json` at the repo root lists plugins with
  `name`, `source` (relative path), and `description`.
- `plugins/<plugin>/.claude-plugin/plugin.json` carries the plugin's own
  `name`, `version`, `description`, and `author` block.
- Field names use camelCase where Claude Code defines them; owner/author
  blocks use `name` and `email`.

## Skills

Each skill lives at `plugins/<plugin>/skills/<skill-name>/SKILL.md` and
begins with YAML frontmatter:

```yaml
---
name: context-builder
description: Short, imperative description used by the harness for invocation matching.
---
```

Optional frontmatter fields observed in reference material (use when they
apply) [INFERRED - VALIDATE from `plugins/prp-core/skills/prp-ralph-loop/SKILL.md`]:

- `user-invocable: false` — hides the skill from user-level `/skill` listings.

## Commands

File per command under `plugins/<plugin>/commands/<name>.md`. Frontmatter
observed in prp-core reference files (use as a template when building relay
commands) [INFERRED - VALIDATE]:

```yaml
---
description: One-line user-facing description shown in the slash-command picker.
argument-hint: <path/to/thing> [--flag]
---
```

The body is the prompt. Use `$ARGUMENTS` to interpolate the user's argument
string.

## Agents

File per agent under `plugins/<plugin>/agents/<name>.md`. Frontmatter observed
in reference material [INFERRED - VALIDATE from `plugins/prp-core/agents/*.md`]:

```yaml
---
name: code-reviewer
description: When the agent should be used; used by the Agent tool to route.
model: sonnet
color: blue
---
```

The body is the agent's system prompt.

## Hooks

- Configured in `plugins/<plugin>/hooks/hooks.json` under a top-level `hooks`
  key, with one array per event (`Stop`, `PostToolUse`, etc.).
- Scripts are referenced via `${CLAUDE_PLUGIN_ROOT}` to stay portable across
  installations:
  ```json
  { "type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/hooks/my-hook.sh" }
  ```
- Hook scripts live alongside `hooks.json` in the same `hooks/` folder.

## Plugin-owned resource references

`relay`'s own agents, commands, and skills cite four distinct classes
of file path. Each class has exactly one correct citation form —
mixing them up is exactly how the eight plugin-owned resource
templates went unreachable from every installed plugin for five
releases (`PRPs/reports/plugin-root-audit/`).

- **Packaged** — `${CLAUDE_PLUGIN_ROOT}/{agents,commands,skills,
  .claude-plugin,scripts,resources}/…` must resolve inside
  `plugins/relay/` in every installed copy of the plugin — for example,
  `${CLAUDE_PLUGIN_ROOT}/resources/prd-template.md`. Only a path that
  physically lives under `plugins/relay/` may use this prefix.
- **Target-scoped** — a bare `docs/…` reference (no
  `${CLAUDE_PLUGIN_ROOT}` prefix) names the TARGET project's own copy
  — generated by `context-builder` (or, for `docs/context/design-system.md`,
  scaffolded by `/relay-design-map`) in the project relay is running
  against. Never prefix a target-scoped reference with
  `${CLAUDE_PLUGIN_ROOT}` — the plugin does not ship a `docs/` tree.
- **Source-only-prose** — content that lives in this repository's own
  source but is never packaged (`PRPs/`, and root `docs/` beyond
  `docs/context/`) is cited as prose only, e.g. `` the source PRD
  `test-runner.prd.md`, in the relay plugin repo (not packaged) `` —
  never as a resolvable token path, and never repointed at
  `${CLAUDE_PLUGIN_ROOT}/…` (that would keep the reference broken, just
  at a different path).
- **Cite-by-title** — the target-owned governance docs
  (`docs/decisions.md`, `docs/anti-patterns.md`,
  `docs/context/architecture.md`) are cited by section title, never by
  line number or embedded date. The target project's own copy carries
  unrelated content at the same line/date, so a pinned citation
  resolves silently to the wrong thing instead of failing loud.

## Documentation files

- Tier 1 (`CLAUDE.md`) and Tier 2 (`docs/KNOWLEDGE_BASE.md`) contain no
  `[INFERRED - VALIDATE]` markers, no ASCII trees, and no `@` triggers.
- Tier 3 (`docs/*.md`) and domain/context files may contain inferences — mark
  them with `[INFERRED - VALIDATE]`.
- Paths inside documentation use forward slashes relative to the repo root.

## Language of documentation

- User-facing docs in this repo are written in English.
- Governance files (`decisions.md`, `anti-patterns.md`) keep their header
  notes in Portuguese as generated by the context-builder skill template —
  preserve this until the skill is updated otherwise.
- Planning documents under `docs/planning/` are authored in Portuguese (BR).
