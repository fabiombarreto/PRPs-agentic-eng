# Constraints

## Project maturity

`relay` is in its earliest stage. Only the Foundation phase is partially
delivered:

- `context-builder` skill — present
- `decision-gate.md`, `decisions.md`, `anti-patterns.md` — generated by the
  context-builder itself
- All other phases (Test Runner, orchestrator, approval cycle, CI/CD) — not
  started

Consequence: do NOT propose changes that assume agents, commands, or hooks
already exist. Building one of those is a net-new Phase deliverable.

## Runtime versions

None. The plugin has no runtime dependencies — it is markdown + JSON consumed
by Claude Code. The only constraint is that installations must run on a
Claude Code version that supports the plugin format used by
`plugins/relay/.claude-plugin/plugin.json`. [INFERRED - VALIDATE — no minimum
version is declared anywhere in the repo]

## Graceful degradation is mandatory

The planning documents require that every future component degrade
gracefully when its preconditions are absent. Concretely:

- Missing MCP Context7 → skip `docs/libs/` generation, continue.
- Missing Docker → Test Runner falls back to local execution and reports the
  risk.
- Missing test frameworks → Test Runner is skipped entirely with a clear
  skip-reason in the final report.
- No declared test framework (`test_frameworks: []` or missing) → the test
  writer/reviewer pair is silently skipped (heuristic activation is forbidden;
  `tdd:` only selects test-first vs test-after ordering, never whether the pair
  runs).

See `docs/planning/planejamento_fase_2.docx` §8.

## Patterns actively avoided

Listed in full in `docs/anti-patterns.md`. Summary: no test-weakening, no
heuristic TDD activation, no secret leakage in reports, no dependency on
interactive permission prompts during autonomous runs, no treating
`prp-core/` as active relay code.
