## Summary

Relocates relay's two shipped helper scripts (`generate-final-report.mjs`, `normalize-test-output.mjs`) from the repo root's `scripts/` directory into `plugins/relay/scripts/`, so that the `${CLAUDE_PLUGIN_ROOT}/scripts/...` invocations already written into `plugins/relay/agents/test-runner.md` and `plugins/relay/commands/relay-pr.md` resolve to a real file once relay is installed as a packaged plugin in a target project — today they only work by the accident of this repo being both the plugin's source and its own dogfood target. Extends the `path-existence` validation check (`scripts/validate/checks/path-existence.mjs`) so `${CLAUDE_PLUGIN_ROOT}/scripts/...` joins the set of reference classes it resolves and checks, turning this exact class of defect into a `npm run validate` failure instead of a silent runtime substitution. Updates every non-test repo-relative reference to the two scripts' old location across one production command file, two docs files, and four documentation-site pages, and records the change in `documentation/changelog.html`'s `Unreleased` section. Leaves the third file named in the source description — the test file `scripts/normalize-test-output.test.mjs`, plus four sibling test files that reference the old paths — entirely untouched: relocating or editing any of them is the test-writer/test-reviewer pair's post-implementation responsibility under R-X strict, not this plan's.

## User Story

As a relay plugin maintainer
I want the two shipped helper scripts to live inside `plugins/relay/scripts/`, with every production/doc/documentation-site reference pointing there, and the `path-existence` check able to catch the next dangling `${CLAUDE_PLUGIN_ROOT}/scripts/...` reference automatically
So that `node ${CLAUDE_PLUGIN_ROOT}/scripts/normalize-test-output.mjs` and `generate-final-report.mjs` resolve correctly the first time relay runs inside a real target-project installation, instead of silently falling back to a repo-local copy that will not exist anywhere but this repo

## Problem Statement

`plugins/relay/agents/test-runner.md:154` and `plugins/relay/commands/relay-pr.md:309` invoke `node ${CLAUDE_PLUGIN_ROOT}/scripts/normalize-test-output.mjs` and `node ${CLAUDE_PLUGIN_ROOT}/scripts/generate-final-report.mjs` respectively. `${CLAUDE_PLUGIN_ROOT}` always resolves to the installed plugin's own directory, never to a dev repo root — but the plugin ships no `scripts/` directory at all; both files live at this repo's root (`scripts/generate-final-report.mjs`, `scripts/normalize-test-output.mjs`). In any target project other than this one, both invocations name a path that does not exist. This has been masked because relay dogfoods itself from this same repo, where the `test-runner` agent has twice been observed substituting the repo-local `scripts/` copy when the `${CLAUDE_PLUGIN_ROOT}` path failed to resolve, silently working around the defect instead of surfacing it. `.claude/settings.json` already carries an allow-list entry for the packaged path (`Bash(node */plugins/relay/scripts/normalize-test-output.mjs *)`) alongside the repo-relative one, evidence that the move was anticipated but never completed. Compounding this, the `path-existence` validation check that guards dangling references does not yet resolve `${CLAUDE_PLUGIN_ROOT}/scripts/...` tokens at all (its allowed-prefix list is `agents/, commands/, skills/, .claude-plugin/`), so this exact defect class is currently invisible to `npm run validate` — it would surface only at dispatch time, inside someone else's project.

## Solution Statement

Move (not copy) `generate-final-report.mjs` and `normalize-test-output.mjs` from `scripts/` to `plugins/relay/scripts/`, leaving `${CLAUDE_PLUGIN_ROOT}/scripts/...` invocations in `test-runner.md` and `relay-pr.md` unedited (they become correct automatically). Extend `path-existence.mjs`'s `CLAUDE_PLUGIN_ROOT_ALLOWED_PREFIXES` array to include `'scripts/'`, mirroring the already-written extension on the prior unmerged branch `claude/laughing-mcnulty-af2f58` (commit `fe3562c`, checked out on disk at `.claude/worktrees/laughing-mcnulty-af2f58/`), including its corrected module-header rationale and its explicit `${CLAUDE_PLUGIN_ROOT}/docs/…` / `/PRPs/…` deferred-gap documentation. Update every non-test repo-relative mention of the two scripts' old path across `plugins/relay/commands/relay-qa-report.md`, `docs/api-reference.md`, `docs/design/visual-first-dogfood-runbook.md`, and four `documentation/` site pages, plus add one `Unreleased > Fixed` changelog entry. Leave `.claude/settings.json` untouched (editing it is outside the autonomous pipeline's permitted scope), leave `docs/context/settings-allowlist.md` untouched (already correct — it lists only the packaged form), and leave all five old-path-referencing test files untouched (test-pair territory).

**Why `normalize-test-output.test.mjs` is not moved here.** The file imports its subject with a relative specifier (`import { ... } from './normalize-test-output.mjs'`) and re-derives its own path via `fileURLToPath(new URL('./normalize-test-output.mjs', import.meta.url))`. The instant Task 2 relocates the source file, that relative import dangles regardless of whether the test file itself also moves — and fixing it requires editing the test file's content, not just relocating it. Separately, even a pure content-preserving rename (a `git mv` with zero text changes) is left to the test pair too. This is not because R-X's own purpose — preventing test-weakening — is philosophically implicated by a byte-for-byte-preserving rename; it is narrower and more mechanical than that: `code-reviewer`'s actual R-X implementation is a blanket test-glob straight-fail with no carve-out for rename-only diffs, so any diff touching a path matching the test glob trips it regardless of whether content changed. The practical choice (leave both the location and the content to the test pair) is correct either way; this is the accurate reason for it, not an overclaim that renames inherently weaken tests. The test-writer/test-reviewer pair's post-implementation pass is expected to both relocate this file to `plugins/relay/scripts/normalize-test-output.test.mjs` and repoint its import in the same change, since they must touch the file's content anyway.

The whole file aborts as a single load failure, not 26 individual assertion failures. The test pair is restoring an entire file's worth of coverage in one move, not retargeting one assertion — worth knowing going in, since the two failures will not look alike in a `node --test` run's output.
