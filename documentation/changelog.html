0.7.0 — 2026-04-25

Plan authoring stage shipped — second slice of project Phase 3 (Agents — Orchestrator). The plan-stage writer/reviewer pair is now live: /relay-plan dispatches the autonomous plan-writer agent to transform an APPROVED PRD into a per-phase DRAFT plan; /relay-plan-review dispatches the autonomous plan-reviewer agent which runs an 8-item structural rubric (R1–R8 with R8 for PRD↔plan traceability) and auto-flips DRAFT→APPROVED on full pass. Adds the canonical docs/context/plan-template.md as the source of truth for plan section structure. Records the per-phase plan filename pattern (<feature>-phase-<N>-<slug>.plan.md) as an explicit decision, refining the api-reference shorthand.

Added

  • plugins/relay/agents/plan-writer.md — autonomous PRD-phase → DRAFT plan transformer. Parses the source PRD's Implementation Phases table, selects the next actionable row, dispatches research-codebase + research-web in parallel, consults the three Decision Gate sources, writes a DRAFT plan to PRPs/plans/<feature>-phase-<N>-<slug>.plan.md, and back-fills the source PRD's row N (Status to in-progress; PRP Plan cell to the relative plan path).
  • plugins/relay/agents/plan-reviewer.md — autonomous 8-item rubric runner. Diverges from prd-reviewer in three documented ways: auto-flips *Status: DRAFT* → *Status: APPROVED* on rubric pass without user dialogue (interactivity boundary), evaluates all 8 items every run with no short-circuit (per AC-10), and has no Step 5 dialogue loop (CHANGES_REQUESTED is terminal). Every verdict appended to PRPs/plans/<basename>.review.jsonl.
  • plugins/relay/commands/relay-plan.md — public command surface for the plan-writer. Single-role (no Phase B reviewer adoption per the writer/reviewer split decision); 4 preconditions (P1 PRD readable, P2 PRD ends with *Status: APPROVED*, P3 Decision Gate sources readable, P4 actionable phase exists in the table); surfaces plan-writer's halts verbatim and exits.
  • plugins/relay/commands/relay-plan-review.md — public command surface for the plan-reviewer. Single-role (no Phase B writer adoption); 3 preconditions (P1 plan readable, P2 plan ends with *Status: DRAFT*, P3 Decision Gate sources readable); surfaces APPROVED summary or CHANGES_REQUESTED bullet list verbatim.
  • docs/context/plan-template.md — canonical plan section shape. Mirrors docs/context/prd-template.md structure with four mandatory adaptations: Decision Gate header, PRD↔plan back-reference, per-task VALIDATE invariant, TDD routing note. Anchors plan-reviewer R2 (15 mandatory sections in order) and Implementer expectations.
  • docs/decisions.md — new 2026-04-25 row recording the per-phase plan filename pattern as an explicit decision, refining the api-reference shorthand.

Changed

  • docs/api-reference.md — /relay-plan and /relay-plan-review rows now carry the implemented badge and the per-phase filename pattern. Notes expanded to cover the writer's autonomous PRD-parse + research dispatch + back-fill, and the reviewer's 8-item rubric with R8 traceability.
  • docs/context/architecture.md — §PRP artifact paths row for plans refined from <feature>.plan.md shorthand to the per-phase pattern <feature>-phase-<N>-<slug>.plan.md, with cross-reference to the new decision row.

Format notes

The site follows its own semver independent of the relay plugin (per AGENTS.md §7.1):

  • Patch (0.x.Y) — typo fixes, wording, broken-link repair. No structural change.
  • Minor (0.X.0) — new pages, new sections, new NAV entries, new CSS components. No breaking change to existing content.
  • Major (X.0.0) — breaking restructure: renamed folders, removed pages, overhauled theme. Migration notes accompany the entry.

Pre-1.0 cadence: minor bumps frequently, major bumps rarely, patch bumps whenever a single fix goes in alone. After 1.0 the site is considered externally stable and removal of any page triggers a major bump.
