0.10.0 — 2026-05-06

TDD writer/reviewer pair (B7/B8) shipped — Phase 2 of planejamento_fase_2.docx trilho TDD now live. The dead-code TDD routing branch in /relay-execute v0.9.0 is replaced by a live integration: when docs/context/methodology.md declares tdd: true, the orchestrator invokes /relay-tdd (B7 TDD Writer) followed by /relay-tdd-review (B8 TDD Reviewer) between /relay-plan-review and /relay-implement; on B8 CHANGES_REQUESTED, the orchestrator re-invokes /relay-tdd with the JSONL feedback up to max_tdd_review_retries=2; on budget exhaustion, HALT with the new FAILED_TDD_REVIEW_BUDGET_EXCEEDED outcome code. R-X strict (D17 of implementation-authoring.prd.md) is preserved verbatim — the implementer never edits test files; B7 is the authorized author of new test files in the autonomous pipeline. The driver of this PRD was three real-world halts on the user's /relay-execute runs (Phase 2 xfail removal, Phase 3 AC-5 test addition, Phase 4 manual fallback) — the TDD pair is the structural unblock for any feature that requires new test files, not just for projects practicing TDD as historical methodology. Synthetic B8 fixture shipped at PRPs/reports/tdd-writer-reviewer/synthetic-b8-fixture-1/ (one dirty variant with all 5 pathologies + R-RED-LEGITIMATE broken-setup planted; one clean variant covering 4 ACs without any pathology) for rubric calibration before Phase 5 dogfood. Added

  • plugins/relay/agents/tdd-writer.md — new B7 TDD Writer agent. Reads source PRD's ## Acceptance Criteria + APPROVED plan; walks each AC and emits one of three per-AC outcomes (NEW_TEST_REQUIRED writes a framework-idiomatic test file, EXISTING_TEST_COVERS path:line documents the mapping without writing a duplicate, AMBIGUOUS aborts with structured halt). Aggregate verdict SUITE_DRAFT_WRITTEN or EXISTING_COVERAGE_SUFFICIENT recorded in PRPs/reports/<feature>/tdd-initial-suite.diff. Tools: Task, Read, Write, Edit, Glob. Color: green. Hard constraints: never writes production code (R-X strict's symmetric inverse), never modifies existing test files, prompt parametrized by methodology.md test_frameworks[].
  • plugins/relay/agents/tdd-reviewer.md — new B8 TDD Reviewer agent. Six-row rubric (R-IMPL-LEAK, R-TRIVIAL-ASSERT, R-MOCK-ABUSE, R-AC-COVERAGE, R-DUPLICATE, hybrid R-RED-LEGITIMATE) appended to PRPs/plans/<basename>.tdd-review.jsonl (append-only Read+concat+Write). R-MOCK-ABUSE ships with four syntactic-categorical detections (mock-of-SUT, mock of concrete type when interface exists, chained mocks ≥3 deep, was_called-only assertions); quantitative threshold deferred to post-dogfood calibration. R-RED-LEGITIMATE hybrid: dynamic Bash execution of the project's test command when framework executable, distinguishing assertion-failure red (passed: true) from broken-setup red (passed: false) from green-pre-impl (passed: false); degrades gracefully to passed: null with reason when Bash/framework unavailable per AC-13. Tools: Read, Write, Glob, Grep, Bash, BashOutput, Task — explicitly NO Edit; the /relay-tdd-review command owns the suite-status flip (D11 read-only invariant). Color: green.

0.8.0 — 2026-04-30

Implementation authoring stage shipped — third writer/reviewer pair, completing the autonomous core of project Phase 3 (Agents — Orchestrator). The implementation-stage writer/reviewer pair is now live: /relay-implement dispatches an internal writer↔reviewer loop between the autonomous implementer agent (color: green) and the autonomous code-reviewer agent (color: magenta); on APPROVED rubric performs three D8 post-approval mutations atomically (plan trailing-block flip to *Status: IMPLEMENTED*, plan move to PRPs/plans/completed/, source PRD row N flip from in-progress to complete). /relay-code-review is the standalone single-shot reviewer surface for hand-invoked review (read-only counterpart; never auto-flips plan status; never performs D8 mutations). The loop is bounded by max_implement_retries=3 (4 attempts total), max_implement_minutes=45 (wall-clock; first-to-expire-wins distinct from retry exhaustion), and max_disputes_per_session=2 (TEST_CONTRACT_DISPUTE escape valve cap; arbitration mode resolves via DISPUTE_REJECTED/DISPUTE_UPHELD_TEST_WRONG/DISPUTE_UPHELD_PRD_AMBIGUOUS). Oscillation detection always-on (file-set intersection + semantic-reversal heuristic). Per-attempt cumulative diff.patch captured at PRPs/reports/<feature>/phase-<N>/attempts/<i>/. Records the universal R-X test-modification guard (D9 Layer 0) as the rubric-level enforcement of the long-standing "no weakening tests" anti-pattern. Cuts the prior Unreleased block (reviewer-coherence-layer Phases 1–4) into the same v0.8.0 release because both feature stacks are at stable shippable points.

Six distinct outcome codes (FAILED_AFTER_N_RETRIES, FAILED_TIME_BUDGET_EXCEEDED, FAILED_OSCILLATION_DETECTED, FAILED_DISPUTE_CAP_EXCEEDED, DISPUTE_UPHELD_TEST_WRONG, DISPUTE_UPHELD_PRD_AMBIGUOUS) plus PARTIAL_D8_FAILURE for atomicity violations.
  • plugins/relay/commands/relay-code-review.md — new standalone single-shot reviewer surface. Five preconditions (P1 plan readable, P2 plan APPROVED-or-IMPLEMENTED, P3 worktree has diff vs base, P4 Decision Gate sources readable, P5 base-commit derivable). Critical divergence from /relay-plan-review: this command does NOT auto-flip plan status and does NOT perform any D8 mutation — the plan trailing block is byte-identical before and after. Read-only counterpart to /relay-implement's mutation-triggering autonomous loop, for hand-invoked review where no automated state transition is desired.

0.7.3 — 2026-04-28 (reviewer-coherence-layer Phases 1–4)

Phases 1, 2, and 3 of the reviewer-coherence-layer feature — additive R-COH-* coherence layer shipped on prd-reviewer and plan-reviewer. The reviewers now run an additional layer after R1–R7 (PRD) / R1–R8 (plan) that catches intra-artifact contradictions the structural rubric does not detect. Phase 1 (prd-reviewer): intra-PRD contradictions including ACs that contradict each other in prose, Success Metrics decoupled from the Key Hypothesis, Solution Detail that drifts from Proposed Solution, references to non-existent sections / ACs / phases, table-vs-prose number drift, and Decisions Log entries that contradict the Proposed Solution. Two deterministic checks (R-COH-NUMBER-DRIFT, R-COH-SECTION-REF-MISSING) plus a bounded K=5 LLM judgment pass over five named contradiction classes. Phase 2 (plan-reviewer): intra-plan contradictions including tasks that don't reference any AC, Files-to-Change rows untouched by tasks, VALIDATE commands mismatching declared frameworks, Patterns-to-Mirror SOURCE paths missing, Mandatory Reading paths missing, plus K=5 LLM-detected drift between Summary / Solution Statement and Tasks. Five deterministic checks (R-COH-TASK-AC-MISSING, R-COH-FILES-UNTOUCHED, R-COH-VALIDATE-FRAMEWORK-MISMATCH, R-COH-PATTERN-SOURCE-MISSING, R-COH-MANDATORY-READING-MISSING) plus the K=5 pass with HD-Eval section-pair decomposition. AC-10 contract evolution: Phase 2 consciously evolves AC-10 of plan-authoring.prd.md from "exactly 8 objects … no extras" to "R1–R8 always present, no duplicates among R1–R8; R-COH-* rows additional"; AC-10's no-short-circuit invariant is preserved verbatim. The evolution is recorded as a new entry in docs/decisions.md; the APPROVED plan-authoring.prd.md is not mutated. Both layers combine deterministic checks with a bounded K=5 LLM judgment pass; an empty array is the correct return when no contradictions exist (no padding). Existing R1–R7 / R1–R8 textual definitions are byte-identical pre/post both phases; the layers are purely additive. prd-reviewer remains interactive on rubric pass; plan-reviewer remains autonomous with CHANGES_REQUESTED terminal. Phase 3 (code-reviewer): intra-diff coherence shipped via four deterministic checks (R-COH-DEAD-IMPORT, R-COH-CALLER-DRIFT, R-COH-CONFIG-DANGLING, R-COH-REGISTRY-MISSING) inline in the parent agent + a new sub-agent code-reviewer-semantic invoked via Task for the bounded K=5 LLM judgment pass over three K=5 IDs (R-COH-COMMENT-MISMATCH, R-COH-TEST-NAME-LIES, R-COH-OTHER-INTERNAL-CONTRADICTION) plus a dedicated R-COH-TASK-CONTRADICTION check (always emitted) plus a R-COH-SEMANTIC-DEGRADED degradation marker. The sub-agent receives the diff + plan task + PRD AC excerpts via XML-delimited prompt (Anthropic best practices); is read-only (tools: Glob, Grep, Read); returns structured JSON. R-COH-* rows appear in standard mode only; arbitration mode is unchanged. D11 + AC-10 contract evolution (2026-04-28): Phase 3 consciously evolves D11 of implementation-authoring.prd.md (Task added to code-reviewer's tools — read-only invariant preserved verbatim; Edit remains absent) and AC-10 (relaxed from "exactly 8 objects, no extras" to "R-S*/R-L*/R-SEM/R-X always present, no duplicates among them; R-COH-* rows additional in standard mode"); both evolutions are recorded as a single combined 2026-04-28 entry in docs/decisions.md. New context file: docs/context/code-review-registries.md with the default-relay 4-path allowlist for R-COH-REGISTRY-MISSING.

Format notes

The site follows its own semver independent of the relay plugin (per AGENTS.md §7.1):

  • Patch (0.x.Y) — typo fixes, wording, broken-link repair. No structural change.
  • Minor (0.X.0) — new pages, new sections, new NAV entries, new CSS components. No breaking change to existing content.
  • Major (X.0.0) — breaking restructure: renamed folders, removed pages, overhauled theme. Migration notes accompany the entry.

Pre-1.0 cadence: minor bumps frequently, major bumps rarely, patch bumps whenever a single fix goes in alone. After 1.0 the site is considered externally stable and removal of any page triggers a major bump.
