Usage metrics

The per-project, local-only metrics artifact relay can materialize from the audit trail it already writes: what it contains, why every cell is a bare code, how to generate it, and what is deliberately not built.

Purpose

relay already writes an audit trail in every target project: orchestrator-run.json, run.json, test-review.json, per-attempt diffs and the *.review.jsonl verdict logs. Improving the plugin from that evidence used to mean assembling it by hand across repositories. The usage-metrics artifact turns the trail into a small, versioned, portable set of files that a human, an AI or a script can read when deciding what to improve next.

Local files, no telemetry

Nothing transmits data anywhere. Metrics sit inside the repository that produced them; combining projects is a manual, human-initiated act of collecting files.

File layout

Shards live in PRPs/metrics/, one file per relation per calendar month, named <relation>-v<MAJOR>-<YYYY-MM>.tsv, plus one -undated file per relation and a single scan-v1.tsv.

PRPs/metrics/verdict-v1-2026-08.tsv
PRPs/metrics/verdict-v1-undated.tsv
PRPs/metrics/rubric-v1-2026-08.tsv
PRPs/metrics/run-v1-2026-08.tsv
PRPs/metrics/scan-v1.tsv

There are four relations: verdict, rubric, run and scan. The codebook is plugins/relay/resources/usage-metrics-schema.md.

Closed field contract

A cell is a bare enumerated code, a non-negative integer, an ISO-8601 UTC instant or the single sentinel -. Never a label, a sentence or a path. All meaning lives in the schema document, and a reader resolves codes against it. Rubric ids are an open set resolved against the reviewer agent files, so an unknown id is treated as new, not corrupt. Free text is excluded on purpose: it is the privacy mechanism, not a filter.

Running it

node ${CLAUDE_PLUGIN_ROOT}/scripts/usage-metrics.mjs materialize
node ${CLAUDE_PLUGIN_ROOT}/scripts/usage-metrics.mjs --dry-run
node ${CLAUDE_PLUGIN_ROOT}/scripts/usage-metrics.mjs query

materialize regenerates every shard by full rescan, so re-runs converge and never duplicate. --dry-run reports row counts and destinations without writing. query prints per-stage counts, first-attempt failure rates and the top failing rubric ids. The mode is mandatory and arguments are parsed strictly, so a typo cannot fall through to rewriting shards. See Scripts.

Isolated from the pipeline

It is operator-run, never part of a pipeline stage. No agent, command or skill may reference PRPs/metrics; the metrics-isolation check enforces it. A reviewer that knows its own pass rate has an incentive to approve leniently.
