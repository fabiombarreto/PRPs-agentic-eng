Introduction

Autonomous feature delivery for Claude Code

relay is a Claude Code plugin that takes a feature from PRD to merged PR without supervision between stages. Writer/reviewer agent pairs produce the plan, write the code, run the tests, fix failures, and open the PR — the human stays in the loop only where human judgment actually matters.

At a glance

🏛 Three pillars
Initialization → Implementation → Approval. Each pillar has a clear boundary between interactive and autonomous work.
🤝 Interactive at the right moment
Dialog happens at PRD authoring, where catching misunderstanding is cheapest. Everything after PRD approval runs autonomously.
🔁 Self-correcting Test Runner
A classifier separates legitimate bugs from infra and flakiness; a loop retries with the Implementer until green or budget exhausted.
🧪 Optional TDD track
Explicit opt-in via methodology.md. When active, tests are written before implementation and become the acceptance contract.
⌨ Command surface
Twelve commands, one per stage. Each invocable in isolation or composed by the orchestrator into a full run.
🚦 Current status
Phase 1 (Foundation) and the Test Runner PRD are implemented. The orchestrator across Pillar 2 is next.

What it is, concretely

Most teams using AI-assisted development today write a PRD, then a plan, then some code, then run the tests, interpret the failures, ask the AI to fix them, re-run, and repeat. Each hand-off is a separate command and a separate approval. The developer spends more time orchestrating than creating.

relay moves the orchestration into the plugin. You describe the feature; relay writes the PRD with you (this is the only interactive stage), then goes off and builds it. When you come back, there's either a pull request waiting to be merged or a clear diagnostic for the one decision the AI couldn't make on its own.

Autonomous

Autonomous

↓

The legend: Interactive means you're part of the loop; Autonomous means the pipeline runs without asking you anything (unless something is genuinely unrecoverable); Manual means the step is triggered by you explicitly but runs autonomously once started.

Why it exists

Every team shipping AI-assisted features hits the same three problems:

  1. Too many manual hand-offs. A PRD command. A plan command. An implementation command. A review command. A commit command. A PR command. The human approves each one, spending most of their time as a scheduler.
  2. Testing is a bottleneck. E2E tests are rarely run in the loop because setting them up and interpreting the output takes more effort than the fix itself. Bugs ship.
  3. Business rules are ignored. The AI doesn't know about the decisions the team already made. Each session reinvents patterns that were intentionally rejected months ago.

relay addresses all three:

  • One command drives the whole thing after the PRD is approved. The pipeline is orchestrated, not scheduled.
  • Tests run in an isolated Docker environment with an auto-correction loop. The Test Runner distinguishes real failures from infra issues and flakiness; it never deletes tests to reach green, and a post-green reviewer enforces that.
  • A docs/ tree produced by a context-builder skill encodes the project's stack, conventions, domain rules, and past decisions. Every agent consults it before acting. The Decision Gate makes that consultation mandatory.

Who it's for

  • Teams using Claude Code for real feature work — not experiments, not toys. The plugin assumes you have tests, Docker, and a PR workflow.
  • Projects with non-trivial domain rules. relay's governance layer (decisions, anti-patterns, domain areas) is overkill for a weekend script but lifesaving for a production codebase.
  • Engineers who want to stay in the loop at the right moment. If you want to approve every generated line, relay is not for you. If you want to approve the intent and let the plugin handle the mechanical rest, it is.
