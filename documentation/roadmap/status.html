Phase status

Where relay is today. Two levels of tracking: the five project-level phases (Foundation → CI/CD) that structure the overall rollout, and the per-PRD phase tables inside each feature's PRD. This page covers both.

Legend

  • done — artifact delivered, validated as working
  • partial — artifact delivered; some aspect (usually a runtime signal) still pending validation
  • pending — not started or explicitly deferred

Project-level phases

relay's overall delivery follows five ordered phases from the planning document:

#PhaseScopeStatus
1 Foundation Context-builder skill + decision-gate + decisions.md + anti-patterns.md + MCP validation done
2 Testing Isolated container, Test Runner agent, auto-correction loop, post-green review, reports done (artifacts)
3 Agents Orchestrator — single /relay-execute command driving the full pipeline from approved PRD to PR partial (PRD authoring stage shipped: /relay-prd + prd-writer + prd-reviewer + research-web + research-codebase; remaining stages pending)
4 Approval /relay-approve + Docs Updater + Docs Reviewer pending
5 CI/CD Full end-to-end autonomous pipeline integrated with CI pending

What's shipped, concretely

Plugin artifacts

In plugins/relay/:

  • Skill: skills/context-builder/SKILL.md — initializes / updates the documentation tree for any target project
  • Agents: agents/test-runner.md, agents/post-green-reviewer.md, agents/prd-writer.md, agents/prd-reviewer.md, agents/research-web.md, agents/research-codebase.md
  • Commands: commands/relay-test.md, commands/relay-test-review.md, commands/relay-prd.md

Other agents and commands from the 12-command surface (Commands) are pending; their implementations are the main deliverables of project phases 3 and 4.

Shared scripts

In scripts/ at the plugin repo root:

  • normalize-test-output.mjs — parses JUnit XML (pytest, Playwright, Vitest) into the canonical schema
  • generate-final-report.mjs — assembles the AC-10 compliant final-report.md from run.json + test-review.json + per-attempt records

Both are Node.js with no npm dependencies. Claude Code ships with Node, so these work on every host running relay regardless of the target project's own language stack.

Governance artifacts

In docs/ at the plugin repo root:

  • decisions.md — 14 stable decisions (see Decisions)
  • anti-patterns.md — 7 forbidden patterns (see Anti-patterns)
  • decision-gate.md — the mandatory control mechanism
  • context/architecture.md, conventions.md, constraints.md, integrations.md, methodology.md
  • context/prd-template.md — canonical PRD shape
  • context/settings-allowlist.md — catalog of allow/deny patterns
  • context/redaction-policy.md — three-layer secret redaction policy
  • context/test-output-schema.md — schema + observability layout

What's next

The big one. The PRD authoring stage shipped (/relay-prd + prd-writer + prd-reviewer, plus the reusable research-web and research-codebase subagents); the rest of the pipeline is still pending. The PRD for the next stage — Plan authoring (/relay-plan + /relay-plan-review) — is APPROVED at PRPs/prds/plan-authoring.prd.md and queued for implementation.

Shipped:

Pending:

  • /relay-plan + /relay-plan-review — PRD APPROVED; implementation next
  • /relay-worktree
  • /relay-tdd + /relay-tdd-review (opt-in)
  • /relay-implement + /relay-code-review

When Phase 3 fully lands, Phase 5 of the Test Runner PRD (no-prompts autonomous run) and AC-2/3/4 (auto-correction succeeds / budget exhausted / oscillation) become validatable, closing out the remaining Test Runner ACs.

Phase 4 (Approval cycle)

/relay-approve <pr> plus Docs Updater and Docs Reviewer agents. Closes the feedback loop so documentation stays in sync with what was merged.

Phase 5 (CI/CD)

Integration with real CI: GitHub Actions workflows that invoke relay, external-service gating, automated merge rules. Last phase, furthest out.

Known gaps

Honest list of things documented but not yet realized:

/relay-implement gap

The /relay-test command's auto-correction loop, when it hits RETRY_NEEDED, is designed to invoke the Implementer. The Implementer agent is part of Phase 3 (Orchestrator), not yet implemented. Until it lands, /relay-test HALTS on first RETRY_NEEDED with a clear message and writes failure feedback to disk. Users apply the fix manually and re-run. This is documented behavior, not a bug.

Coverage baseline

The post-green reviewer detects coverage drops >5% when a baseline file exists at PRPs/reports/coverage-baseline.json. The baseline is team-committed (opt-in); no automatic generation yet. When baseline is missing, the reviewer notes the limitation in its verdict and proceeds with structural checks only.

Weak-test detection

B3 classifier intentionally skips the weak_test category for MVP. Detecting a poorly-written test requires reading the test's source code; the heuristic surface is too small to catch most cases. B5 (post-green review) is the actual guard — it catches tests that were removed or skipped, which covers the common weakening patterns.
