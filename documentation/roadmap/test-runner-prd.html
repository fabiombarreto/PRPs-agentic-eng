Test Runner PRD — deep dive

The Test Runner is the closed-loop component that turns a candidate implementation into a GREEN outcome (or a well-classified abort). This page walks through the 9-phase PRD that drove its delivery, with per-phase outcomes, acceptance criteria, and the artifacts each phase produced. It complements the high-level phase status page with the full detail a reviewer needs.

Source

Canonical PRD at PRPs/prds/test-runner.prd.md in the plugin repo. The per-phase plans are under PRPs/plans/test-runner/phase-<N>.md. Artifacts from the dogfood run are in PRPs/reports/dogfood-2026-04-21/.

Scope at a glance

The Test Runner stage (B1-B8 in the component inventory) is bounded by three guarantees:

  1. Deterministic verdict. Every invocation ends with one of: GREEN, FAILED_AFTER_N_RETRIES, FAILED_TIME_BUDGET_EXCEEDED, FAILED_OSCILLATION, or FAILED_INFRA_UNRECOVERABLE. No silent failures.
  2. Bounded work. max_test_retries = 3 attempts; max_test_minutes = 30 wall clock. Configurable via .relay.yaml or CLI flags but never unbounded.
  3. Read-only against tests. The loop may only modify implementation files. Editing, skipping, or deleting tests to achieve green is an anti-pattern enforced by the post-green reviewer.

Component map

The PRD carved the work into 8 plugin components and 4 infra components:

A1 — Compose primitives
docker-compose.test.yml per target + make test-bootstrap/make test-down.
A2 — Test output normalizer
normalize-test-output.mjs: JUnit XML → canonical schema v1.
A3 — Report generator
generate-final-report.mjs: run.json + attempts → final-report.md.
A4 — Redaction filter
Three-layer policy applied on every captured stream.
B1 — Test Runner agent
Orchestrates one attempt: boot infra, run suite, capture output.
B2 — Output capture
stdout/stderr/JUnit → per-attempt record.json.
B3 — Failure classifier
Canonical JSON → verdict: GREEN, RETRY_NEEDED, INFRA_UNRECOVERABLE.
B4 — Auto-correction loop
On RETRY_NEEDED, routes feedback to Implementer; on next commit, re-runs B1.
B5 — Post-green reviewer
After GREEN, checks for weakened/removed/skipped tests.
B6 — Run report
Synthesizes final run artifact for the PR description.
B7 — TDD Writer
Generates test suite from PRD AC (TDD track only).
B8 — TDD Reviewer
Rejects suites that leak implementation or use excess mocks.

The 9 phases

Phase 0 — Foundations

Goal
Establish the repository conventions the rest of the PRD depends on: artifact paths, decision log, anti-patterns, command surface.
Deliverables
  • docs/decisions.md seeded with 6 entries
  • docs/anti-patterns.md seeded with 4 patterns
  • docs/context/{architecture,conventions,constraints,methodology}.md
  • PRPs/ artifact root convention
Exit criteria
Downstream phases can cite stable paths without guessing.
Status
Complete

Phase 1 — Infra primitives (A1)

Goal
Standardize the boot/teardown surface so B1 can assume Docker Compose semantics regardless of stack.
Deliverables
  • docker-compose.test.yml template shipped via context-builder
  • make test-bootstrap / make test-down targets
  • Graceful fallback when Docker is absent (verdict: FAILED_INFRA_UNRECOVERABLE / docker_not_running)
Acceptance criteria
  • AC1: make test-bootstrap returns 0 in < 60s on warm cache.
  • AC2: make test-down is idempotent.
  • AC3: Missing Docker produces a single-line diagnostic, not a Python traceback.
Status
Complete

Phase 2 — Normalizer (A2)

Goal
Produce one canonical JSON schema that every framework-specific JUnit XML is mapped into. B3's classifier reads the canonical form only.
Deliverables
  • plugins/relay/scripts/normalize-test-output.mjs
  • docs/schema/test-output-v1.json
  • Framework mappings: pytest, Vitest, Playwright, Jest, Go test
Acceptance criteria
  • AC1: Unknown framework → clear error, not a crash.
  • AC2: Missing XML file → verdict normalizer_failure with the expected path.
  • AC3: Mixed-framework suite (pytest + Playwright) → merged canonical output.
Status
Complete

Phase 3 — Classifier (B3)

Goal
Turn canonical JSON into a verdict: GREEN, RETRY_NEEDED (with implementer-feedback.json), or INFRA_UNRECOVERABLE (with subcause).
Deliverables
  • classifier logic inside the test-runner agent
  • Subcause inventory: missing_settings_json, docker_not_running, db_unreachable, normalizer_failure, no_runner_detected, no_test_framework
Acceptance criteria
  • AC1: All-pass canonical → GREEN.
  • AC2: Any failure with valid infra → RETRY_NEEDED + structured feedback.
  • AC3: Subcause exhaustively covers the common infra failures observed in dogfood.
Status
Complete

Phase 4 — Auto-correction loop (B4)

Goal
Wire B3's RETRY_NEEDED verdict back to the Implementer, then re-invoke B1 on its next commit. Bound by max_test_retries.
Deliverables
  • Loop driver inside /relay-test command
  • Per-attempt subdirectory convention PRPs/reports/<feature>/attempts/<N>/
  • Oscillation detector: file-set intersection + content-reversion check
  • run.json with outcome, attempts[], time_breakdown
Acceptance criteria
  • AC1: Loop terminates on first GREEN.
  • AC2: max_test_retries exhausted → FAILED_AFTER_N_RETRIES.
  • AC3: Wall-clock budget exceeded → FAILED_TIME_BUDGET_EXCEEDED.
  • AC4: Attempt N+1 reverts files from attempt N → FAILED_OSCILLATION.
Known gap
Until /relay-implement lands, the loop halts on the first RETRY_NEEDED and writes implementer-feedback.json for human consumption. See Handling failures.
Status
Complete (with known gap)

Phase 5 — Post-green reviewer (B5)

Goal
After GREEN, verify the green wasn't achieved by weakening tests. Detect removed tests, added skips, trivial assertions, coverage drops.
Deliverables
  • post-green-reviewer agent
  • /relay-test-review command
  • Per-language heuristics for test deletion / skip / trivial assertions
  • Coverage baseline opt-in at PRPs/reports/coverage-baseline.json
  • test-review.json verdict: APPROVED | CHANGES_REQUESTED
Acceptance criteria
  • AC1: Pure implementation diff → APPROVED, concerns: [].
  • AC2: Diff deletes a test function → CHANGES_REQUESTED with type: test_removed.
  • AC3: Diff adds @skip → CHANGES_REQUESTED with type: test_skipped.
  • AC4: Baseline absent → notes: ["coverage baseline unavailable..."], no false flag.
Status
Complete

Phase 6 — Run report (B6)

Goal
Generate the single markdown report that goes into the PR description: outcome, attempt count, time breakdown, classified failures, redaction summary.
Deliverables
  • plugins/relay/scripts/generate-final-report.mjs
  • Markdown template pinned to docs/schema/final-report-v1.md
  • Secret redaction integrated via A4 filter
Acceptance criteria
  • AC1: All sections present regardless of outcome.
  • AC2: Redacted values appear as [REDACTED:<category>], never raw.
  • AC3: Report is < 50KB (PR description limit safe).
Status
Complete

Phase 7 — TDD track (B7 + B8)

Goal
For projects with tdd: true, generate the test suite before the implementer runs, and reject suites that leak implementation details.
Deliverables
  • TDD Writer agent (B7) with PRD-AC → test prompt
  • TDD Reviewer agent (B8) with rejection heuristics for excess mocks, trivial asserts, implementation-specific fixtures
  • /relay-tdd-write + /relay-tdd-review commands
Acceptance criteria
  • AC1: tdd: false or missing → skill silently skips B7/B8.
  • AC2: Suite with > 50% mocked collaborators → CHANGES_REQUESTED.
  • AC3: Suite with trivial asserts → CHANGES_REQUESTED.
  • AC4: PRD has no concrete AC → B7 halts and asks for clarification rather than inventing behavior.
Status
Complete

Phase 8 — Dogfood + hardening

Goal
Run the full pipeline against a real target project (Phoenix) and fix whatever breaks. Capture artifacts as reference for future debugging.
Deliverables
  • Dogfood artifacts at PRPs/reports/dogfood-2026-04-21/
  • Fixes emerging from the run (gitignore pattern, oscillation detector edge case, redaction regex tuning)
  • Phoenix dogfood walkthrough
Acceptance criteria
  • AC1: End-to-end synthetic run terminates with a well-formed run.json.
  • AC2: Every issue found during dogfood either fixed, documented as a known gap, or converted to a decision entry.
  • AC3: Artifacts committed for future reference.
Status
Complete

Rolled-up acceptance criteria (PRD-level)

The PRD-level ACs that the 9 phases collectively satisfied:

  1. A single /relay-test <worktree> invocation terminates with a structured outcome in every documented scenario.
  2. The outcome distinguishes infra failure, convergence failure, time budget exhaustion, and oscillation — no generic "failed."
  3. The loop never modifies test files. Proven by post-green reviewer running on every GREEN.
  4. Every artifact produced by the Test Runner lives under PRPs/reports/<feature>/. Never under .claude/.
  5. Captured output is redacted before being written to disk. Three-layer policy applied.
  6. TDD track is opt-in by explicit declaration. Heuristic activation is forbidden.
  7. A missing or broken infra surfaces a single diagnostic line, not a traceback.
  8. The PR description embeds the full run report in < 50KB markdown.

What's next

The Test Runner PRD is done. The broader rollout continues along the 5-phase program (Foundation / Testing / Agents / Approval / CI/CD):

  • Phase 3 — Agents: /relay-implement to close the auto-correction loop without human intervention.
  • Phase 4 — Approval: /relay-pr + Docs Updater so a PR reaches "ready for review" autonomously.
  • Phase 5 — CI/CD: GitHub Actions wiring, settings lint, Decision Gate enforcement hooks.

See Phase status for the current position in that program.
