Agents

The specialized Claude Code agents relay invokes. Each agent has a focused system prompt, a narrow tool allowlist, and a structured output format. Commands (slash commands) wrap agents with orchestration logic; the agents themselves are reusable single-responsibility units.

Implemented

test-runner shipped

Path
plugins/relay/agents/test-runner.md
Model
sonnet
Invoked by
/relay-test command, per attempt
Responsibility
Execute one attempt of a test suite, normalize the output, classify every failure (B3), return a structured verdict so the calling command can drive the auto-correction loop (B4).
Never does
Loop on its own. Modify tests. Modify production code. Invoke other agents. Write outside PRPs/reports/. Return unstructured verdicts.

Inputs (passed by the command)

worktree: absolute path to the worktree
attempt: 1-based attempt number
run_id: UUID shared across all attempts in this session
tier: unit | integration | e2e (optional; present when layered execution is active)
framework: pytest | playwright | vitest (optional; auto-detect when absent)
time_remaining_ms: wall-clock budget remaining
previous_record_refs: paths to prior attempts' record.json (for flakiness detection)

Outputs — verdict JSON in a fenced block

Returns exactly one of five verdicts:

GREEN
All tests passed (or all failures were flaky-retry-resolved). record_path references the attempt's record.
RETRY_NEEDED
At least one legitimate failure. Includes a feedback_for_implementer payload the command hands to the Implementer.
RETRY_FLAKY
All failures are flaky-suspected. Command should re-run the suite without invoking the Implementer.
ABORT_INFRA
Infrastructure broken (missing settings.json, Docker down, DB unreachable, normalizer failure). Includes reason so the command can decide whether to attempt recovery.
ABORT_TIME
Attempt entered with time_remaining_ms ≤ 0 or consumed so much time that continuing isn't meaningful.

Classifier heuristics (B3, inline in the agent prompt)

Three real categories plus a default:

infra
Regex against error messages: connection refused, ECONNREFUSED, psycopg.OperationalError, container not running, docker.errors.DockerException, OOMKilled, etc. Indicates the environment is broken, not the code.
flaky
Regex: timeout, timed out, race condition, port already in use. Also: same failure (same suite + test name) appears in a previous attempt AND the file it lives in wasn't modified since.
legitimate
Default — no infra pattern matched, no flaky pattern matched. The Implementer is expected to fix.
weak_test
Intentionally not implemented in B3 for MVP. The post-green reviewer (B5) is the actual guard against test weakening.

Redaction before persist

Env vars matching the redaction policy have their values replaced with [REDACTED] (or [REDACTED_URL] for connection strings) before stdout.log is written to disk. Never writes raw output that could contain secret values.

post-green-reviewer shipped

Path
plugins/relay/agents/post-green-reviewer.md
Model
sonnet
Invoked by
/relay-test-review command
Responsibility
Given a GREEN test state, verify the green wasn't achieved by weakening tests. Returns APPROVED or CHANGES_REQUESTED with a concrete concerns list.
Never does
Re-run tests. Modify code. Propose specific fixes (surface the weakening; let the caller decide on remediation). Return verdicts other than the two specified.

Inputs

worktree: absolute path
run_json_path: absolute path to run.json (must have outcome: GREEN)
base_branch: reference to diff against (default main/master)
run_id: UUID matching run.json

Detection rules

test_removed
Count per-language regex matches on removed - lines: def test_*, it(, test(, describe(, func Test*, rspec block heads. Net-negative (after offsetting additions to tolerate renames) is a concern.
test_skipped
Count added + lines matching skip markers: @pytest.mark.skip, @unittest.skip, .skip(), xit(, xdescribe(, test.skip, t.Skip(). Net-positive is a concern.
trivial_assertion
Best-effort: flags crystal-clear cases like expect(true).toBe(true), assertTrue(True), assert True. Doesn't over-fire.
coverage_drop
If PRPs/reports/coverage-baseline.json exists, compares current coverage to it. Absolute drop > 5% is a concern. When baseline is missing, emits a notes[] entry rather than blocking approval.

Verdict structure

{
  "verdict": "APPROVED" | "CHANGES_REQUESTED",
  "run_id": "...",
  "analyzed_files": 7,
  "concerns": [
    { "type": "test_removed", "file": "...", "net_removed": 2, "evidence": ["..."] }
  ],
  "notes": [
    "coverage baseline unavailable (no PRPs/reports/coverage-baseline.json)"
  ]
}

prd-writer shipped

Path
plugins/relay/agents/prd-writer.md
Model
sonnet
Invoked by
/relay-prd command (Phase A)
Responsibility
Drive the interactive 6-phase PRD authoring flow with the user (Initiate → Foundation → Grounding → Deep Dive → optional re-grounding → Decisions → Generate). Invoke research-web and research-codebase in parallel during GROUNDING. Consult the three Decision Gate sources (decisions.md, anti-patterns.md, architecture.md) and emit the evidence block as the first fenced block of the PRD. Read methodology.md for the TDD routing note. Write the DRAFT to PRPs/prds/<kebab>.prd.md.
Never does
Approve its own output (the reviewer owns the flip). Skip phases. Fill mandatory sections with plausible filler instead of TBD - needs validation. Overwrite an existing PRD (collision uses numeric suffix; APPROVED files never overwritten). Write under .claude/.

Inputs (passed by the command)

mode: blank | description | draft-path
description: free-text (when mode == description)
draft_path: absolute path (when mode == draft-path; the command has
            already verified the file is not APPROVED)
target_root: absolute path to the target project root

Draft-path: skip-on-answered detection

When invoked with a draft path, the writer reads the draft and detects which Phase 1, 2, 4, and 6 questions are already answered. A question counts as answered when the draft has a heading or paragraph addressing it, content of at least one complete sentence, and no TBD / TODO / {placeholder} prefix. Answered questions are skipped; only unanswered ones go to dialogue.

prd-reviewer shipped

Path
plugins/relay/agents/prd-reviewer.md
Model
sonnet
Invoked by
/relay-prd command (Phase B), after the writer hands off the DRAFT
Responsibility
Validate the DRAFT against the 7-item structural rubric. On full pass, ask the user to approve in free-text dialogue. On explicit approval, re-validate the rubric one final time, then flip *Status: DRAFT* to *Status: APPROVED* via two-line Edit and stamp *Approved: YYYY-MM-DD*. Append every verdict to PRPs/prds/<basename>.review.jsonl.
Never does
Approve without explicit user confirmation. Flip without the final pre-flip re-validation. Rewrite whole sections inline (structural defects route back to prd-writer via Task). Edit the DRAFT silently to make the rubric pass. Operate on a file whose status is already APPROVED (returns error: already_approved).

The 7-item rubric

R1 Decision Gate
Block present as first fenced block under the title; six required lines populated; Result: is PROCEED or HALT (<reason>).
R2 Mandatory sections
All 14 sections from the template present in order, no extras inserted between them.
R3 No TBD in mandatories
Problem Statement, Proposed Solution, Key Hypothesis, Success Metrics rows, AC-N items must not contain TBD. Permitted in Open Questions, in Research Summary when research degraded, and in deferred risk mitigations.
R4 AC count and shape
At least 3 AC-N items; each begins with **AC-N <name>:** and is observable (Given/When/Then or input→output).
R5 TDD routing
Reads tdd: from docs/context/methodology.md and verifies the PRD's TDD routing line matches the corresponding verbatim string.
R6 No .claude/
Output path has no .claude/ prefix; PRD body does not reference .claude/PRPs/.
R7 Implementation Phases
Table with the canonical header row plus at least one data row with non-empty Phase, Description, Status.

Inline edit vs. writer handoff

Surgical edits — single sentence, single AC-N, single table row, typo, Open Question resolution — are applied via Edit with the narrowest possible old_string. Structural defects — regenerating Problem Statement / Proposed Solution / Key Hypothesis / Research Summary / restructured phases — invoke prd-writer via Task in draft-path mode with the user's change request as the brief.

research-web shipped

Path
plugins/relay/agents/research-web.md
Model
sonnet
Tool allowlist
WebSearch, WebFetch only
Invoked by
prd-writer during Phase 3 GROUNDING; reusable by any future relay agent that needs market context
Responsibility
Bounded market-context research for a feature idea — competitors, similar products, known patterns and anti-patterns, recent trends. Returns evidence with source URLs.
Caps (hard)
4 searches; 10 fetches; 8 findings.
Never does
Recommend, opine, or synthesize strategy. Fabricate findings. Emit a finding without a source URL. Exceed the caps. Use any tool beyond WebSearch / WebFetch.

Shared return shape

Both research agents return the same JSON shape so calling agents can consume them uniformly:

{
  "findings": [
    { "title": "...", "summary": "...", "evidence": "...", "source": "https://... or path/to/file.ts:123" }
  ],
  "gaps": ["sub-questions the search did not answer"],
  "degradation_reason": null,
  "scope_cap_reached": false
}

Empty findings with a non-null degradation_reason is a correct outcome (e.g., WebSearch unavailable, codebase empty) — never a fabricated fill.

Agent file format (convention)

Every relay agent follows the same file shape, matching the upstream Claude Code agent format used by prp-core and other plugins: 

---
name: agent-name
description: One-line imperative description used by the Agent tool for routing.
model: sonnet | opus | haiku
color: coral | green | blue | etc.
---

[agent system prompt — the body]

## Decision Gate (mandatory, before any action)
...evidence block template...

## Inputs
...what the caller passes...

## Protocol
...step-by-step protocol...

## Outputs
...exact output shape, always structured...

## Constraints (hard rules)
...what the agent must NOT do...

## Graceful degradation
...how to handle missing preconditions...

The structure is intentional: reviewers reading a new agent file know exactly where to find each section. Agents reading each other via the Agent tool also get consistent output format.

How commands invoke agents

Commands use the Agent tool (built into Claude Code) with subagent_type=<agent-name> and a prompt containing the agent's inputs. The agent executes inside its own session with its own tool allowlist. The command parses the verdict from the agent's final message and dispatches the next action.

This separation — commands as orchestration, agents as decision units — is what makes individual stages independently testable. You can invoke the test-runner agent directly via the Agent tool without going through /relay-test at all, useful when debugging the agent's classification heuristics in isolation.
