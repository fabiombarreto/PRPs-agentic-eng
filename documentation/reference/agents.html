Agents

The specialized Claude Code agents relay invokes. Each agent has a focused system prompt, a narrow tool allowlist, and a structured output format. Commands (slash commands) wrap agents with orchestration logic; the agents themselves are reusable single-responsibility units.

Implemented

test-runner shipped

Path
plugins/relay/agents/test-runner.md
Model
sonnet
Invoked by
/relay-test command, per attempt
Responsibility
Execute one attempt of a test suite, normalize the output, classify every failure (B3), return a structured verdict so the calling command can drive the auto-correction loop (B4).
Never does
Loop on its own. Modify tests. Modify production code. Invoke other agents. Write outside PRPs/reports/. Return unstructured verdicts.

Inputs (passed by the command)

worktree: absolute path to the worktree
attempt: 1-based attempt number
run_id: UUID shared across all attempts in this session
tier: unit | integration | e2e (optional; present when layered execution is active)
framework: pytest | playwright | vitest (optional; auto-detect when absent)
time_remaining_ms: wall-clock budget remaining
previous_record_refs: paths to prior attempts' record.json (for flakiness detection)

Outputs — verdict JSON in a fenced block

Returns exactly one of five verdicts:

GREEN
All tests passed (or all failures were flaky-retry-resolved). record_path references the attempt's record.
RETRY_NEEDED
At least one legitimate failure. Includes a feedback_for_implementer payload the command hands to the Implementer.
RETRY_FLAKY
All failures are flaky-suspected. Command should re-run the suite without invoking the Implementer.
ABORT_INFRA
Infrastructure broken (missing settings.json, Docker down, DB unreachable, normalizer failure). Includes reason so the command can decide whether to attempt recovery.
ABORT_TIME
Attempt entered with time_remaining_ms ≤ 0 or consumed so much time that continuing isn't meaningful.

Classifier heuristics (B3, inline in the agent prompt)

Three real categories plus a default:

infra
Regex against error messages: connection refused, ECONNREFUSED, psycopg.OperationalError, container not running, docker.errors.DockerException, OOMKilled, etc. Indicates the environment is broken, not the code.
flaky
Regex: timeout, timed out, race condition, port already in use. Also: same failure (same suite + test name) appears in a previous attempt AND the file it lives in wasn't modified since.
legitimate
Default — no infra pattern matched, no flaky pattern matched. The Implementer is expected to fix.
weak_test
Intentionally not implemented in B3 for MVP. The post-green reviewer (B5) is the actual guard against test weakening.

Redaction before persist

Env vars matching the redaction policy have their values replaced with [REDACTED] (or [REDACTED_URL] for connection strings) before stdout.log is written to disk. Never writes raw output that could contain secret values.

post-green-reviewer shipped

Path
plugins/relay/agents/post-green-reviewer.md
Model
sonnet
Invoked by
/relay-test-review command
Responsibility
Given a GREEN test state, verify the green wasn't achieved by weakening tests. Returns APPROVED or CHANGES_REQUESTED with a concrete concerns list.
Never does
Re-run tests. Modify code. Propose specific fixes (surface the weakening; let the caller decide on remediation). Return verdicts other than the two specified.

Inputs

worktree: absolute path
run_json_path: absolute path to run.json (must have outcome: GREEN)
base_branch: reference to diff against (default main/master)
run_id: UUID matching run.json

Detection rules

test_removed
Count per-language regex matches on removed - lines: def test_*, it(, test(, describe(, func Test*, rspec block heads. Net-negative (after offsetting additions to tolerate renames) is a concern.
test_skipped
Count added + lines matching skip markers: @pytest.mark.skip, @unittest.skip, .skip(), xit(, xdescribe(, test.skip, t.Skip(). Net-positive is a concern.
trivial_assertion
Best-effort: flags crystal-clear cases like expect(true).toBe(true), assertTrue(True), assert True. Doesn't over-fire.
coverage_drop
If PRPs/reports/coverage-baseline.json exists, compares current coverage to it. Absolute drop > 5% is a concern. When baseline is missing, emits a notes[] entry rather than blocking approval.

Verdict structure

{
  "verdict": "APPROVED" | "CHANGES_REQUESTED",
  "run_id": "...",
  "analyzed_files": 7,
  "concerns": [
    { "type": "test_removed", "file": "...", "net_removed": 2, "evidence": ["..."] }
  ],
  "notes": [
    "coverage baseline unavailable (no PRPs/reports/coverage-baseline.json)"
  ]
}

prd-writer shipped

Path
plugins/relay/agents/prd-writer.md
Model
sonnet
Invoked by
/relay-prd command (Phase A)
Responsibility
Drive the interactive 6-phase PRD authoring flow with the user (Initiate → Foundation → Grounding → Deep Dive → optional re-grounding → Decisions → Generate). Invoke research-web and research-codebase in parallel during GROUNDING. Consult the three Decision Gate sources (decisions.md, anti-patterns.md, architecture.md) and emit the evidence block as the first fenced block of the PRD. Read methodology.md for the TDD routing note. Write the DRAFT to PRPs/prds/<kebab>.prd.md.
Never does
Approve its own output (the reviewer owns the flip). Skip phases. Fill mandatory sections with plausible filler instead of TBD - needs validation. Overwrite an existing PRD (collision uses numeric suffix; APPROVED files never overwritten). Write under .claude/.

Inputs (passed by the command)

mode: blank | description | draft-path
description: free-text (when mode == description)
draft_path: absolute path (when mode == draft-path; the command has
            already verified the file is not APPROVED)
target_root: absolute path to the target project root

Draft-path: skip-on-answered detection

When invoked with a draft path, the writer reads the draft and detects which Phase 1, 2, 4, and 6 questions are already answered. A question counts as answered when the draft has a heading or paragraph addressing it, content of at least one complete sentence, and no TBD / TODO / {placeholder} prefix. Answered questions are skipped; only unanswered ones go to dialogue.

prd-reviewer shipped

Path
plugins/relay/agents/prd-reviewer.md
Model
sonnet
Invoked by
/relay-prd command (Phase B), after the writer hands off the DRAFT
Responsibility
Validate the DRAFT against the 7-item structural rubric plus the additive R-COH-* coherence layer (deterministic intra-PRD checks + a bounded K=5 LLM judgment pass). On full pass (R1–R7 plus all R-COH-* rows passed: true), ask the user to approve in free-text dialogue. On explicit approval, re-validate the rubric one final time, then flip *Status: DRAFT* to *Status: APPROVED* via two-line Edit and stamp *Approved: YYYY-MM-DD*. Append every verdict to PRPs/prds/<basename>.review.jsonl.
Never does
Approve without explicit user confirmation. Flip without the final pre-flip re-validation. Rewrite whole sections inline (structural defects route back to prd-writer via Task). Edit the DRAFT silently to make the rubric pass. Operate on a file whose status is already APPROVED (returns error: already_approved). Pad the K=5 LLM pass with synthetic contradictions to fill the cap — returning fewer than 5 findings (including zero) is the correct behavior when fewer real contradictions exist.

The 7-item rubric

R1 Decision Gate
Block present as first fenced block under the title; six required lines populated; Result: is PROCEED or HALT (<reason>).
R2 Mandatory sections
All 14 sections from the template present in order, no extras inserted between them.
R3 No TBD in mandatories
Problem Statement, Proposed Solution, Key Hypothesis, Success Metrics rows, AC-N items must not contain TBD. Permitted in Open Questions, in Research Summary when research degraded, and in deferred risk mitigations.
R4 AC count and shape
At least 3 AC-N items; each begins with **AC-N <name>:** and is observable (Given/When/Then or input→output).
R5 TDD routing
Reads tdd: from docs/context/methodology.md and verifies the PRD's TDD routing line matches the corresponding verbatim string.
R6 No .claude/
Output path has no .claude/ prefix; PRD body does not reference .claude/PRPs/.
R7 Implementation Phases
Table with the canonical header row plus at least one data row with non-empty Phase, Description, Status.

The R-COH-* coherence layer (additive)

Runs after R1–R7 and appends rows to the same rubric[] array of the per-PRD JSONL. The layer detects intra-PRD contradictions the structural rubric does not catch — ACs that contradict each other in prose, Success Metrics that don't measure the Key Hypothesis, Solution Detail that drifts from Proposed Solution, references to non-existent sections / ACs / phases, table-vs-prose number drift, Decisions Log entries that contradict the Proposed Solution. Two execution stages: deterministic checks first (regex / cross-reference validation), then a bounded K=5 LLM judgment pass over the full PRD body.

R-COH-NUMBER-DRIFT
Deterministic. Table row counts match prose mentions of the same noun (e.g. table says "5 phases", prose says "4 phases" → fail).
R-COH-SECTION-REF-MISSING
Deterministic. Every AC-<N>, Phase <N>, and section back-reference in the prose resolves to a token actually defined in the file.
R-COH-AC-CONTRADICT
K=5 finding. Two ACs contradict each other in prose. reason quotes both sides verbatim (Datadog "quote both sides" pattern).
R-COH-METRIC-HYPOTHESIS-DECOUPLED
K=5 finding. Success Metrics measure something the Key Hypothesis does not claim, or vice versa.
R-COH-SOLUTION-DETAIL-DRIFT
K=5 finding. Solution Detail describes a different approach than Proposed Solution.
R-COH-DECISIONS-CONTRADICT
K=5 finding. Decisions Log entries contradict the Proposed Solution or another Decisions Log entry.
R-COH-OTHER-INTERNAL-CONTRADICTION
K=5 finding. Catchall for findings that don't fit the named classes; the LLM picks this only as fallback.

The K=5 prompt is inline within this agent (no Task sub-agent dispatch — that pattern applies only to code-reviewer). The prompt instructs the model to return an empty array [] when no contradictions exist (no padding to 5), to quote contradicting fragments verbatim from both sides per finding, and to drop any candidate finding for which it cannot produce verbatim quotes from both sides. Temperature is 0.2 (evaluation-pass default). The combined rubric[] length per run is 9 to 14 rows: 7 (R1–R7) + 2 (deterministic R-COH-*) + ≤5 (K=5 pass).

Inline edit vs. writer handoff

Surgical edits — single sentence, single AC-N, single table row, typo, Open Question resolution — are applied via Edit with the narrowest possible old_string. Structural defects — regenerating Problem Statement / Proposed Solution / Key Hypothesis / Research Summary / restructured phases — invoke prd-writer via Task in draft-path mode with the user's change request as the brief.

plan-writer shipped

Path
plugins/relay/agents/plan-writer.md
Model
sonnet
Invoked by
/relay-plan command
Responsibility
Autonomously transform an APPROVED PRD into a per-phase DRAFT plan. Parses the source PRD's Implementation Phases table, selects the next actionable row (first pending row whose Depends cell is empty or references only complete rows), dispatches research-codebase and research-web in parallel during GROUNDING, consults the three Decision Gate sources (decisions.md, anti-patterns.md, architecture.md), writes the DRAFT to PRPs/plans/<feature>-phase-<N>-<slug>.plan.md with all 15 mandatory sections in order plus trailing *Status: DRAFT*, then back-fills the source PRD's row N (flips Status from pending to in-progress; populates the PRP Plan cell with the relative plan path). The ## Metadata table includes a phase_type field (scaffold / docs / refactor / feature) inferred from the phase Goal and task bodies (first-match wins); this field is consumed by plan-reviewer's Phase 0 pre-pass and the R-COH-VALIDATE-FRAMEWORK-MISMATCH exemption branch.
Never does
Approve its own output (the plan-reviewer owns the DRAFT→APPROVED flip per the interactivity boundary). Pick a row whose Depends cell references any pending or in-progress row. Skip the Decision Gate emission. Write under .claude/. Overwrite an existing plan (collision uses numeric suffix; APPROVED plans never overwritten). Mutate rows of the source PRD other than the row it is planning. Omit the canonical TDD routing label prefix in the plan's ## Notes section (codified in v0.7.1 patch to keep plan-reviewer R5 deterministic).
Tools
Task, Read, Write, Edit, Glob — Task for the parallel research subagent dispatch; Edit for the source PRD back-fill.

Per-phase plan filename pattern

Plans use the path PRPs/plans/<feature>-phase-<N>-<slug>.plan.md where <feature> is the source PRD basename (without .prd.md), <N> is the Implementation Phases row number, and <slug> is the kebab-cased phase name. The 2026-04-25 entry in docs/decisions.md records this divergence from the api-reference shorthand <feature>.plan.md — one PRD generates one plan per actionable phase, not one plan per feature. plan-reviewer R8c validates the back-reference between the plan filename and the source PRD's row N.

PRD back-fill discipline

Writing the plan file and back-filling the source PRD are both responsibilities of the writer (the source PRD becomes the single source of truth for "which phases have plans / are in-progress / are complete"). The back-fill is a single Edit against the row's table line with a verbatim-row old_string so collisions across concurrent invocations on the same PRD fail loud rather than silently corrupt the table. Concurrent writes are mitigated through serialization by the orchestrator (D2 of relay-execute.prd.md); robust file-lock semantics are deferred until Pillar 3 lands.

plan-reviewer shipped

Path
plugins/relay/agents/plan-reviewer.md
Model
sonnet
Invoked by
/relay-plan-review command
Responsibility
Validate the DRAFT plan against the 8-item structural rubric (R1–R8) plus the additive R-COH-* coherence layer (5 deterministic intra-plan checks + a bounded K=5 LLM judgment pass). Phase 0 pre-pass (v0.12.0): before rubric evaluation, reads the plan's ## Metadata table; if phase_type is absent, infers it from plan body signals (first match wins: scaffold → OS/filesystem-only VALIDATE commands; docs → doc-files-only Files to Change; refactor → restructuring primary action; feature → default) and writes the field inline. This is the only bounded exception to the no-inline-edit rule — the pre-pass runs once, before the rubric, never on CHANGES_REQUESTED. On full pass, auto-flip *Status: DRAFT* to *Status: APPROVED* via two-line Edit and stamp *Approved: YYYY-MM-DD* — no user dialogue (interactivity boundary). On any failure, emit a CHANGES_REQUESTED bullet list naming each failing rubric item by ID + reason; CHANGES_REQUESTED is terminal for the run. Append every verdict to PRPs/plans/<basename>.review.jsonl with all 8 R1–R8 outcomes plus zero or more R-COH-* outcomes.
Never does
Flip without the rubric pass (all 8 R1–R8 plus all R-COH-* must read passed: true). Flip without the final pre-flip re-validation. Short-circuit the rubric (R1–R8 always present, no duplicates among R1–R8). Inline-edit plan bodies on CHANGES_REQUESTED (no Task tool — no writer handoff in the autonomous flow); the Phase 0 phase_type pre-pass is the sole permitted exception and runs before the rubric, not on CHANGES_REQUESTED. Prompt the user. Operate on a file whose status is already APPROVED (returns error: already_approved). Pad the K=5 LLM pass with synthetic contradictions to fill the cap — returning fewer than 5 findings (including zero) is the correct behavior when fewer real contradictions exist.

The 8-item rubric

R1 Decision Gate
Block present as first fenced block under the # Feature: ... title; six required lines populated; Result: is PROCEED or HALT (<reason>).
R2 Mandatory sections
All 15 plan sections (Source PRD → Summary → User Story → Problem Statement → Solution Statement → Metadata → Mandatory Reading → Patterns to Mirror → Files to Change → NOT Building → Step-by-Step Tasks → Validation Commands → Acceptance Criteria → Risks and Mitigations → Notes) present in order, no extras inserted between them.
R3 No TBD in mandatories
Summary, Patterns to Mirror snippet headers and code blocks, Files to Change cells, Step-by-Step Tasks MIRROR/VALIDATE lines must not contain TBD. Permitted in Notes and in deferred Risks mitigations.
R4 Tasks count and shape
At least 3 tasks under ## Step-by-Step Tasks, each with a **VALIDATE**: line and a non-empty command on the same or following line.
R5 TDD routing
Reads tdd: from docs/context/methodology.md and verifies the plan's TDD routing line in ## Notes matches the corresponding verbatim string from prd-writer.md Step 7.4 byte-for-byte.
R6 No .claude/
Plan path has no .claude/ prefix; plan body does not reference .claude/PRPs/ except as quoted prohibition.
R7 Files to Change
Table with File / Action / Justification columns plus at least one data row with non-empty cells.
R8 PRD↔plan traceability
R8a: Source PRD section names a real APPROVED PRD. R8b: every plan AC-A item references at least one PRD AC-N that exists in the source PRD. R8c: plan filename pattern <feature>-phase-<N>-<slug>.plan.md; PRD row N has Status in-progress or complete with PRP Plan cell pointing at this plan.

The R-COH-* coherence layer (additive)

Runs after R1–R8 and appends rows to the same rubric[] array of the per-plan JSONL. The layer detects intra-plan contradictions the structural rubric does not catch — tasks that don't reference any AC, Files-to-Change rows that no task touches, VALIDATE commands incompatible with the project's declared frameworks, Patterns-to-Mirror SOURCE paths that don't exist, Mandatory Reading paths that don't exist, plus prose-level drift between Summary / Solution Statement and the Step-by-Step Tasks. Two execution stages: deterministic checks first (regex / cross-reference validation), then a bounded K=5 LLM judgment pass over plan-section pairs (HD-Eval-style criteria decomposition).

R-COH-TASK-AC-MISSING
Deterministic. Every Step-by-Step Task references at least one Acceptance Criterion (AC-A<i> or AC-<N> token).
R-COH-FILES-UNTOUCHED
Deterministic. Every row in the Files to Change table has at least one task whose body mentions the file path.
R-COH-VALIDATE-FRAMEWORK-MISMATCH
Deterministic. Every **VALIDATE**: command matches a framework declared in methodology.md's test_frameworks array. Silent-degradation branch when the array is empty: check skipped, passed: true with reason. Phase-type exemption branch (v0.12.0): when plan_phase_type (set by Phase 0) is scaffold or docs, check skipped with passed: true and reason "phase_type: <value>; VALIDATE commands are expected to use OS/filesystem tools rather than test-framework invocations for scaffold/docs phases". This exemption exists because scaffold and docs phases legitimately validate using OS/filesystem tools (Test-Path, Select-String, Get-ChildItem, npm install, etc.) — requiring a test-framework invocation in these phases would produce performative boilerplate rather than real validation.
R-COH-PATTERN-SOURCE-MISSING
Deterministic. Every # SOURCE: <path>:<line-range> header in Patterns to Mirror resolves to a real path with the cited range in bounds.
R-COH-MANDATORY-READING-MISSING
Deterministic. Every non-URL path in the Mandatory Reading table resolves under target_root.
R-COH-SUMMARY-TASKS-DRIFT
K=5 finding. Summary or Solution Statement claims approach X but Step-by-Step Tasks deliver approach Y.
R-COH-AC-TASK-DECOUPLED
K=5 finding. Plan AC-A item references behavior no task implements, or task delivers behavior no AC-A enforces.
R-COH-PATTERN-TASK-DRIFT
K=5 finding. Pattern-to-Mirror snippet content diverges from the referencing task's MIRROR claim.
R-COH-MANDATORY-READING-IRRELEVANT
K=5 finding. A Mandatory Reading row's "why" justification doesn't match the cited file's actual content.
R-COH-OTHER-INTERNAL-CONTRADICTION
K=5 finding. Catchall when none of the named classes apply.

The K=5 prompt is inline within this agent (no Task sub-agent — plan-reviewer has no Task tool). Section-pair decomposition (Summary vs. Tasks; ACs vs. Tasks; Patterns vs. Tasks; Mandatory Reading vs. cited files) anchors each finding to verbatim section-heading citations and quotes from both contradicting sides. Empty array [] when no contradictions exist (no padding to 5). Temperature 0.2 (evaluation-pass default). The combined rubric[] length per run is 13 to 18 rows: 8 (R1–R8) + 5 (deterministic R-COH-*) + ≤5 (K=5 pass).

AC-10 of plan-authoring.prd.md originally mandated the rubric[] array contain "exactly 8 objects … no extras". Phase 2 of the reviewer-coherence-layer feature consciously evolves this to "R1–R8 always present, no duplicates among R1–R8; R-COH-* rows additional"; the no-short-circuit invariant is preserved verbatim. The contract evolution is recorded as the 2026-04-28 entry in docs/decisions.md; the APPROVED plan-authoring.prd.md is not mutated.

implementer shipped

Path
plugins/relay/agents/implementer.md
Model
sonnet
Invoked by
/relay-implement command (internal dispatch per attempt)
Responsibility
Autonomous plan-driven code writer. Reads methodology + plan + source PRD; executes Step-by-Step Tasks via Edit/Write directly in the working tree (state accumulates across tasks per D6 aggregate validation); runs the plan's Validation Commands Levels 1–3 after all tasks complete; emits one of two verdicts: IMPLEMENTATION_COMPLETE with {files_changed, validation: {level_1/2/3}, validation_outputs}, or TEST_CONTRACT_DISPUTE with {disputed_tests, prd_refs, claim, proposed_resolution} when the plan's existing tests appear to contradict the PRD (D9 Layer 1 escape valve).
Never does
Modify test files without emitting a TEST_CONTRACT_DISPUTE verdict (universal R-X rule per D9 Layer 0). Re-ground via research subagents (no Task tool per D11 — the plan is the source of truth). Perform D8 post-approval mutations (those are /relay-implement's responsibility). Loop — the agent runs single-attempt per dispatch; the loop logic lives in /relay-implement's Phase A.
Tools
Read, Write, Edit, Glob, Grep, Bash, BashOutput, KillBash — Bash is open at the agent layer; the project's .claude/settings.json allowlist is the security gate per the 2026-04-19 narrow-patterns decision (codified as the 2026-04-30 D11 entry in docs/decisions.md).
Color
green

Verdict shapes

IMPLEMENTATION_COMPLETE
The implementer believes it has addressed every Step-by-Step Task and the plan's Validation Commands all pass (or are reported with their per-Level outcomes for the code-reviewer to evaluate). The verdict carries the list of files changed, per-Level PASS/FAIL for L1/L2/L3, and any captured validation output excerpts.
TEST_CONTRACT_DISPUTE
The implementer believes the plan's existing tests are contradictory with the source PRD's Acceptance Criteria. The verdict carries: disputed_tests (list of test file paths + line ranges), prd_refs (cited PRD AC-N items), claim (the implementer's structured argument why the tests are wrong), proposed_resolution (a description of how the tests would need to change to align with the PRD). Counts as one attempt; capped at max_disputes_per_session = 2. The code-reviewer arbitrates with one of three verdicts (DISPUTE_REJECTED / DISPUTE_UPHELD_TEST_WRONG / DISPUTE_UPHELD_PRD_AMBIGUOUS) per D9 Layer 2.

test-writer shipped

Path
plugins/relay/agents/test-writer.md
Model
sonnet
Color
green (red-green-refactor cycle association)
Tools
Task, Read, Write, Edit, Glob
Invoked by
/relay-write-test command (autonomous)
Responsibility
B7 of relay's Phase 2 trilho TDD. Reads the source PRD's ## Acceptance Criteria section + APPROVED plan; walks each in-scope AC and emits one of three per-AC outcomes: NEW_TEST_REQUIRED (writes a framework-idiomatic test file with comment header naming the source PRD + AC-N for traceability), EXISTING_TEST_COVERS path:line (records the AC→existing-test mapping in the suite manifest without writing a duplicate), or AMBIGUOUS (aborts with structured halt naming the AC and reason — the user must tighten the PRD). Writes the suite manifest at PRPs/reports/<feature>/test-suite.diff with aggregate verdict SUITE_DRAFT_WRITTEN or EXISTING_COVERAGE_SUFFICIENT and trailing *Status: DRAFT*.
Never does
Write production code (R-X strict's symmetric inverse — B7 is the only agent authorized to create test files in the autonomous pipeline; symmetrically forbidden from creating non-test files). Modify existing test files (always emits AMBIGUOUS or EXISTING_TEST_COVERS instead). Invent placeholder asserts when the AC is too abstract. Flip the suite manifest's status to APPROVED — that's /relay-test-write-review's job. Loop on CHANGES_REQUESTED from B8 — the orchestrator (/relay-execute) owns the retry budget max_tdd_review_retries=2.

Per-AC outcome shapes

NEW_TEST_REQUIRED
The AC describes behavior not currently covered by any test in the target's test root. B7 writes a framework-idiomatic test file (pytest, vitest, jest, ExUnit, RSpec, playwright, JUnit5 (Java, Maven/Gradle), Go go test, .NET/xUnit — selected from methodology.md test_frameworks[0]) with the AC encoded as a discriminative observable assertion. For a framework outside that list, B7 first attempts corpus discovery (mirroring the idiom of the project's existing tests) before falling back to AMBIGUOUS. The test body sets up minimal preconditions ("Given"), triggers the action ("When"), and asserts the observable ("Then"). Comment header carries the source PRD + AC-N path for traceability.
EXISTING_TEST_COVERS
The existing-coverage scan found a test that covers the AC. B7 records the mapping AC-N → existing_test_path:line in the suite manifest's ## AC outcomes table. No new test file is written; no existing test file is modified. When the existing test only partially covers the AC, B7 emits NEW_TEST_REQUIRED for the missing-property delta (a new test asserting only the uncovered properties).
AMBIGUOUS
The AC's prose lacks Given/When/Then concreteness, an unambiguous input/output example, or a discriminative observable that B7 can encode without inventing implementation details. Examples that trigger AMBIGUOUS: "the feature works correctly" (abstract), "performance is acceptable" (no measurable threshold), "the validateToken function returns false" (leaks imagined implementation). B7 halts with a structured message naming each ambiguous AC; partial test files for earlier-resolved ACs remain in the worktree. Note: precise ACs can also surface as AMBIGUOUS when the phase creates the types they name — that is a foundation phase, not a vague AC. The fix is to mark the plan phase_type: foundation (the TDD track then skips test-first for that phase) rather than to rewrite the PRD; B7's Phase 0 guard and /relay-write-test's P5 precondition self-skip this case before authoring begins.

The six-row rubric

R-IMPL-LEAK
Implementation-detail leakage. Fails when any test asserts on a private symbol (underscore-prefix, double-underscore, or visibility keyword), asserts on call-count of a specific method (when the AC does not name call count as the observable), embeds an internal method name in the test name, or asserts on a strict subset of the AC's required properties (TDD-Bench django-13401 pattern).
R-TRIVIAL-ASSERT
Trivial asserts. Fails on tautologies (expect(true).toBe(true)), existence-only assertions, strict-subset coverage of AC properties, or constant-input/constant-return tests when the AC describes a discriminative range.
R-MOCK-ABUSE
Four syntactic-categorical detections (no quantitative threshold in MVP): (1) mock of the SUT itself; (2) mock of a concrete type when an interface/protocol exists; (3) mock chained ≥3 levels deep; (4) was_called-only assertions without an effect check.
R-AC-COVERAGE
Every in-scope AC has ≥1 test reference (test name encoding the AC's observable, comment header naming the AC, or explicit EXISTING_TEST_COVERS mapping). Per yrkan.com Requirements Traceability Matrix convention; pass threshold for MVP: 100%.
R-DUPLICATE
Two tests asserting the same property without discriminative input variance (same equivalence class). Fails the pair, not just one.
R-RED-LEGITIMATE
Hybrid static + dynamic check. Dynamic: invokes the project's test command via Bash; non-zero exit + assertion-failure output = passed: true (red for the right reason); non-zero exit + import/compile/setup-error output is classified via the seam-set discriminator — if every unresolved symbol is in the plan's ## Files to Change CREATE/UPDATE set the failure is legitimate red-by-design (passed: true, the test drives a not-yet-created production symbol; this makes compiled-language red first-class), otherwise it is broken setup (passed: false); zero exit = passed: false (suite green pre-implementation). Static fallback: when Bash is unavailable (framework not installed, sandbox restriction, Docker not running) → passed: null with reason: "degraded — test framework execution unavailable: …" per AC-13. The aggregate verdict treats null as non-blocking when all other rows pass.

The JSONL audit log path is PRPs/plans/<basename>.test-write-review.jsonl, paralleling the .review.jsonl and .code-review.jsonl conventions for plan-reviewer and code-reviewer. The schema admits passed ∈ {true, false, null} — the null value is reserved for R-RED-LEGITIMATE degraded environments and never appears for the other five rubric ids.

The 8-item rubric

R-S1 Tasks addressed
Every ### Task <i>: in the plan's Step-by-Step Tasks has its target file appearing in the diff (or, for CREATE actions, the new file exists).
R-S2 Files-to-Change rows
Every row of ## Files to Change has at least one corresponding change in the diff.
R-S3 AC observability
Every plan AC-A bullet has an observable counterpart in the diff (test or production code).
R-L1 Static analysis
Plan's Level-1 STATIC_ANALYSIS command exits 0.
R-L2 Unit tests / content invariants
Plan's Level-2 CONTENT_INVARIANTS / UNIT_TESTS command exits 0.
R-L3 Integration / dry-run
Plan's Level-3 INTEGRATION / DRY-RUN command exits 0.
R-SEM Semantic review
Diff's business-rule consistency, bugs, security gaps; alignment to plan task and PRD AC. The "primary value layer" per D4 of the source PRD.
R-X Test-modification guard
Diff does NOT touch test files (canonical pathspec set), unless a prior arbitration upheld the implementer's TEST_CONTRACT_DISPUTE. D17 straight-fail in standard mode without an upheld dispute.

The R-COH-* coherence layer (additive)

Runs after R-S*/R-L*/R-SEM/R-X in standard mode and appends rows to the same rubric[] array of the per-plan code-review jsonl. The layer detects intra-diff contradictions the structural and semantic rubric does not catch — dead imports, signature changes the diff didn't propagate to its own callers (within diff + 1-hop imports, M=10 cap), configuration references missing from touched config files, new files unregistered in expected indexes, plus comment-vs-code contradictions, test-name-vs-assert lies, and code that contradicts the source plan task's literal description. Two execution stages: deterministic checks first (inline in the parent agent via Bash/ast-grep/Grep), then a bounded sub-agent dispatch to code-reviewer-semantic via Task for the K=5 LLM judgment pass + a dedicated R-COH-TASK-CONTRADICTION check.

R-COH-DEAD-IMPORT
Deterministic. Imports declared but not referenced in the file body (per language; ast-grep / lint in report mode). Per-language degradation when the language isn't supported.
R-COH-CALLER-DRIFT
Deterministic. Function/method signatures changed in the diff without corresponding caller updates within diff + first-degree imports (M=10 hop cap).
R-COH-CONFIG-DANGLING
Deterministic. Configuration-key references in the diff (config["KEY"], getenv("KEY"), process.env.KEY, etc.) that aren't defined in the touched config files.
R-COH-REGISTRY-MISSING
Deterministic. New files (CREATE actions) under directories listed in docs/context/code-review-registries.md that aren't registered in the expected index files. Silent-degradation when the registries file is absent or empty.
R-COH-COMMENT-MISMATCH
K=5 finding (sub-agent). Comment in the diff contradicts the code below it; reason quotes both sides verbatim.
R-COH-TEST-NAME-LIES
K=5 finding (sub-agent). Test name describes one behavior but assertions check another.
R-COH-OTHER-INTERNAL-CONTRADICTION
K=5 finding (sub-agent). Catchall for findings that don't fit the named classes.
R-COH-TASK-CONTRADICTION
Dedicated check (sub-agent), always emitted as exactly one row. Diff's signature / parameter list / return type / observable behavior contradicts the source plan task's literal description. An extension of R-SEM, focused narrowly on intra-diff structural divergence vs. the plan task's statement.
R-COH-SEMANTIC-DEGRADED
Emitted by the parent (not the sub-agent) when the sub-agent's return is unparseable JSON or when its degradation_reason is set. Always passed: true with reason; the run continues, never halts.

The K=5 prompt is delegated to the code-reviewer-semantic sub-agent (the only relay reviewer that uses sub-agent dispatch — D2 of the source PRD: PRD/plan reviewers run K=5 inline because their artifacts are small markdown files; code-reviewer dispatches a sub-agent because diffs can be large and parent token budget pressures justify the factoring). The parent injects the diff + plan task + PRD AC excerpts into the sub-agent's prompt via XML tags (<diff>, <plan_task>, <prd_acs>, <instructions>) per Anthropic best practices. The sub-agent is read-only (tools: Glob, Grep, Read); no Bash, no Edit, no Write, no Task. Empty findings: [] when no contradictions exist (no padding). Temperature 0.2.

AC-10 of implementation-authoring.prd.md originally mandated the rubric[] array contain "exactly one entry per rubric item evaluated, no duplicates, no extras". Phase 3 of the reviewer-coherence-layer feature consciously evolves this to "R-S*/R-L*/R-SEM/R-X always present, no duplicates among them; R-COH-* rows additional in standard mode". Arbitration mode (exactly 1 object with id arbitration) is unchanged. D11's read-only invariant is also preserved: Task is added to code-reviewer's tools EXCLUSIVELY for sub-agent dispatch; Edit remains absent. Both contract evolutions are recorded as the 2026-04-28 combined entry in docs/decisions.md; the APPROVED implementation-authoring.prd.md is not mutated.

Agent file format (convention)

Every relay agent follows the same file shape, matching the upstream Claude Code agent format used by prp-core and other plugins: 

---
name: agent-name
description: One-line imperative description used by the Agent tool for routing.
model: sonnet | opus | haiku
color: coral | green | blue | etc.
---

[agent system prompt — the body]

## Decision Gate (mandatory, before any action)
...evidence block template...

## Inputs
...what the caller passes...

## Protocol
...step-by-step protocol...

## Outputs
...exact output shape, always structured...

## Constraints (hard rules)
...what the agent must NOT do...

## Graceful degradation
...how to handle missing preconditions...

The structure is intentional: reviewers reading a new agent file know exactly where to find each section. Agents reading each other via the Agent tool also get consistent output format.

How commands invoke agents

Commands use the Agent tool (built into Claude Code) with subagent_type=<agent-name> and a prompt containing the agent's inputs. The agent executes inside its own session with its own tool allowlist. The command parses the verdict from the agent's final message and dispatches the next action.

This separation — commands as orchestration, agents as decision units — is what makes individual stages independently testable. You can invoke the test-runner agent directly via the Agent tool without going through /relay-test at all, useful when debugging the agent's classification heuristics in isolation.
