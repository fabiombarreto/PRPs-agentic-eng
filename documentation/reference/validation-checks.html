Validation checks

The complete catalog of what the validation suite tests. Each registered static check and the behavioral eval layer is documented with the functionality it guards, a concrete example that passes, a concrete example that fails (with the exact finding text the check emits), and the unit tests that cover it. The Summary table below carries the current check count. For the why-and-how overview, see the Validation suite guide.

How to read this page

Every check returns the shared contract { name, ok, findings: [{ message, file, line }] }. Most are a pure function (operates on already-read inputs) plus a wrapper (does the file I/O); native-validate is wrapper-only. The runner (scripts/validate/index.mjs) runs every registered check with no short-circuit, prints one line per check plus each finding as file:line — message, and exits non-zero if any check failed. Finding messages below are quoted verbatim from the check source.

version-parity

Functionality. Enforces the AGENTS.md §7.5 lock-step rule: the version in plugins/relay/.claude-plugin/plugin.json must equal the latest released version in documentation/changelog.html. "Latest released" is the first versioned <h2> heading, skipping the always-first id="unreleased" heading; the separator after the version is irrelevant and non-version headings do not stop the scan. Reads exactly those two files.

Passes when the manifest and the latest release agree — e.g. plugin.json version 0.20.0 and changelog <h2 id="unreleased">Unreleased</h2> then <h2 id="v0-20-0">0.20.0 — 2026-07-12</h2>. This is the current tree state.

Fails when they drift — e.g. manifest 0.20.0, latest release 0.19.0:

version mismatch: plugins/relay/.claude-plugin/plugin.json declares "0.20.0" but the latest documentation/changelog.html release is "0.19.0"

It also fails loud (a finding, never a crash) on a missing/unparseable manifest, a manifest with no version, or a changelog with no versioned heading (only "Unreleased").

Unit tests (14). Match passes with no findings; mismatch fails naming both versions; the Unreleased heading is skipped even when it looks like a version; the first versioned heading is taken; both the &#8212; entity and a literal em-dash separator parse; and six robustness cases (missing / non-JSON / no-version manifest; missing / unparseable / only-Unreleased changelog); plus a scope test that an unrelated third input is never read.

native-validate

Functionality. Shells out to claude plugin validate ./plugins/relay --strict (via spawnSync, no shell), delegating to Claude Code's own frontmatter / kebab-case / wrong-type-field validator, scoped to the relay plugin tree only. A non-zero exit becomes a finding; when the claude CLI is unavailable it degrades to a clean skip.

Passes when the native validator exits 0 — or when claude is not on PATH (degrades to ok: true with a note). Both surface as [PASS].

Fails when the validator exits non-zero (e.g. malformed frontmatter). The finding, where the tail is the last 2000 chars of combined stdout+stderr:

claude plugin validate ./plugins/relay --strict exited 1: <tail>

The graceful-skip note (not a finding) reads native validator skipped: "claude" CLI unavailable (…).

Unit tests (5). Exit-0 passes; a non-zero exit surfaces the code + tail; a missing CLI degrades cleanly (ok, note set); a very long tail is truncated; and the invocation is scoped to ./plugins/relay, never prp-core. All use a hermetic fake claude executable, never the real CLI.

registration-parity

Functionality. Cross-references the on-disk command set (plugins/relay/commands/*.md) and agent set (plugins/relay/agents/*.md) against three documentation surfaces: the NAV array in assets/js/app.js, assets/data/search-index.json, and changelog.html. NAV is page-level, so it is only checked structurally (must reference the commands and agents reference pages). Commands get a full missing-and-stale diff on the other two surfaces (anchored on /relay- with a negative lookbehind so path segments do not false-positive); agents are checked missing-direction only.

Passes when every shipped command and agent is referenced where expected and no doc references a command that has no file — e.g. command relay-plan and agent plan-writer both mentioned across the surfaces, and NAV pointing at both reference pages.

Fails when a surface drifts. Representative findings:

command "relay-execute" is registered under plugins/relay/commands/ but is not referenced (as "/relay-execute") in documentation/assets/data/search-index.json
documentation/assets/data/search-index.json references "/relay-old-thing" but plugins/relay/commands/relay-old-thing.md does not exist
agent "ghost-writer" is registered under plugins/relay/agents/ but is not referenced in documentation/changelog.html
documentation/assets/js/app.js NAV does not reference reference/commands.html

This is the check that caught the stale relay-tdd names and the six commands missing from the search index.

Unit tests (11). Consistent surfaces pass; a command missing from the search index fails; a stale command mentioned but absent fails; an agent missing from the changelog fails while a stray mention never produces a stale finding; both missing NAV reference pages fail; a mid-path /relay- never false-positives; four missing-input cases; and a real-wrapper test that no finding ever resolves under prp-core.

path-existence

Functionality. Scans every .md under plugins/relay/ and docs/ (never prp-core) and flags dangling references, using a precision-first allowlist of three reference classes: backtick-quoted repo scripts/… paths; ${CLAUDE_PLUGIN_ROOT}/{agents,commands,skills,.claude-plugin,scripts}/… plugin assets; and intra-repo markdown links to docs/…md or documentation/…html. Placeholder and example tokens (<…>, *, feat-x, foo-bar, anything after "example"/"e.g.") are skipped, so it never fires on illustrative prose.

Passes when every in-scope reference resolves on disk — e.g. a doc citing scripts/validate/index.mjs, which exists.

Fails when a reference is dangling — the canonical example is a doc citing scripts/normalize-test-output.py when only the .mjs sibling exists:

dangling reference "scripts/normalize-test-output.py" — resolved path "scripts/normalize-test-output.py" does not exist on disk

Unit tests (8). All-resolve passes; a dangling reference is named with raw token + resolved path + file:line; the wrapper-level worked example flags the .py but not the real .mjs; every dangling reference aggregates with no short-circuit; missing input fails loud; an empty array passes (distinct from null); a malformed entry is treated as failing (fail-safe); and no finding resolves under prp-core.

dispatch-graph

Functionality. Reads the bodies of plugins/relay/commands/*.md and enforces the dispatch graph: every subagent_type: X must resolve to plugins/relay/agents/<X>.md, and every Next: pointer to a /relay-x command must resolve to a command file. An optional relay: namespace prefix on the agent name is normalized away first; the Next: scan only fires on lines that literally contain Next:.

Passes when every dispatch resolves — e.g. a command with subagent_type: plan-writer (agent exists) and Next: /relay-plan-review (command exists). The namespaced forms subagent_type: relay:code-reviewer and Next: /relay:relay-plan-review resolve the same way.

Fails when a target is missing:

references subagent_type "ghost-agent" but plugins/relay/agents/ghost-agent.md does not exist
Next: pointer references "/relay-ghost-command" but plugins/relay/commands/relay-ghost-command.md does not exist

A namespaced miss is reported using the normalized name, never the raw relay:x form.

Unit tests (11). All-resolve passes; a bare unresolved subagent_type fails; a namespaced reference normalizes and resolves; a namespaced miss reports the normalized name; an unresolved Next: fails; a namespaced Next: resolves; a /relay-x mention without Next: is ignored; and four robustness cases (missing listing, unreadable file, null agent set treated as empty, no prp-core findings).

frontmatter-schema

Functionality. Validates the YAML frontmatter of every command, agent, and SKILL.md under plugins/relay/ against a per-type JSON Schema (via ajv). Agents get an extra code-level check that the frontmatter name equals the filename stem. Required fields per type:

command
requires description and argument-hint; forbids name.
agent
requires name, description, model, color, tools — plus name must equal the filename stem.
skill
requires name and description.

Passes when frontmatter is complete — e.g. an agent plan-writer.md with name: plan-writer, description, model, color, and tools all present.

Fails when a required field is missing (this is the check that caught two agents missing tools) or a rule is broken:

frontmatter schema violation at "<instancePath>": <ajv message>
agent frontmatter "name" ("foo") does not match filename stem ("bar")

Unit tests (13). Valid command / agent / skill each pass; a command carrying a forbidden name fails; a command missing description fails; an agent missing tools fails; an agent whose name mismatches its stem fails; a skill missing description fails; missing input fails loud; an unparseable frontmatter surfaces the parse error verbatim; an unknown component kind fails without a throw; two invalid files back-to-back attribute the right errors to the right file; and no prp-core findings.

artifact-naming

Functionality. Scans PRPs/plans/*.jsonl (top level only) for a doubled .plan segment in review-log filenames. The correct forms are <basename>.review.jsonl, <basename>.code-review.jsonl, and <basename>.test-write-review.jsonl.

Passes when names follow the convention — e.g. foo-phase-1-bar.review.jsonl. A name that merely contains "plan" does not false-positive.

Fails when the .plan segment is doubled — e.g. …rename-behavior-preserving.plan.review.jsonl:

doubled ".plan" segment in artifact filename — expected "<basename>.review.jsonl", "<basename>.code-review.jsonl", or "<basename>.test-write-review.jsonl"

Unit tests (6). Correct names pass; the worked example (.plan.review.jsonl) is caught; the doubled form is caught for the code-review and test-write-review suffixes too; a name merely containing "plan" does not false-positive; missing input fails loud; an empty array passes.

bootstrap-parity

Functionality. Reads exactly plugins/relay/skills/context-builder/SKILL.md and enforces Windows parity: if it emits a worktree-bootstrap.sh template it must also emit a worktree-bootstrap.ps1 template. Asymmetric — only .sh-implies-.ps1 is required; emitting neither is fine.

Passes when both templates are emitted, or neither is, or only .ps1 is.

Fails when the skill emits .sh with no .ps1 sibling:

plugins/relay/skills/context-builder/SKILL.md emits a worktree-bootstrap.sh template but no matching worktree-bootstrap.ps1 template — Windows hosts have no bootstrap script parity

Unit tests (6). Both-present passes; neither-present passes; the worked example (.sh without .ps1) is caught; only-.ps1 passes (the documented asymmetry); a word-boundary anchor rejects similar-but-different tokens; and missing input fails loud.

gating-structure

Functionality. Reads exactly plugins/relay/skills/context-builder/SKILL.md and verifies that every registered gating site — an opt-in methodology key such as figma_track, which must never be flipped by heuristic — documents all three properties the docs_sync key established as precedent: deterministic default-value emission on *init, preserve-on-*update (never mutate an already-set value), and backfill only when the key is entirely absent. Two sites are registered today, figma_track and visual_first_approval; each contributes three markers, so six marker assertions run on every invocation. Extensible by design: a future opt-in key appends an entry to the module's SITES array rather than adding a new check module.

Passes when all three markers are present for every registered site — the current tree state, where SKILL.md documents both keys completely. Each site is evaluated independently, so one fully-documented key never masks a gap in another.

Fails when a marker is missing, one finding per missing marker with no short-circuit:

gating site "figma_track" missing required marker "default-false-emission" (non-heuristic discipline undocumented)
gating site "visual_first_approval" missing required marker "backfill-only-when-absent" (non-heuristic discipline undocumented)

Note that the marker id preserve-on-update is shared across sites, so the finding always names the site as well as the marker. It also fails loud (a finding, never a crash) on an absent or unreadable skill file, via missing file: … and could not read ….

Unit tests (12). All-markers-present passes with zero findings; each of figma_track's three markers fails independently when removed; all three missing at once produces exactly three findings, scoped to that site while visual_first_approval stays satisfied; the same four tests mirror for visual_first_approval (its emission marker is default-auto-emission, and its preserve-on-update test asserts the site name explicitly, since that marker id is shared); missing input (null, undefined, empty string) fails loud rather than throwing; a real-wrapper test runs against the actual SKILL.md; and a registration test pins the wiring in scripts/validate/index.mjs.

feedback-chain

Functionality. Verifies that the writer-side prior_feedback contract stays wired end to end across the six prompt files it watches (three command/agent pairs). It enforces three groups of invariants. First, for each registered writer pair (relay-plan/plan-writer, relay-write-test/test-writer, relay-implement/implementer), the command must forward prior_feedback, the agent must declare it, and the agent must carry a ## Targeted revision mode section. Second, three plan-writer-specific invariants that a bare presence grep cannot express: the input is declared in both the PRD-mode and description-mode groups, the Phase 2 grounding carve-out names all four grounding-dependent rubric ids, and the "Re-grounding without cause" anti-pattern agrees with Phase 2 rather than stating a stale unqualified rule. Third, each writer's pre-emission self-check block exists, frames itself as front-running rather than replacing the reviewer, and states artifact properties in its item lines instead of quoting the reviewer's rubric — together with three guards on where and how those blocks sit: plan-writer's must precede its write step or it is not pre-emission, implementer's must stay a labelled block rather than becoming a third ### Phase 4. heading (a corpus test pins that count at two), and test-writer's original lifecycle-ledger sentence must survive the extension verbatim.

Passes when all six watched files carry the contract — the current tree state. The third group's rule is deliberately scoped to item lines only (numbered or dash-prefixed): a rubric id in the surrounding prose is required, not forbidden, because test-writer's closing parenthetical must name R-LIFECYCLE-LEGITIMATE and R-AC-COVERAGE to establish the front-running framing. A whole-block prohibition would contradict the design it guards.

Fails when any link in the chain is cut. Representative findings:

command does not forward prior_feedback to plugins/relay/agents/plan-writer.md; its retries regenerate blind
writer does not declare prior_feedback, so plugins/relay/commands/relay-implement.md forwards it into a void
writer declares no "## Targeted revision mode" section, so a retry has no protocol to correct rather than regenerate
input-declared-in-both-mode-groups: prior_feedback missing from the description mode input group(s); a retry in that mode stays blind
self-check does not state that it front-runs (rather than replaces) the reviewer's independent rubric
expected exactly 2 '### Phase 4.' headings, found 3 — a corpus test pins this count

It exists because the fix it guards is prose spread across five of those six files (relay-implement.md, the sixth, already forwarded the input and needed no change), so nothing mechanical would otherwise stop a later edit from silently re-severing it — the exact failure the check was written after. It also discharges three verification gaps that were accepted as technical debt during its own feature's plan review, converting them from one-time manual checks into permanent gates. Extensible the same way gating-structure is: a new writer pair appends to PAIRS, a new self-check to SELF_CHECKS.

Unit tests (23). A baseline fixture satisfying every invariant passes; each of the three pair-level failures is caught independently; input-declared-in-both-mode-groups is covered in four directions (PRD-mode missing, description-mode missing, no Inputs section, no description-mode split); the grounding carve-out names the omitted id; the re-grounding anti-pattern fails both on a missing "per DRAFT" qualifier and on an omitted carve-out id; the self-check rules cover an absent block, a missing front-run framing, and an item line quoting a rubric token — paired with two complementary tests establishing that a rubric token in surrounding prose is accepted, one on the real fixture's own parenthetical and one on a token inserted deliberately, which is what distinguishes the real rule from a naive whole-block ban; the plan-writer ordering guard catches a self-check placed after the write step; the implementer heading count fails in both the too-few and too-many directions; the test-writer lifecycle-ledger sentence is pinned verbatim; one looped test covers every unreadable-input shape without throwing; and a real-wrapper test plus a registration test cover the live tree and the index.mjs wiring.

timestamp-contract

Functionality. Mechanically enforces the review_started_at contract shipped in v0.25.0 (commit e0a0c17): a registry of seven jsonl-appending reviewers and eight dispatching commands under plugins/relay/ (three deliberate exclusions — post-green-reviewer, code-reviewer-semantic, relay-execute — are commented in the module rather than silently omitted). Per reviewer it asserts a declared review_started_at input, a "### Timestamp discipline (mandatory)" section naming T00:00:00 as explicitly unacceptable, and a fallback branch that matches the reviewer's own capability — derived at runtime by parsing its tools: frontmatter line for a Bash entry, never hardcoded — so a Bash-capable reviewer must self-serve date -u +%Y-%m-%dT%H:%M:%SZ and must not instruct setting timestamp_degraded, while a clockless reviewer must do the reverse. The degraded-flag assertion distinguishes an instruction to SET the flag from the phrase "never sets timestamp_degraded", which appears verbatim in every Bash-capable reviewer and would make a naive substring test vacuous. Per command it asserts the date -u +%Y-%m-%dT%H:%M:%SZ capture and the review_started_at pass-through. Beyond prose, it scans PRPs/plans/*.jsonl for verdict entries at or after the marker recorded in PRPs/reports/efficiency/v0.25.0.json and fails any post-marker entry stamped T00:00:00 without an accompanying timestamp_degraded flag; pre-marker entries are exempt by construction, and an absent or unparseable marker skips that assertion with a visible note rather than failing or silently passing.

CONSUMERS registry (consumer end of the contract). The assertions above gate only the PRODUCER half — that reviewers emit timestamp_degraded correctly. A separate CONSUMERS registry, currently listing scripts/efficiency.mjs, gates the CONSUMER half: a registered file's content is stripped of // line comments and /* */ block comments first, then must still contain at least one reference to timestamp_degraded — so a file that only documents the flag in a comment, without reading it in executable code, fails. scripts/eval.mjs and .claude/commands/efficiency-report.md are deliberately NOT registered (neither classifies jsonl artifacts by timestamp), carried as a comment in the module rather than a silent gap — mirroring feedback-chain.mjs's PAIRS registry, the in-repo precedent for gating both ends of a contract rather than only one.

Passes when every registered reviewer and command carries a compliant section, every registered consumer references timestamp_degraded in executable code, and no post-marker jsonl entry violates the output assertion — the current tree state.

Fails when any prose, consumer, or output invariant breaks. Representative findings:

does not declare a review_started_at input
no "### Timestamp discipline (mandatory)" section found
Bash-capable reviewer's Timestamp discipline section instructs setting timestamp_degraded, but this reviewer has Bash and must self-serve the instant instead
clockless reviewer's Timestamp discipline section instructs date -u, but this reviewer has no Bash tool to run it
does not capture the instant with date -u +%Y-%m-%dT%H:%M:%SZ
registered consumer does not reference timestamp_degraded in executable code (comment-only or absent)
post-marker jsonl verdict entry carries a T00:00:00 timestamp without an accompanying timestamp_degraded flag

Unit tests (26). A baseline fixture satisfying every prose invariant across all seven reviewers and eight commands simultaneously passes; two WATCHED_FILES shape tests cover the registry itself, one confirming every registered path (including the CONSUMERS entry) is present without duplicates and one confirming the three deliberately excluded reviewer/command paths are absent; three per-reviewer prose classes are each caught independently (missing review_started_at, a missing "### Timestamp discipline (mandatory)" section, a section that drops the T00:00:00 unacceptability sentence); the four-test load-bearing capability class covers a Bash-capable reviewer instructed to SET timestamp_degraded failing, the negation-trap discriminator proving that same reviewer's real "never sets" wording still passes (so a naive substring test would be vacuous), a clockless reviewer instructed to run date -u it has no tool for failing, and granting Bash to an otherwise-unchanged clockless reviewer's tools: line flipping its expected branch from passing to failing; two per-command prose tests cover a missing date -u +%Y-%m-%dT%H:%M:%SZ capture and a missing review_started_at pass-through; four consumer-end tests cover a genuine executable reference passing, a reference appearing only inside a // line comment failing, one appearing only inside a block comment failing, and the two deliberate CONSUMERS omissions (scripts/eval.mjs, .claude/commands/efficiency-report.md) being both absent from the registry and documented in the module source; five jsonl-output tests cover a post-marker T00:00:00 entry without the flag failing, the same entry with the flag passing, a pre-marker T00:00:00 entry passing (historic entries are exempt by design), an absent marker skipping with a visible note, and an unparseable marker skipping with a visible note; one looped robustness test exercises six malformed/missing input shapes without throwing; two wrapper-level tests exercise the runTimestampContractCheck filesystem error paths directly — a missing watched file and an unreadable one sitting as a directory; and the suite closes with a real-wrapper test against the actual repository tree plus an index.mjs registration test.

plugin-root-resolvable

Functionality. Closes the two blind spots path-existence structurally cannot cover, now that the eight plugin-owned resource templates live under plugins/relay/resources/. Walks every .md, .mjs, and .js file under plugins/relay/ (skipping node_modules and .git) and applies two rules with different anchoring strategies.

R1 — unprefixed resource citation
Backtick-anchored, mirroring path-existence's own token resolution. Any citation of one of the eight packaged basenames (prd-template.md, plan-template.md, design-spec-template.md, component-map-template.md, redaction-policy.md, settings-allowlist.md, test-output-schema.md, mock-sentinels.md) in any form other than the exact ${CLAUDE_PLUGIN_ROOT}/resources/<basename> prefix — bare, or carrying any other path.
R2 — monorepo path leak
Raw-line scanned rather than backtick-anchored, because its two shapes usually sit inside fenced shell blocks that are never wrapped in inline backticks: a literal <target_root>/plugins/relay/… path, and a --prefix plugins/relay/… invocation.

R1 covers a class that stayed invisible for five releases because this repository is simultaneously the plugin's source and its own dogfooding target: a bare docs/context/<x>.md-shaped citation resolved correctly here and nowhere else. R2 covers the defect the resource-packaging work started from — visual-verification tooling resolving to nothing in every installed instance because a script path was authored against the monorepo layout instead of ${CLAUDE_PLUGIN_ROOT}.

R2 is deliberately scoped to those two concrete shapes rather than any backtick-quoted plugins/relay/… substring. The repo's # SOURCE: provenance anchors and its "mirrors plugins/relay/agents/<x>.md" cross-file citations are a large and growing corpus of legitimate self-reference — documentary, not runtime-resolved — and flagging them would make npm run validate permanently red against correct content. The two chosen shapes carry no such ambiguity: <target_root> is never legitimately followed by plugins/relay/, since a target project's tree never contains that segment. The --prefix pattern is intentionally installer-agnostic — npm ci and npx accept the identical flag and would carry the identical defect, so anchoring on one installer's name would under-catch without buying precision.

Placeholder tokens (containing whitespace, angle brackets, *, or square brackets) and tokens preceded on the same line by an example marker (e.g., for example, example) are skipped — the same exclusion path-existence uses, so neither rule fires on illustrative prose.

Passes when every citation of a packaged resource uses the exact ${CLAUDE_PLUGIN_ROOT}/resources/ prefix and no file carries either R2 shape — the current tree state. An e.g.-preceded mention is illustrative and never flagged.

Fails when either rule fires, one finding per offending line with no short-circuit:

resource "mock-sentinels.md" cited as `mock-sentinels.md` — plugin-owned resources must be cited as `${CLAUDE_PLUGIN_ROOT}/resources/mock-sentinels.md`
literal "<target_root>/plugins/relay/…" path — a target project never contains a plugins/relay/ segment; use ${CLAUDE_PLUGIN_ROOT}/<subdir>/… instead
npm --prefix targeting "plugins/relay/…" — this path does not exist in the installed plugin cache; use ${CLAUDE_PLUGIN_ROOT}/<subdir>/… instead

Unit tests (8). Three cover R1: a bare basename is flagged while the correctly-prefixed form of the same basename in the same fixture is not; a path-suffixed stale citation (docs/context/prd-template.md) is flagged too, since any form but the exact packaged prefix is a finding; and an e.g.-preceded mention is not flagged. Three cover R2: a --prefix plugins/relay/… invocation inside a fenced bash block is caught, which is what proves the raw-line scan (a fenced block is never itself inline-backticked); the same shape under npx is caught identically, pinning installer-agnosticism; and a literal <target_root>/plugins/relay/… leak is caught. One pins a documented limitation rather than a defect — a bare script-path mention carrying neither prefix form is caught by neither rule, since R1 is scoped to the eight basenames and R2 to its two shapes — and carries a companion R1-triggering line in the same fixture, so the test proves the scan is genuinely active rather than vacuously skipping the file. The last asserts the { name, ok, findings } contract shape with ok deriving from findings.length === 0. Every fixture-writing test writes a disposable file under the check's own scan root and removes it in a finally, wrapped in a shared scan-root lock because node:test runs test files concurrently and other suites scan the same tree with no fixture isolation of their own.

metrics-isolation

Functionality. The anti-Goodhart guard for the usage-metrics artifact. No pipeline agent, command, or skill may reference the metrics artifact path: an LLM reviewer that could read its own pass-rate would have an incentive to approve leniently, which is the failure mode the whole measurement design exists to avoid. The artifact is written by an operator-invoked script and read by an operator; the pipeline never sees it. Scope deliberately covers plugins/relay/skills/ alongside agents/ and commands/ — skills/ holds context-builder, exactly the file a future phase would be tempted to teach about the metrics directory. A second, narrower rule covers the codebook: the metrics schema resource may name the path (it documents it), but no agent, command, or skill may cite the schema in a way that instructs reading the data.

diff-base-form

Functionality. Pins the form relay uses to derive a changed-file set. Pillar 2 never commits, and a feature worktree's HEAD never moves off its base — so git diff <base>..HEAD compares a commit to itself and returns an EMPTY set on every standard invocation. An empty set does not fail a rubric. It makes R-S1 trivially true, R-X (the universal test-modification guard) pass by vacuity, the arbitration path's purely-additive verification verify nothing, and the post-green weakening scan report “no weakening found” for every run. The failure is silent by construction: every run looks green.

Measured before the fix, on a worktree carrying five genuinely modified files: git diff --name-only <base>..HEAD returned 0 paths; git diff --name-only <base> returned 8. Nine call sites across two agents carried the two-dot form. Passes when every git diff in plugins/relay/agents/ and plugins/relay/commands/ uses the single-argument form — the current tree state.

Fails when the two-dot shape is reintroduced, or a scanned file is unreadable, or the scan set is empty (an empty scan cannot prove the invariant). Representative finding:

plugins/relay/agents/post-green-reviewer.md:261 — two-dot diff range against a diff base — use the single-argument form (`git diff <base>`), which compares the base against the working tree...

topology-contract

Functionality. Guards the repository-topology contract's exact-match parsing surface. lane-worktree-parity

Functionality. A lane gets its own filesystem only if it also gets its own branch — git refuses to check one branch out in two worktrees, so the branch dimension is forced by the path dimension rather than chosen alongside it. The two slugs therefore have to move together, and they appear on one line in two independent positions. Editing one and not the other is easy, and its consequence is invisible: the worktree paths would diverge per lane while the branch silently collapsed two lanes back onto one ref.

The check compares the two positions against each other rather than against a hardcoded expected token, for the same reason topology-contract does: a constant living in the check would itself drift. Vacuity is guarded explicitly — if the scanned sources yield zero creation commands, because a file moved or was reworded out of pattern range, the check fails rather than reporting a clean pass over an empty set.

missing or unreadable source file: plugins/relay/commands/relay-worktree.md
