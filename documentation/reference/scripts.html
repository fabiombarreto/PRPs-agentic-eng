Scripts

The helper scripts relay ships alongside agents and commands. All written in Node.js with zero npm dependencies so they run on every host regardless of the target project's language stack. Invoked via ${CLAUDE_PLUGIN_ROOT}/scripts/<name>.mjs.

Why Node.js, no dependencies

Claude Code itself runs on Node, so the node runtime is guaranteed available on any host where relay can run. Python is common but not universal — a pure Node / Go / Rust project may not have Python installed. Using Node as the script runtime makes relay truly portable across target projects regardless of their own stack.

Both scripts below are also built without external npm packages — not even xml2js or similar. The parsers are hand-rolled regex on stable formats (JUnit XML has a constrained shape). This keeps the plugin self-contained: cloning the repo and opening it in Claude Code is enough; no npm install step.

normalize-test-output.mjs shipped

Path
plugins/relay/scripts/normalize-test-output.mjs
Purpose
Normalize JUnit XML output from pytest / Playwright / Vitest into the relay canonical test-output schema v1.
Invoked by
test-runner agent, once per attempt. Also invocable directly for debugging.
Runtime
Node.js ≥ 18.
Dependencies
None. Uses only Node built-ins (fs, path, crypto).

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/normalize-test-output.mjs \
    --framework pytest|playwright|vitest \
    --junit path/to/junit.xml \
    [--tier unit|integration|e2e] \
    [--run-id <uuid>] \
    [--attempt <N>] \
    [--coverage path/to/coverage.json] \
    [--trace path/to/trace.zip]

Output: JSON conforming to schema v1 on stdout. Exit code 0 on success, 2 on invalid input (missing JUnit file, malformed XML).

What it does

  1. Parses the JUnit XML. Handles both <testsuites> roots and single <testsuite> roots, CDATA sections in <failure> bodies, standard XML entity escapes.
  2. Tallies counts per suite and aggregates: { passed, failed, skipped, total }.
  3. Extracts per-testcase failures: suite, test name, file, line, message, stack trace.
  4. Leaves failures[].category as null — the B3 classifier in the test-runner agent fills it in next.
  5. Emits the record with a generated-if-absent run_id (UUIDv4) and a generated_at timestamp.
  6. Determines outcome: PASSED if all pass, FAILED if any fail, SKIPPED_UPSTREAM_FAILURE if zero tests ran.

Framework-specific handling

pytest
<testcase> has classname in Python dotted form (mec10.apps.accounts.tests.test_user). File and line come from pytest's JUnit emission.
Playwright
classname is the spec file path. Traces are referenced via --trace flag (path only, not parsed).
Vitest
classname is the describe-block name. Coverage JSON (v8 provider) referenced via --coverage.

Example

node plugins/relay/scripts/normalize-test-output.mjs \
    --framework pytest \
    --junit reports/results.xml \
    --tier e2e \
    --attempt 1

Produces a record like (truncated):

{

  "attempt": 1,
  "tier": "e2e",

  "duration_ms": 11640,

      "suite": "mec10.apps.assessment.tests",
      "test": "test_evidence_factory_uses_sandbox_bucket",

generate-final-report.mjs shipped

Path
plugins/relay/scripts/generate-final-report.mjs
Purpose
Assemble the AC-10 compliant final-report.md for a Test Runner session from all its persisted artifacts.
Invoked by
/relay-pr command (future) as the last step before opening the PR. Also manually for audit.
Runtime
Node.js ≥ 18.
Dependencies
None.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/generate-final-report.mjs \
    <reports-dir> \
    [--out path/to/output.md]

Without --out, writes to <reports-dir>/final-report.md.

Inputs read from the reports directory

FileRequiredUsed for
run.jsonyesTop-level outcome, budgets, elapsed_ms, time_breakdown, attempt index, TDD mode flag, secrets_redacted summary, skipped components
test-review.jsonnoPost-green review verdict and concerns (rendered when present)
attempts/<N>/record.jsonyes for each NPer-attempt failures table with categorized failures
attempts/<N>/stdout.lognoReferenced in attempt detail (not rendered inline)
attempts/<N>/diff.patchnoReferenced in attempt detail

Missing optional files are handled gracefully — the corresponding section either shows "not run" or is omitted.

Report sections

The generated final-report.md contains, in order:

  1. Header: feature name, outcome badge with emoji, total duration, run ID, TDD track status, budgets.
  2. Summary table: attempts count, total wall-clock, post-green review verdict.
  3. Time breakdown: per-phase durations from run.json.time_breakdown.
  4. Failure classification histogram: counts per category (legitimate / infra / flaky / weak_test / unclassified) across all attempts.
  5. Per-attempt detail: for each attempts/<N>/, a section with outcome badge, duration, counts, tier, framework, log and diff pointers, and a failures table with category / suite / test / file:line / message.
  6. Post-green review: verdict, base branch, analyzed files, concerns list with evidence, notes.
  7. Secrets redaction: count + categories from run.json.secrets_redacted.
  8. Skipped components: name + reason for any graceful-degradation skip.
  9. TDD track: only present when tdd_mode: true — initial suite diff path, B8 review artifacts.
  10. Footer: generation timestamp and source artifacts path.

Output conventions

  • Durations formatted as 500ms, 30s, 4m 32s — readable to humans, not machine-parseable.
  • File paths in the Markdown always use forward slashes (attempts/1/stdout.log), even on Windows.
  • Message text in failures tables is truncated at 120 chars and | characters escaped to keep the table valid.
  • Outcome badges: ✅ for green/passed/approved, ❌ for failed, ⏱ for time-budget, 🔁 for oscillation, ⚠ for infra-unrecoverable, ⏭ for skipped.

auth-kit-secrecy.mjs shipped

Path
plugins/relay/scripts/auth-kit-secrecy.mjs
Purpose
Make it impossible to write a secret before the ignore rules are proven. Copies the packaged auth-kit.gitignore resource into <root>/PRPs/auth/.gitignore and proves with git check-ignore that every secret path is ignored.
Invoked by
/relay-auth-setup and /relay-auth-scripts; the generated per-role login scripts call it too, before any write. Also invocable directly.
Runtime
Node.js ≥ 18.
Dependencies
None. Synchronous Node built-ins only.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-kit-secrecy.mjs scaffold [--root <dir>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-kit-secrecy.mjs prove    [--root <dir>] [--path <relative-path>]...
node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-kit-secrecy.mjs ensure   [--root <dir>] [--path <relative-path>]...

The mode is mandatory. Exit code 0 when proven or done, 1 for FAILED_IGNORE_UNPROVEN, 2 for bad arguments (an unknown argument, a flag missing its value, no mode, an absolute --path, or a --path containing a .. segment), always without writing. ensure is the gate later phases call before any secret write. The only file the script ever writes is that tracked ignore file; it never reads, prints or writes a credential value.

auth-local-guard.mjs shipped

Path
plugins/relay/scripts/auth-local-guard.mjs
Purpose
The local-only guard of the test-auth kit: decides whether a target URL is a local application. The host comes from the WHATWG URL parser's own hostname component and is decided by exact equality against the built-in loopback names, or against hostnames declared in the tracked PRPs/auth/local-hosts.txt (one bare hostname per line, # comments allowed), each of which must resolve with every address loopback.
Invoked by
/relay-auth-setup and /relay-auth-scripts; the generated per-role login scripts call it too. Also invocable directly.
Runtime
Node.js ≥ 18.
Dependencies
None. node: built-ins only.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-local-guard.mjs check --url <url> [--root <dir>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-local-guard.mjs list-declared [--root <dir>]

The mode is mandatory. Exit code 0 when allowed, 1 for FAILED_NON_LOCAL_TARGET, 2 for bad arguments. A target carrying userinfo is refused even when its host is local. There is no per-run flag and no environment-variable source for declared hosts, and the script never writes any file.

qa-run.mjs shipped

Path
plugins/relay/scripts/qa-run.mjs
Purpose
The runner of the test-auth kit's consumer side. Parses a qa-report.md, gives every case exactly one of pass, fail, blocked or needs-human, captures redacted evidence and writes results.json under a fresh PRPs/reports/<feature>/qa-run/<run-id>/ directory. It never edits the report and ends every run by stating that the human validation gate is still open.
Record resolution
Before routing, a case whose coverage is automated is resolved from the Test Runner's schema-v1 record.json (the top-level record, else the latest attempt): the JUnit artifact it points at decides pass or fail per cited test file, with reason code AUTOMATED_EVIDENCE and evidence naming the record's run. A record outside schema v1, a run that executed nothing, a JUnit artifact written after the record, an unlisted file or a path matching more than one file all leave the case routed as before. results.json carries a separate record_resolved count; counts stays the four-outcome partition and the summary line excludes record-resolved cases from the driver-executed numbers.
Session proof
A kit login script now proves every saved or reused session in both directions: the probe must succeed with the session and fail without it, and a declared browser probe (an authenticated-only marker, optionally a role marker) is the proof for its role. FAILED_PROBE_NOT_PROTECTED, FAILED_PROBE_WRONG_ACCOUNT and FAILED_PROBE_PAGE_UNLOADABLE reach the report as named blocked reasons; every other session failure keeps SESSION_UNAVAILABLE.
Invoked by
/relay-qa-run. Also invocable directly.
Runtime
Node.js ≥ 18.
Dependencies
None of its own: node: built-ins only. playwright is resolved lazily at run time, from the project root and then from plugins/relay/scripts/visual/; when it is absent the HTTP and browser cases are blocked, never a crash.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs parse --report <path>
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs init --root <dir> --feature <slug> [--env-handle <path>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs run --root <dir> --feature <slug> --run-dir <rel-dir> [--env-handle <path>] [--max-cases <n>]

The mode is mandatory. Exit code 0 when completed, 1 for a named FAILED_* halt or an aborted run, 2 for bad arguments. The local-only guard runs before any request, login or write; one marked write helper is the only writer and refuses any path outside the run directory; evidence is redacted in memory before it is written.

How new scripts join the plugin

If a future stage needs a new helper script (e.g., a coverage-differ, a mutation-tester wrapper), it should follow the same pattern:

  1. Node.js .mjs file in plugins/relay/scripts/.
  2. Zero npm dependencies — Node built-ins only.
  3. CLI-style argv parsing with --flag value.
  4. Structured JSON or Markdown on stdout.
  5. Exit code 0 on success, 2 on invalid input, 1 on unexpected error.
  6. Narrow allow pattern added to plugins/relay/resources/settings-allowlist.md so the script is in the default .claude/settings.json the context-builder generates.
