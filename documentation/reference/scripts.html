Scripts

The helper scripts relay ships alongside agents and commands. All written in Node.js with zero npm dependencies so they run on every host regardless of the target project's language stack. Invoked via ${CLAUDE_PLUGIN_ROOT}/scripts/<name>.mjs.

Why Node.js, no dependencies

Claude Code itself runs on Node, so the node runtime is guaranteed available on any host where relay can run. Python is common but not universal — a pure Node / Go / Rust project may not have Python installed. Using Node as the script runtime makes relay truly portable across target projects regardless of their own stack.

Both scripts below are also built without external npm packages — not even xml2js or similar. The parsers are hand-rolled regex on stable formats (JUnit XML has a constrained shape). This keeps the plugin self-contained: cloning the repo and opening it in Claude Code is enough; no npm install step.

normalize-test-output.mjs shipped

Path
scripts/normalize-test-output.mjs
Purpose
Normalize JUnit XML output from pytest / Playwright / Vitest into the relay canonical test-output schema v1.
Invoked by
test-runner agent, once per attempt. Also invocable directly for debugging.
Runtime
Node.js ≥ 18.
Dependencies
None. Uses only Node built-ins (fs, path, crypto).

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/normalize-test-output.mjs \
    --framework pytest|playwright|vitest \
    --junit path/to/junit.xml \
    [--tier unit|integration|e2e] \
    [--run-id <uuid>] \
    [--attempt <N>] \
    [--coverage path/to/coverage.json] \
    [--trace path/to/trace.zip]

Output: JSON conforming to schema v1 on stdout. Exit code 0 on success, 2 on invalid input (missing JUnit file, malformed XML).

What it does

  1. Parses the JUnit XML. Handles both <testsuites> roots and single <testsuite> roots, CDATA sections in <failure> bodies, standard XML entity escapes.
  2. Tallies counts per suite and aggregates: { passed, failed, skipped, total }.
  3. Extracts per-testcase failures: suite, test name, file, line, message, stack trace.
  4. Leaves failures[].category as null — the B3 classifier in the test-runner agent fills it in next.
  5. Emits the record with a generated-if-absent run_id (UUIDv4) and a generated_at timestamp.
  6. Determines outcome: PASSED if all pass, FAILED if any fail, SKIPPED_UPSTREAM_FAILURE if zero tests ran.

Framework-specific handling

pytest
<testcase> has classname in Python dotted form (mec10.apps.accounts.tests.test_user). File and line come from pytest's JUnit emission.
Playwright
classname is the spec file path. Traces are referenced via --trace flag (path only, not parsed).
Vitest
classname is the describe-block name. Coverage JSON (v8 provider) referenced via --coverage.

Example

node scripts/normalize-test-output.mjs \
    --framework pytest \
    --junit reports/results.xml \
    --tier e2e \
    --attempt 1

generate-final-report.mjs shipped

Path
scripts/generate-final-report.mjs
Purpose
Assemble the AC-10 compliant final-report.md for a Test Runner session from all its persisted artifacts.
Invoked by
/relay-pr command (future) as the last step before opening the PR. Also manually for audit.
Runtime
Node.js ≥ 18.
Dependencies
None.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/generate-final-report.mjs \
    <reports-dir> \
    [--out path/to/output.md]

Without --out, writes to <reports-dir>/final-report.md.

Inputs read from the reports directory

FileRequiredUsed for
run.jsonyesTop-level outcome, budgets, elapsed_ms, time_breakdown, attempt index, TDD mode flag, secrets_redacted summary, skipped components
test-review.jsonnoPost-green review verdict and concerns (rendered when present)
attempts/<N>/record.jsonyes for each NPer-attempt failures table with categorized failures
attempts/<N>/stdout.lognoReferenced in attempt detail (not rendered inline)
attempts/<N>/diff.patchnoReferenced in attempt detail

Missing optional files are handled gracefully — the corresponding section either shows "not run" or is omitted.

Report sections

The generated final-report.md contains, in order:

  1. Header: feature name, outcome badge with emoji, total duration, run ID, TDD track status, budgets.
  2. Summary table: attempts count, total wall-clock, post-green review verdict.
  3. Time breakdown: per-phase durations from run.json.time_breakdown.
  4. Failure classification histogram: counts per category (legitimate / infra / flaky / weak_test / unclassified) across all attempts.
  5. Per-attempt detail: for each attempts/<N>/, a section with outcome badge, duration, counts, tier, framework, log and diff pointers, and a failures table with category / suite / test / file:line / message.
  6. Post-green review: verdict, base branch, analyzed files, concerns list with evidence, notes.
  7. Secrets redaction: count + categories from run.json.secrets_redacted.
  8. Skipped components: name + reason for any graceful-degradation skip.
  9. TDD track: only present when tdd_mode: true — initial suite diff path, B8 review artifacts.
  10. Footer: generation timestamp and source artifacts path.

Output conventions

  • Durations formatted as 500ms, 30s, 4m 32s — readable to humans, not machine-parseable.
  • File paths in the Markdown always use forward slashes (attempts/1/stdout.log), even on Windows.
  • Message text in failures tables is truncated at 120 chars and | characters escaped to keep the table valid.
  • Outcome badges: ✅ for green/passed/approved, ❌ for failed, ⏱ for time-budget, 🔁 for oscillation, ⚠ for infra-unrecoverable, ⏭ for skipped.

How new scripts join the plugin

If a future stage needs a new helper script (e.g., a coverage-differ, a mutation-tester wrapper), it should follow the same pattern:

  1. Node.js .mjs file in scripts/.
  2. Zero npm dependencies — Node built-ins only.
  3. CLI-style argv parsing with --flag value.
  4. Structured JSON or Markdown on stdout.
  5. Exit code 0 on success, 2 on invalid input, 1 on unexpected error.
  6. Narrow allow pattern added to docs/context/settings-allowlist.md so the script is in the default .claude/settings.json the context-builder generates.
