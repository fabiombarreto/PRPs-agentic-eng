Scripts

The helper scripts relay ships alongside agents and commands. All written in Node.js with zero npm dependencies so they run on every host regardless of the target project's language stack. Invoked via ${CLAUDE_PLUGIN_ROOT}/scripts/<name>.mjs.

Why Node.js, no dependencies

Claude Code itself runs on Node, so the node runtime is guaranteed available on any host where relay can run. Python is common but not universal — a pure Node / Go / Rust project may not have Python installed. Using Node as the script runtime makes relay truly portable across target projects regardless of their own stack.

Both scripts below are also built without external npm packages — not even xml2js or similar. The parsers are hand-rolled regex on stable formats (JUnit XML has a constrained shape). This keeps the plugin self-contained: cloning the repo and opening it in Claude Code is enough; no npm install step.

normalize-test-output.mjs shipped

Path
plugins/relay/scripts/normalize-test-output.mjs
Purpose
Normalize JUnit XML output from pytest / Playwright / Vitest into the relay canonical test-output schema v1.
Invoked by
test-runner agent, once per attempt. Also invocable directly for debugging.
Runtime
Node.js ≥ 18.
Dependencies
None. Uses only Node built-ins (fs, path, crypto).

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/normalize-test-output.mjs \
    --framework pytest|playwright|vitest \
    --junit path/to/junit.xml \
    [--tier unit|integration|e2e] \
    [--run-id <uuid>] \
    [--attempt <N>] \
    [--coverage path/to/coverage.json] \
    [--trace path/to/trace.zip]

Output: JSON conforming to schema v1 on stdout. Exit code 0 on success, 2 on invalid input (missing JUnit file, malformed XML).

What it does

  1. Parses the JUnit XML. Handles both <testsuites> roots and single <testsuite> roots, CDATA sections in <failure> bodies, standard XML entity escapes.
  2. Tallies counts per suite and aggregates: { passed, failed, skipped, total }.
  3. Extracts per-testcase failures: suite, test name, file, line, message, stack trace.
  4. Leaves failures[].category as null — the B3 classifier in the test-runner agent fills it in next.
  5. Emits the record with a generated-if-absent run_id (UUIDv4) and a generated_at timestamp.
  6. Determines outcome: PASSED if all pass, FAILED if any fail, SKIPPED_UPSTREAM_FAILURE if zero tests ran.

Framework-specific handling

pytest
<testcase> has classname in Python dotted form (mec10.apps.accounts.tests.test_user). File and line come from pytest's JUnit emission.
Playwright
classname is the spec file path. Traces are referenced via --trace flag (path only, not parsed).
Vitest
classname is the describe-block name. Coverage JSON (v8 provider) referenced via --coverage.

Example

node plugins/relay/scripts/normalize-test-output.mjs \
    --framework pytest \
    --junit reports/results.xml \
    --tier e2e \
    --attempt 1

Produces a record like (truncated):

{
  "run_id": "c70ae799-3c2e-4b69-b840-0888362b5e69",
  "attempt": 1,
  "tier": "e2e",
  "framework": "pytest",
  "outcome": "FAILED",
  "duration_ms": 11640,
  "counts": { "passed": 56, "failed": 1, "skipped": 0, "total": 57 },
  "failures": [
    {
      "suite": "mec10.apps.assessment.tests",
      "test": "test_evidence_factory_uses_sandbox_bucket",
      "file": "mec10/apps/assessment/tests/test_factories.py",
      "line": 22,
      "message": "AssertionError: expected sandbox bucket 'phoenix-test-bucket', got 'phoenix-prod-bucket'",
      "stack": "Traceback...",
      "category": null,
      "raw_framework_output_ref": "mec10.apps.assessment.tests.test_factories#test_evidence_factory_uses_sandbox_bucket"
    }
  ],
  "coverage": null,
  "artifacts": { "junit_xml": "/absolute/path/to/results.xml" },
  "generated_at": "2026-04-21T22:25:33.718Z"
}

generate-final-report.mjs shipped

Path
plugins/relay/scripts/generate-final-report.mjs
Purpose
Assemble the AC-10 compliant final-report.md for a Test Runner session from all its persisted artifacts.
Invoked by
/relay-pr command (future) as the last step before opening the PR. Also manually for audit.
Runtime
Node.js ≥ 18.
Dependencies
None.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/generate-final-report.mjs \
    <reports-dir> \
    [--out path/to/output.md]

Without --out, writes to <reports-dir>/final-report.md.

Inputs read from the reports directory

FileRequiredUsed for
run.jsonyesTop-level outcome, budgets, elapsed_ms, time_breakdown, attempt index, TDD mode flag, secrets_redacted summary, skipped components
test-review.jsonnoPost-green review verdict and concerns (rendered when present)
attempts/<N>/record.jsonyes for each NPer-attempt failures table with categorized failures
attempts/<N>/stdout.lognoReferenced in attempt detail (not rendered inline)
attempts/<N>/diff.patchnoReferenced in attempt detail

Missing optional files are handled gracefully — the corresponding section either shows "not run" or is omitted.

Report sections

The generated final-report.md contains, in order:

  1. Header: feature name, outcome badge with emoji, total duration, run ID, TDD track status, budgets.
  2. Summary table: attempts count, total wall-clock, post-green review verdict.
  3. Time breakdown: per-phase durations from run.json.time_breakdown.
  4. Failure classification histogram: counts per category (legitimate / infra / flaky / weak_test / unclassified) across all attempts.
  5. Per-attempt detail: for each attempts/<N>/, a section with outcome badge, duration, counts, tier, framework, log and diff pointers, and a failures table with category / suite / test / file:line / message.
  6. Post-green review: verdict, base branch, analyzed files, concerns list with evidence, notes.
  7. Secrets redaction: count + categories from run.json.secrets_redacted.
  8. Skipped components: name + reason for any graceful-degradation skip.
  9. TDD track: only present when tdd_mode: true — initial suite diff path, B8 review artifacts.
  10. Footer: generation timestamp and source artifacts path.

Output conventions

  • Durations formatted as 500ms, 30s, 4m 32s — readable to humans, not machine-parseable.
  • File paths in the Markdown always use forward slashes (attempts/1/stdout.log), even on Windows.
  • Message text in failures tables is truncated at 120 chars and | characters escaped to keep the table valid.
  • Outcome badges: ✅ for green/passed/approved, ❌ for failed, ⏱ for time-budget, 🔁 for oscillation, ⚠ for infra-unrecoverable, ⏭ for skipped.

auth-kit-secrecy.mjs shipped

Path
plugins/relay/scripts/auth-kit-secrecy.mjs
Purpose
Make it impossible to write a secret before the ignore rules are proven. Copies the packaged auth-kit.gitignore resource into <root>/PRPs/auth/.gitignore and proves with git check-ignore that every secret path is ignored.
Invoked by
/relay-auth-setup and /relay-auth-scripts; the generated per-role login scripts call it too, before any write. Also invocable directly.
Runtime
Node.js ≥ 18.
Dependencies
None. Synchronous Node built-ins only.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-kit-secrecy.mjs scaffold [--root <dir>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-kit-secrecy.mjs prove    [--root <dir>] [--path <relative-path>]...
node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-kit-secrecy.mjs ensure   [--root <dir>] [--path <relative-path>]...

The mode is mandatory. Exit code 0 when proven or done, 1 for FAILED_IGNORE_UNPROVEN, 2 for bad arguments (an unknown argument, a flag missing its value, no mode, an absolute --path, or a --path containing a .. segment), always without writing. ensure is the gate later phases call before any secret write. The only file the script ever writes is that tracked ignore file; it never reads, prints or writes a credential value.

auth-local-guard.mjs shipped

Path
plugins/relay/scripts/auth-local-guard.mjs
Purpose
The local-only guard of the test-auth kit: decides whether a target URL is a local application. The host comes from the WHATWG URL parser's own hostname component and is decided by exact equality against the built-in loopback names, or against hostnames declared in the tracked PRPs/auth/local-hosts.txt (one bare hostname per line, # comments allowed), each of which must resolve with every address loopback.
Invoked by
/relay-auth-setup and /relay-auth-scripts; the generated per-role login scripts call it too. Also invocable directly.
Runtime
Node.js ≥ 18.
Dependencies
None. node: built-ins only.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-local-guard.mjs check --url <url> [--root <dir>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/auth-local-guard.mjs list-declared [--root <dir>]

The mode is mandatory. Exit code 0 when allowed, 1 for FAILED_NON_LOCAL_TARGET, 2 for bad arguments. A target carrying userinfo is refused even when its host is local. There is no per-run flag and no environment-variable source for declared hosts, and the script never writes any file.

qa-run.mjs shipped

Path
plugins/relay/scripts/qa-run.mjs
Purpose
The runner of the test-auth kit's consumer side. Parses a qa-report.md, gives every case exactly one of pass, fail, blocked or needs-human, captures redacted evidence and writes results.json under a fresh PRPs/reports/<feature>/qa-run/<run-id>/ directory. It never edits the report and ends every run by stating that the human validation gate is still open.
Record resolution
Before routing, a case whose coverage is automated is resolved from the Test Runner's schema-v1 record.json (the top-level record, else the latest attempt): the JUnit artifact it points at decides pass or fail per cited test file (a cited describe or test title is decided from only the JUnit testcases it names; evidence records its granularity as file, test or mixed), with reason code AUTOMATED_EVIDENCE and evidence naming the record's run. A record outside schema v1, a run that executed nothing, a JUnit artifact written after the record, an unlisted file or a path matching more than one file all leave the case routed as before. results.json carries a separate record_resolved count; counts stays the four-outcome partition and the summary line excludes record-resolved cases from the driver-executed numbers.
Plan contract
A plan holds literal step objects per driver, validated against the script before anything runs. A {{name}} variable that is not bound is refused before any side effect. Each step result is written into results.json. A plan may carry a human_remainder field: when every driver step of such a case passes, the case is needs-human with reason PARTIAL_REMAINDER, counted in partially_executed and never in the driver-executed rate.
Seeds
A seed declaration runs only when its status is exactly confirmed (otherwise the case is blocked with STATE_UNCONFIRMED); a "command": null entry is blocked with STATE_COMMAND_MISSING, and a runnable declaration must name a store the local-only guard can check. A declaration may capture values from its bounded JSON output into named variables (captures, optionally redact); a value that is missing is CAPTURE_MISSING, never invented.
Database driver
A query step runs over a declared query_sources entry (wrangler-d1 or sqlite3), using the contract in qa-query.mjs. Only a single SELECT or WITH ... SELECT runs, a local invocation is required, and rows are redacted in evidence.
API origins
api_origins in login.config.json lets an HTTP step name a second local origin. Every declared origin passes the local-only guard, the step path must be relative, and a header derived from the session of the role is registered for redaction and never printed.
UI grounding
The ground mode writes a redacted accessibility snapshot of one route for one role. Browser steps may use role-and-name and visible-text locators, valid when the snapshot lists them as one element or the report’s own steps state their name or text, which must match exactly one element when the case runs, otherwise STEP_UNGROUNDED; within, name_prefix, label_text and index scope or reshape a locator and are always resolved when the case runs. The snapshot is written only once two successive accessibility snapshots, 1 second apart, are equal within 20 seconds (otherwise GROUND_UNSTABLE, exit 1, nothing written), its text candidates include paragraph, list-item and cell lines, and with --prefix it is taken after a replay of at most 5 goto, click and fill steps and written to its own --after-<digest> file.
Session proof
A kit login script now proves every saved or reused session in both directions: the probe must succeed with the session and fail without it, and a declared browser probe (an authenticated-only marker, optionally a role marker) is the proof for its role. FAILED_PROBE_NOT_PROTECTED, FAILED_PROBE_WRONG_ACCOUNT, FAILED_PROBE_PAGE_UNLOADABLE, FAILED_PROBE_MARKER_ABSENT and FAILED_KIT_SCRIPT_STALE reach the report as named blocked reasons (the runner's PROBE_BLOCK_CODES); every other session failure keeps SESSION_UNAVAILABLE. For a role whose mechanism is minted, the runner passes the login script --force when the expiry recorded in PRPs/auth/.sessions/<role>.mint.json is within 240 seconds of the run start, so a new session is minted and proved before the first case; it registers session values for redaction source-first (see Redaction floor and run evidence below); and the login halts FAILED_MINT_UNCONFIRMED, FAILED_MINT_COMMAND_MISSING, FAILED_NON_LOCAL_TARGET, FAILED_MINT_COMMAND and FAILED_MINT_OUTPUT are named blocked reasons. Before spawning a role's login script the runner runs a read-only stale pre-flight: it compares the script's template identity stamp with the installed template's and judges only template-generated scripts (a missing stamp counts as stale), failing open when the installed template is unreadable or unstamped. For a browser case whose role records authenticatesAnonymous, the runner blocks with FAILED_TARGET_PRE_AUTHENTICATED unless the record names an alternative local target; that target is passed through the local-only guard and confirmed by a 20 second anonymous check (a fresh context with no session must not show the authenticated-only marker), cached per role. HTTP cases are never gated.
Classification
The plan carries a class per case (CASE_CLASSES: automatable, needs-a-new-driver, human-by-nature, blocked-by-product) and a declining entry a reason_code from the closed REASON_CATALOGUE; PARTIAL_REMAINDER, JUDGEMENT_UNCERTAIN and ROLE_NOT_DEDICATED are runner-owned (RUNNER_OWNED_REASON_CODES) and a plan may not declare them. A code or class outside the closed sets makes the entry PLAN_ENTRY_INVALID. Every reason code also carries a class: impossible for EXTERNAL_CHANNEL, OUTSIDE_LOCAL_ENVIRONMENT and HUMAN_SIGNOFF, gap for every other code, and results.json reports needs_human_impossible and needs_human_gap step counts beside the unchanged four-key counts. results.json gains a classification block and a class and an objective_steps on each case; the four-key counts partition and the outcome vocabulary are unchanged.
Stable grounding
ground reads the accessibility snapshot every GROUND_POLL_INTERVAL_MS (1000) and writes only once two successive reads are equal within GROUND_STABLE_BOUND_MS (20000), else it halts GROUND_UNSTABLE (exit 1, no file). With --prefix it replays at most GROUND_PREFIX_MAX_STEPS (5) flat goto, click and fill steps, a fill value of at most GROUND_PREFIX_VALUE_MAX (200) characters, through the guard and with the role session; a malformed prefix exits 2 (GROUND_PREFIX_INVALID) and a step that cannot be performed on exactly one element halts GROUND_PREFIX_FAILED, both with nothing written. The snapshot taken after a replay is the schema_version 2 file <role>--<route>--after-<8 hex>.snapshot.json and its prefix records each typed value only as a SHA-256 digest, but its entries are page text read after the interaction and can echo a typed value the page renders back: an entry is withheld only for a registered secret, an e-mail address or a regex: match, and a typed value is not registered.
Redaction floor and run evidence
Session values are registered by source: the token artifact, the declared session cookie and every api_origins cookie always, any other cookie, localStorage or IndexedDB string only at SESSION_VALUE_MIN_LENGTH (12) characters and SESSION_VALUE_MIN_ENTROPY (3.0) bits per character, and never a part of the target origin. init writes the run directory’s .gitignore (RUN_IGNORE_RULES: grounding/ and evidence/) through the single write helper and proves it with git check-ignore -q, printing IGNORE_PROOF: proven or IGNORE_PROOF: not-applicable; an unproven rule inside a work tree halts FAILED_IGNORE_UNPROVEN on init, ground and run.
Assertions and request count
Beyond the existing browser steps the validator accepts expect_value, expect_not_visible, expect_state (EXPECT_STATES) and expect_requests, and an http request step may carry "session": "none". A value, a state and an absence are re-read for up to ASSERT_SETTLE_MS (5000) every ASSERT_POLL_INTERVAL_MS (100); an absence is valid only after a positive step (POSITIVE_ASSERTION_ACTIONS) on the same route since the last goto. Visibility is decided by isVisibleToPerson: Playwright’s visibility check and the browser’s checkVisibility, read with its opacity and visibility options, must both hold, so an element at opacity: 0 or visibility: hidden is not visible, and requireVisibleToPerson re-reads it for up to ASSERT_SETTLE_MS for a positive step. The final capture of a browser case is captureFinalPng: a full-page screenshot with the password and expect_value masks, bounded by CAPTURE_TIMEOUT_MS (30000) and retried once as a viewport-only capture if the full-page capture fails; captureElementPng captures one located element with the same masks and bound, and the judge step uses it for a scoped capture. Locator steps are grounded by groundLocators (a snapshot entry that matches exactly one element, or a name or text the report’s own steps state) and built by buildLocator, which resolves the scoped forms within, name_prefix, label_text and index when the case runs; resolveScopeElement resolves a within scope to its one element, the entry a later element capture uses. Chosen inputs are checked by validateChosenInputs and chosenSnapshotRefusal, chosenFillValues lets a later expectation name a chosen value, and a marked write step is found by firstWriteStep and allowed by isDedicatedRole, which accepts a role only when its login.config.json entry has dedicated set to true. A judge step is checked against the report by validateJudgeCriteria, a verdict is parsed by parseJudgeArgs and applied by applyJudgeVerdict, which settles the case through settleJudgedCase and recomputes the counts, and summarizeJudgment reports the pending and the judged steps. A message step is checked by classifyChannelSource against the declared source, and its value is found by extractMessageValue in the message that newestMailAfter or smsEntryAfter chose. expect_requests waits EXPECT_REQUESTS_SETTLE_MS (2000), takes a method or an array of methods, accepts a count of at most EXPECT_REQUESTS_COUNT_MAX (100) and lists at most EXPECT_REQUESTS_EVIDENCE_MAX (50) requests, method, host and path only, in evidence/case-<index>.requests-<step>.json. A listed path can still carry an identifier the redaction table does not recognize, an e-mail address included: the rule that withholds an e-mail address applies to snapshot entries only, and the file sits in the ignored evidence/ directory.
Re-mint
A minted role whose kit login script halts FAILED_PROBE_MARKER_ABSENT is run once more with --force (LOGIN_REMINT_MAX_RETRIES (1); shouldRemintLogin decides it), never the mint command, and a second halt keeps its own code. The kit login template and its KIT_TEMPLATE_ID are unchanged.
Environment preflight
The preflight mode takes the package and its resolved path from describePlaywright, asks the installed package where the Chromium build should be and checks that the file exists, reads every kit login script with the same stale pre-flight that run uses, and probes the ignore rule of PRPs/auth/.sessions/ with git check-ignore; it starts no browser, makes no network request and writes nothing. playwrightUnavailableText builds the halt text of every mode from the plugin directory, and recordStaleSources reads the relative static imports of a record-resolved case’s cited test files and asks git whether each changed after the record’s generated_at.
Chosen numbers
The stability interval and bound, the redaction floor, the prefix caps, the re-read and settle windows, the largest count, the listing of 50 requests, the 200-character cut of a listed path and the re-mint cap are chosen, not measured. The dogfood that follows this release recalibrates them.
Invoked by
/relay-qa-run. Also invocable directly.
Runtime
Node.js ≥ 18.
Dependencies
None of its own: node: built-ins only. playwright is resolved lazily at run time, from the project root and then from plugins/relay/scripts/visual/ (the scripts/visual/ directory of the plugin cache for an installed plugin). When it is absent, run blocks the HTTP and browser cases with the path-free reason FAILED_PLAYWRIGHT_UNAVAILABLE, prints the resolved plugin directory and the one command that provisions it on stderr, and exits 1; ground and preflight halt with the same code. The runner never installs anything itself.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs parse --report <path>
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs init --root <dir> --feature <slug> [--env-handle <path>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs ground --root <dir> --feature <slug> --run-dir <rel-dir> --route <path> [--role <role>] [--env-handle <path>] [--prefix <json>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs run --root <dir> --feature <slug> --run-dir <rel-dir> [--env-handle <path>] [--max-cases <n>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs judge --run-dir <rel-dir> --case <n> --step <k> --verdict <pass|fail|uncertain> --evidence "<what the capture shows>" [--root <dir>]
node ${CLAUDE_PLUGIN_ROOT}/scripts/qa-run.mjs preflight --root <dir>

The mode is mandatory. Exit code 0 when completed, 1 for a named FAILED_* halt or an aborted run, 2 for bad arguments (a malformed --prefix is GROUND_PREFIX_INVALID, exit 2, with nothing written). The local-only guard runs before any request, login or write; one marked write helper is the only writer and refuses any path outside the run directory; evidence is redacted in memory before it is written.

qa-query.mjs shipped

Path
plugins/relay/scripts/qa-query.mjs
Purpose
The pure contract of the runner's read-only database driver. It performs no I/O and spawns nothing; every spawn lives in qa-run.mjs. The qa-run-contract check enforces this.
Statement guard
Exactly one SELECT or WITH ... SELECT. Any comment, second statement, PRAGMA, ATTACH, VACUUM or write is QUERY_NOT_READ_ONLY.
Source kinds
A closed table. wrangler-d1 needs --local and refuses --remote and --preview; sqlite3 needs -readonly. A violation is FAILED_NON_LOCAL_TARGET or QUERY_SOURCE_INVALID.
Also provides
Argv assembly, output parsing, row assertions (expect_rows, expect_json) and row redaction. Refusal reasons never carry a statement fragment, a row value or a source command.
Invoked by
/relay-qa-run, imported lazily by qa-run.mjs. It has no command line.
Runtime
Node.js ≥ 18. No dependencies.

executable-content-hash.mjs shipped

Path
plugins/relay/scripts/executable-content-hash.mjs
Purpose
Computes an auditable hash of a source file's executable content at two git revisions, so the code reviewer's R-X test-modification guard can tell a diff that changes what a test asserts from one that changes only what it says. Comments, Python docstrings and test-title string literals are removed before hashing; everything else is kept byte for byte.
Fail-closed
A path is reported cleared: false whenever anything is uncertain: an unsupported extension, a file absent on either side, an unterminated string or comment, or an ambiguous JavaScript /. A caller treats every non-cleared path as a plain R-X match.
Invoked by
The code-reviewer agent, in standard mode.
Runtime
Node.js ≥ 18. No dependencies.

Usage

node ${CLAUDE_PLUGIN_ROOT}/scripts/executable-content-hash.mjs --base <rev> --head <rev|WORKTREE> [--repo <dir>] [--pretty] -- <path> [<path> ...]

One JSON report on stdout. Exit 0 whenever a report was produced, including when every path was flagged: the verdict lives in the report. Exit 2 on a usage or internal error.

How new scripts join the plugin

If a future stage needs a new helper script (e.g., a coverage-differ, a mutation-tester wrapper), it should follow the same pattern:

  1. Node.js .mjs file in plugins/relay/scripts/.
  2. Zero npm dependencies — Node built-ins only.
  3. CLI-style argv parsing with --flag value.
  4. Structured JSON or Markdown on stdout.
  5. Exit code 0 on success, 2 on invalid input, 1 on unexpected error.
  6. Narrow allow pattern added to plugins/relay/resources/settings-allowlist.md so the script is in the default .claude/settings.json the context-builder generates.
