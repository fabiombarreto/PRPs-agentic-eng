Commands

The full slash-command surface of the relay plugin. Nineteen commands, organized by role (writer / reviewer / infra / orchestrator / QA / Pillar 3). Each command is invocable on its own for testing or manual intervention; the orchestrator (/relay-execute) composes the Pillar 2 stages into a full run.

The happy path

Day-to-day feature delivery uses five commands:

/relay-prd     "a short description of the feature"   # interactive — produces approved PRD
/relay-execute PRPs/prds/<feature>.prd.md              # autonomous — drives PRD through plan/implement/test
# ...review the output, run manual tests, then:
/relay-commit  [<feature> | target description]         # local git commit (no push; worktree or current-branch mode)
/relay-pr      <feature>                                # push branch + open PR
# ...PR review + approval, then:
/relay-approve <pr-number>                              # merge + worktree cleanup + docs update

Everything else exists for granular invocation — running a single stage for debugging, re-running a reviewer on a hand-edited artifact, or composing a custom flow.

Writers

Produce an artifact. Each writer has a corresponding reviewer (below) except /relay-prd, which merges writer and reviewer into one interactive flow.

/relay-prd — interactive PRD authoring implemented

Input
A short description of the feature, a path to a draft PRD markdown to refine (skips Q&A questions already answered in the draft), or no argument (opens with "What do you want to build?").
Output
PRPs/prds/<feature>.prd.md with status APPROVED. Filename is chosen by the writer in kebab-case from the Phase 1 content; collisions are resolved with a numeric suffix; APPROVED files are never overwritten. A review log is appended at PRPs/prds/<basename>.review.jsonl.
Mode
Interactive. Runs the 6-phase Q&A (Initiate → Foundation → Grounding → Deep dive → optional re-grounding → Decisions → Generate). Research is performed via the research-web and research-codebase subagents during the GROUNDING phase.
Refuses
Operating on a file whose current status is APPROVED. The user is instructed to manually flip the file back to DRAFT (or copy/rename) to start a new authoring session against it.
Agents
Delegates the 6-phase flow to prd-writer; delegates rubric validation and the DRAFT→APPROVED flip to prd-reviewer.
Notes
The only command on the interactive side of the interactivity boundary. Always runs the PRD Reviewer at the end; the PRD is not persisted as APPROVED until the reviewer's 7-item rubric passes and the user explicitly approves in dialogue.

/relay-plan <prd-path | description> implemented

Input
PRD mode: A PRD file with status APPROVED (ending with *Status: APPROVED*) containing a parseable Implementation Phases table with at least one row whose Status is pending and whose Depends cell is empty or references only complete rows. Description mode (new, v0.13.0): Any non-empty free-text argument that does not resolve to a .prd.md file and does not contain an “Implementation Phases” table — plan written to PRPs/plans/<slug>.plan.md (flat filename, no PRD back-fill).
Output
PRD mode: PRPs/plans/<feature>-phase-<N>-<slug>.plan.md with status *Status: DRAFT* (one plan per actionable Implementation Phases row; codified in docs/decisions.md 2026-04-25). Plan-writer back-fills the source PRD's row N (Status flipped from pending to in-progress; PRP Plan cell populated with the relative plan path). Description mode: PRPs/plans/<slug>.plan.md with status *Status: DRAFT* (flat filename; no PRD row back-filled; description captured verbatim in the plan's ## Source section; derived AC-A<i> items used throughout).
Mode
Autonomous, single-role. /relay-plan never adopts the reviewer; /relay-plan-review is the separate reviewer surface (per the writer/reviewer split decision).
Agents
Delegates plan generation to plan-writer, which dispatches research-codebase + research-web in parallel during GROUNDING, consults the three Decision Gate sources, writes the DRAFT with all 15 mandatory sections, and performs the source PRD back-fill via a verbatim-row Edit.
Notes
Four preconditions (PRD readable, PRD APPROVED, Decision Gate sources readable, at least one actionable phase exists with satisfied dependencies); writer halts surface verbatim through the command. Collisions on the per-phase filename resolved with numeric suffix; APPROVED plans never overwritten. See PRPs/prds/plan-authoring.prd.md.
Shipped: PRD-less mode (v0.13.0)

/relay-plan now supports a description-only (PRD-less) input mode in addition to the standard APPROVED-PRD mode. Input-type detection (Phase 0): if the argument resolves to a .prd.md file or its content contains an “Implementation Phases” table, the command runs the existing PRD mode unchanged. Any other non-empty free-text argument enters description mode. Output: a flat PRPs/plans/<slug>.plan.md (no phase number, no PRD back-fill). Decision Gate preserved: the three Decision Gate sources are consulted in both modes. Full chain supported: the generated plan is consumable by /relay-implement end-to-end (P3 PRD-row check branched; D8 Mutation c no-op for absent PRD row; code-reviewer/code-reviewer-semantic use plan-derived ACs). Note: tdd: true targets are deferred to a future branch; description mode supports tdd: false projects only. Supersedes the 2026-05-15 decision entry. See docs/decisions.md [2026-06-16].

/relay-write-test <plan-path> implemented

Input
A plan ending with *Status: APPROVED* whose source PRD's Implementation Phases row N has Status: in-progress.
Output
PRPs/reports/<feature>/test-suite.diff manifest with aggregate verdict SUITE_DRAFT_WRITTEN or EXISTING_COVERAGE_SUFFICIENT (the latter when every in-scope AC is already covered by existing tests). Test files (when verdict is SUITE_DRAFT_WRITTEN) committed to the framework-native test root in the target project. Suite manifest carries *Status: DRAFT* for /relay-test-write-review to flip.
Mode
Autonomous. Activation gate is a declared test framework (non-empty test_frameworks in docs/context/methodology.md) — active in BOTH methodology modes; test_frameworks: [] or a missing file → silent self-skip exiting 0. The tdd: value selects ordering only: tdd: true = test-first (runs before the Implementer); tdd: false = test-after (runs after the Implementer + Code Review). Adopts test-writer protocol inline.
Notes
Reads the source PRD's Acceptance Criteria section to derive tests. Walks each AC and emits one of five per-AC outcomes (NEW_TEST_REQUIRED writes a framework-idiomatic test, EXISTING_TEST_COVERS path:line records the mapping without writing a duplicate, EXISTING_TEST_UPDATED/OBSOLETE_TEST_REMOVED/REDUNDANT_TEST_REMOVED record lifecycle ops in the manifest ledger, AMBIGUOUS aborts the suite asking the user to tighten the PRD). Prompt parametrized by methodology.md test_frameworks[] — supports pytest, vitest, jest, ExUnit, RSpec, playwright. Never writes production code (R-X strict's symmetric inverse). See PRPs/prds/test-pair-universalization.prd.md (formerly PRPs/prds/tdd-writer-reviewer.prd.md).

/relay-implement <plan-path> implemented

Input
A plan ending with *Status: APPROVED* whose source PRD's Implementation Phases row N has Status: in-progress. The plan's Step-by-Step Tasks, Validation Commands Levels 1–3, Files to Change, and Acceptance Criteria are the rubric's structural inputs.
Output
Working tree carries the implementation diff against the base commit. On APPROVED rubric: plan trailing block flipped to *Status: IMPLEMENTED*, plan moved to PRPs/plans/completed/<basename>.plan.md, source PRD row N flipped from in-progress to complete. On HALT: structured halt.json with attempt history at PRPs/reports/<feature>/phase-<N>/halt.json. Immediately after code-review APPROVED and before the D8 mutations, a Phase A.3.5 — Docs-sync dispatch sub-phase runs the docs-updater/docs-reviewer pair non-interactively against the current attempt's diff.patch, syncing docs/ in the worktree (own max_docs_review_retries=2 budget; gated by docs_sync in docs/context/methodology.md and a per-invocation --no-docs flag; deferred operator questions surface via the Docs: line in the Final output surface).
Mode
Autonomous.
Notes
Internal writer↔reviewer loop dispatching the implementer agent (writes code via Edit/Write directly in the working tree) and the code-reviewer agent (three-layer rubric: structural / static / semantic + R-X universal test-modification guard) once per attempt. Bounded by max_implement_retries=3 (4 attempts total), max_implement_minutes=45 (wall-clock; first-to-expire-wins), max_disputes_per_session=2 (TEST_CONTRACT_DISPUTE escape valve cap; arbitration mode resolves with DISPUTE_REJECTED/DISPUTE_UPHELD_TEST_WRONG/DISPUTE_UPHELD_PRD_AMBIGUOUS). Oscillation detection always-on. Per-attempt cumulative diff.patch at PRPs/reports/<feature>/phase-<N>/attempts/<i>/. D8 post-approval mutations are best-effort atomic with rollback note on partial failure. Name chosen to match prp-implement from the upstream prp-core plugin. See PRPs/prds/implementation-authoring.prd.md.

Reviewers

Validate an existing artifact. Reviewers accept hand-edited artifacts — if you edit a plan manually and want to re-validate, /relay-plan-review is the right tool. Reviewers never modify the artifact; they emit APPROVED or CHANGES_REQUESTED with an actionable list.

/relay-plan-review <plan-path> implemented

Input
A plan ending with *Status: DRAFT* (from /relay-plan or hand-edited).
Output
On rubric pass: plan trailing block flipped to *Status: APPROVED* via two-line Edit with an inserted *Approved: <YYYY-MM-DD>* line. On any failure: CHANGES_REQUESTED with the failing rubric items by ID + reason. Every verdict appended to PRPs/plans/<basename>.review.jsonl with all 8 R1–R8 outcomes plus zero or more R-COH-* outcomes (no short-circuit).
Mode
Autonomous, single-shot. CHANGES_REQUESTED is terminal for the run; the orchestrator (/relay-execute) decides regeneration via /relay-plan per max_plan_review_retries=2.
Agents
Delegates rubric validation and the DRAFT→APPROVED flip to plan-reviewer, which runs the 8-item structural rubric (R1 Decision Gate, R2 mandatory sections, R3 no TBD, R4 ≥3 atomic tasks with VALIDATE, R5 TDD routing, R6 no .claude/ writes, R7 Files-to-Change row, R8 PRD↔plan traceability with R8a/R8b/R8c) plus the additive R-COH-* coherence layer (5 deterministic intra-plan checks + a bounded K=5 LLM judgment pass).
Notes
Three preconditions (plan readable, plan ends with *Status: DRAFT*, Decision Gate sources readable). Diverges from /relay-prd's reviewer in three ways: auto-flips without user dialogue (interactivity boundary), evaluates all 8 items every run (no short-circuit), no Step 5 dialogue loop (CHANGES_REQUESTED is terminal). Phase 0 pre-pass (v0.12.0): before rubric evaluation, the reviewer infers and writes the phase_type field (scaffold / docs / refactor / feature) in the plan's ## Metadata table when absent — the only bounded exception to the reviewer's no-inline-edit rule. This drives the R-COH-VALIDATE-FRAMEWORK-MISMATCH phase-type exemption. See PRPs/prds/plan-authoring.prd.md.

/relay-test-write-review <suite-path> implemented

Input
A test suite manifest at PRPs/reports/<feature>/test-suite.diff ending with *Status: DRAFT*.
Output
APPROVED or CHANGES_REQUESTED appended to PRPs/plans/<basename>.test-write-review.jsonl (append-only Read+concat+Write). On APPROVED, the suite manifest is flipped *Status: DRAFT* → *Status: APPROVED* via the command's own Edit. Symmetric self-skip with /relay-write-test on test_frameworks: [] / missing methodology.md.
Mode
Autonomous, single-shot. Mirrors the /relay-code-review shape: Task-dispatches test-reviewer; reads the just-appended JSONL line; flips suite status on APPROVED. Explicit no-D8-mutation no-op step preserved (the reviewer command does not modify the source PRD's Implementation Phases table or move plans to completed/).
Notes
Rubric ids evaluated per run with no short-circuit, including R-IMPL-LEAK (asserts on private symbols, call-count assertions, test names matching internal method names), R-TRIVIAL-ASSERT (tautologies, existence-only, strict-subset of AC properties), R-MOCK-ABUSE (mock-of-SUT, mock of concrete type when interface exists, chained mocks ≥3 deep, was_called-only assertions), R-AC-COVERAGE (every in-scope AC has ≥1 test reference), R-DUPLICATE (two tests asserting the same property without discriminative input variance), R-LIFECYCLE-LEGITIMATE (update/delete ops match an APPROVED ledger entry), and the mode-selected hybrid R-RED-LEGITIMATE (test-first) / R-GREEN-LEGITIMATE (test-after) — dynamic Bash execution distinguishing legitimate from illegitimate suite state; passed: null graceful degradation when framework unavailable per AC-13. The orchestrator (/relay-execute) decides retry vs HALT per max_tdd_review_retries=2. See PRPs/prds/test-pair-universalization.prd.md (formerly PRPs/prds/tdd-writer-reviewer.prd.md).

/relay-code-review <plan-path> implemented

Input
A plan path resolving to PRPs/plans/<basename>.plan.md (status *Status: APPROVED*, mid-implementation review) or PRPs/plans/completed/<basename>.plan.md (status *Status: IMPLEMENTED*, post-implementation re-review after a hand-edit). A working-tree diff against the base branch is required (P3 precondition).
Output
APPROVED or CHANGES_REQUESTED appended to PRPs/plans/<basename>.code-review.jsonl. The plan trailing block is byte-identical before and after the command runs, regardless of verdict.
Mode
Autonomous, single-shot.
Notes
Standalone single-shot dispatch of the code-reviewer agent in mode: 'standard'; no internal loop, no retries, no per-attempt diff.patch artifact, no D8 mutations. Critical architectural divergence from /relay-plan-review: this command surfaces the verdict and exits without auto-flipping plan status — D8 mutations (plan trailing-block flip, plan move to completed/, source PRD row N flip) are exclusively /relay-implement's responsibility per source PRD AC-12 + D5 + D8. Read-only counterpart to /relay-implement's mutation-triggering autonomous loop, for hand-invoked review where no automated state transition is desired. Closest external precedent is Cloudflare's AI code review architecture (sub-reviewers emit findings; coordinator alone mutates state) and GitHub's Comment PR review type (verdict without approval signal). See PRPs/prds/implementation-authoring.prd.md.

/relay-test-review <worktree> implemented

Input
A worktree with a green test state (requires run.json with outcome: GREEN).
Output
PRPs/reports/<feature>/test-review.json with verdict (APPROVED or CHANGES_REQUESTED) and concerns list.
Detects
Removed test functions, newly-added skip markers, trivial assertion downgrades, coverage drops > 5% when baseline is available.
Flags
--base <branch> — base branch to diff against (default main or master).

Infra & execution

/relay-worktree <feature-name> implemented

Input
Feature name (free argument); or PRD-derived slug when invoked internally by /relay-execute. Sanitized to [a-z0-9-] max 64 chars; characters outside the set are dropped; leading/trailing hyphens stripped. Empty result after sanitization → HALT with actionable message.
Output
Worktree at .worktrees/<feature>/ and branch feature/<feature>. Bootstrap log at PRPs/reports/<feature>/worktree-bootstrap.log when scripts/worktree-bootstrap.sh runs.
Mode
Deterministic infra command (no LLM, no agent). Idempotent: silently reuses an existing worktree when the branch matches; halts loud (FAILED_BRANCH_DIVERGENCE) when the worktree exists on a different branch, naming both the expected and actual branch and instructing the user to resolve manually or choose a different feature name.
Preconditions
cwd is a git repo (FAILED_NOT_A_GIT_REPO); base ref resolvable (FAILED_BASE_REF_MISSING); branch feature/<feature> available or already on expected worktree (FAILED_BRANCH_CONFLICT); path .worktrees/<feature>/ either empty or a registered git worktree (FAILED_PATH_OCCUPIED). Idempotency detection via git worktree list --porcelain (locale-independent; authoritative git state).
Bootstrap
Invokes scripts/worktree-bootstrap.sh <abs-worktree-path> (or .ps1 on Windows) with a 60-second timeout when the script exists. Stdout/stderr captured to PRPs/reports/<feature>/worktree-bootstrap.log with secret redaction. Failure is non-fatal — worktree creation is the load-bearing outcome; a warning is logged naming the log path. Script absent: silent, no log written.
Flags
--base <ref> — base ref for the new branch (default: origin/main → origin/master → HEAD fallback chain).
Notes
Invoked automatically by /relay-execute between /relay-plan-review and /relay-write-test. --no-worktree flag on /relay-execute skips invocation and preserves the current cwd-based behavior. Creation failure inside /relay-execute falls through to graceful degradation per D3/D4 — pipeline does NOT halt on worktree creation failure; fallback recorded in orchestrator-run.json with worktree_attempted: true, worktree_succeeded: false, fallback_reason: <code>. See PRPs/prds/relay-worktree.prd.md.

/relay-test <worktree> implemented

Input
A worktree with pending code changes.
Output
Green state, or one of: FAILED_AFTER_N_RETRIES, FAILED_TIME_BUDGET_EXCEEDED, FAILED_OSCILLATION, FAILED_INFRA_UNRECOVERABLE, or skipped_no_test_framework (graceful self-skip when test_frameworks: [] or methodology.md absent — no run.json written; symmetric with /relay-write-test P4.a silent self-skip exiting 0).
Produces PRPs/reports/<feature>/run.json plus per-attempt record.json and stdout.log (not written on self-skip).
Encapsulates
B1 (Test Runner agent), B2 (structured output), B3 (failure classification), B4 (auto-correction loop with retry and oscillation detection).
Flags
--max-retries N override retry budget (default 3).
--max-minutes M override time budget (default 30).
--tier unit|integration|e2e force a layer.
--feature <name> override feature slug (defaults to current branch).
Agent
Delegates per-attempt execution to the test-runner agent.

Orchestrator

/relay-execute <prd-path> implemented

Input
An approved PRD.
Output
All phases complete — working tree in .worktrees/<feature>/ carries uncommitted implementation changes, ready for /relay-pr. Does not commit or create a PR (Pillar 3 owns that boundary; see docs/decisions.md 2026-05-18). Or a HALT code with diagnostic. Audit artifact at PRPs/reports/<feature>/orchestrator-run.json.
Composes
/relay-plan → /relay-plan-review → /relay-worktree → /relay-write-test → /relay-test-write-review → /relay-implement → /relay-code-review → /relay-test → /relay-test-review.
Loop behavior
Each writer/reviewer pair loops on CHANGES_REQUESTED until approved or the stage's retry budget is exhausted. Any unrecoverable abort is surfaced with the underlying command's exit reason.
Notes
Dispatch model (D7): inline Read-based command-protocol adoption — the LLM reads each downstream command file and executes its protocol in the same conversation context. No sub-agents spawned at the orchestration layer; zero logic duplication.

State machine (D6): the source PRD's Implementation Phases table is the canonical state machine. Row Status cells (pending / in-progress / complete) are the authoritative phase-state. Re-invocation after a halt is idempotent — the table is re-read on every invocation; complete rows are skipped automatically.

Orchestration budgets (D3): two session-level budgets: max_plan_review_retries (caps the plan→plan-review loop on repeated CHANGES_REQUESTED) and max_orchestrator_minutes (wall-clock; first-to-expire wins). Each downstream command retains its own internal loop budget unchanged.

HALT outcome codes (9): FAILED_PLAN_REVIEW_BUDGET_EXCEEDED, FAILED_PLAN_REVIEW_STUCK (v0.12.0 — identical rubric items fail across consecutive plan-review attempts; early halt before budget exhaustion), FAILED_ORCHESTRATOR_TIME_BUDGET_EXCEEDED, FAILED_TEST_REVIEW_REJECTED, plus four propagated from /relay-implement (FAILED_AFTER_N_RETRIES, FAILED_TIME_BUDGET_EXCEEDED, FAILED_OSCILLATION_DETECTED, FAILED_DISPUTE_CAP_EXCEEDED) and one from /relay-test (FAILED_INFRA_UNRECOVERABLE). Stuck-loop detection (v0.12.0): at Phase A.3.2 the orchestrator compares the current failing rubric item IDs against the previous attempt's IDs (last_plan_review_failing_ids); if identical → HALT FAILED_PLAN_REVIEW_STUCK immediately, before consuming the remaining plan-review budget. The halt artifact at PRPs/reports/<feature>/orchestrator-halt.json carries stuck_rubric_items and manual_recovery_paths. See Handling failures: FAILED_PLAN_REVIEW_STUCK.

Test stage self-skip (v0.11.1): when test_frameworks: [] or methodology.md absent, Phase A.5.0 logs skipped_no_test_framework to orchestrator_run_log and proceeds to Phase A.6 without halting — not a HALT code but a structured outcome entry (symmetric with A.3.5’s skipped_tdd_false).

TDD routing: shipped v0.10.0. The TDD pair (B7 + B8) is engaged in Phase A.3.5 of /relay-execute when docs/context/methodology.md declares tdd: true; the orchestrator-level loop is bounded by max_tdd_review_retries=2 with HALT outcome FAILED_TDD_REVIEW_BUDGET_EXCEEDED. R-X strict (D17 of implementation-authoring.prd.md) is preserved — the implementer never edits test files; B7 is the authorized author of new test files. When tdd: false or methodology.md is missing, A.3.5 self-skips silently as a live no-op.

Name deliberately distinct from /relay-implement (which is the code-writing stage) to avoid collision.

QA / Support

A human-facing command invoked in the validation gate between /relay-execute (Pillar 2) and Pillar 3. It reports test coverage to support manual testing; it is not part of the autonomous loop and is never called by /relay-execute.

/relay-qa-report [prd-path | plan-path | description] implemented

Input
Phase 0 four-way routing by argument shape: a .prd.md path (cases from the PRD Acceptance Criteria), a .plan.md path (cases from the plan’s tasks / validation), non-empty free text (description mode; <feature> from the current branch slug), or blank (diff mode over git status --porcelain + git diff).
Output
A human-facing QA support report at PRPs/reports/<feature>/qa-report.md enumerating test cases, each with seven fields: title, risk level (Critical / High / Medium / Low), required state (DB entities + values), coverage (automated / manual / none), automated test path, manual status (defaults to pending), and a manual step-by-step. A single test may cover multiple cases (n:1); less-critical cases may be left uncovered.
Mode
Single LLM-judgment command — no writer/reviewer pair (the human doing manual QA is the validator). Honest by contract: any case covered by neither an automated nor a manual test is listed explicitly as uncovered, never omitted; cited automated-test paths must resolve to real files, and unconfirmed coverage is marked unverified rather than invented. When PRPs/reports/<feature>/record.json from a prior Test Runner run exists it grounds the automated-coverage column; otherwise coverage is inferred from repo test files. Full reference: /relay-qa-report. See plugins/relay/commands/relay-qa-report.md.
Preconditions
Diff mode on a clean working tree HALTs with FAILED_NOTHING_TO_REPORT and writes no file; an existing PRPs/reports/<feature>/qa-report.md triggers the anti-overwrite guard (confirm-then-continue, or leave it in place) so recorded manual statuses are never silently clobbered.

Design system (Figma track)

A standalone, human-triggered setup command for the Figma Implementation Track. It is invoked once per project (or re-run with --refresh) to build the reusable Figma-to-code component map that later Figma-track phases (Design Spec, Plan Integration) consume. It is never invoked by /relay-execute and never runs as part of the autonomous Pillar 2 loop.

/relay-design-map [--refresh] implemented

Input
No required argument. Optional --refresh flag selects an additive re-scan instead of the one-time setup path. Reads docs/context/design-system.md frontmatter (package name, local design-system clone path, token module path, Figma library file keys, dev_server block).
Output
docs/design/component-map.md with status *Status: APPROVED* — a versioned, human-curatable table mapping Figma library components to real code components, plus a ## Conventions section and an ## UNMAPPED section. Evidence bundles persisted at PRPs/reports/design-map/evidence/. Review log at docs/design/component-map-review.jsonl. On explicit human confirmation only, a single Edit flips figma_track: true in the target project's docs/context/methodology.md.
Mode
Interactive setup command with an internal autonomous stretch. All Figma MCP querying (search_design_system, node-scoped get_metadata, opportunistic get_code_connect_map; budget max_library_search_calls=40) happens in this command's own session — never inside a dispatched agent, per the Phase 2 MCP-access-point decision (docs/decisions.md 2026-07-22). The design-map-writer/design-map-reviewer pair is dispatched in a bounded max_map_review_retries=2 loop over the persisted evidence, mirroring /relay-implement's Phase A.3.5 retry-loop shape. The final figma_track flip requires an explicit, quoted human confirmation — the one sanctioned non-heuristic path to set that key, per docs/anti-patterns.md.
Preconditions
FAILED_FIGMA_MCP_UNAVAILABLE (no Figma MCP tools discoverable via ToolSearch in this session — never silently degrades to a Figma-free run); FAILED_DESIGN_SYSTEM_CONFIG_INCOMPLETE (no docs/context/design-system.md, or required keys still unfilled — the command scaffolds a starter file with [INFERRED - VALIDATE] placeholders, then HALTs naming which keys need a human value before re-running); FAILED_MAP_REVIEW_BUDGET_EXCEEDED (the writer/reviewer loop exhausted its retry budget — HALTs loudly naming the failing R-DM<i> items rather than silently accepting a failing map).
Preflight
Once the map is APPROVED, a best-effort preflight report checks: node present; scripts/visual/ dependency install (this directory ships as of Phase 6 and is expected present; a documented, non-blocking note covers the rare case of an incomplete checkout missing it); the configured dev script exists; the configured port is free. Preflight failures are surfaced as notes in the confirmation summary, never a HALT.
Notes
Agents: design-map-writer (writer, MCP-free, pure evidence-interpreter) and design-map-reviewer (reviewer, MCP-free, six-item R-DM1–R-DM6 rubric, owns the map's DRAFT→APPROVED flip). Canonical map shape defined in plugins/relay/resources/component-map-template.md. See PRPs/prds/figma-implementation-track.prd.md Implementation Phases row 3.

/relay-design-spec <figma-url> [feature-or-description] implemented

Input
A Figma design URL (first token; HALTs FAILED_INVALID_FIGMA_URL if it does not parse as a figma.com/design/... URL) followed by optional free text naming the feature. When the remaining text is empty, feature is derived from the Figma URL's file-name segment instead. Reads docs/design/component-map.md when present (absence is a documented degraded mode, not a HALT).
Output
PRPs/designs/<feature>/design-spec.md with status *Status: APPROVED* only after the user's own explicit affirmative reply — a business-grounded intermediate contract with a ## Frame Inventory, a ## Component Mapping (REUSE/NEW/ASSUMPTION rows citing CM-<n> ids), an embedded ## Token Map, an ## Implementation Delta, and per-frame ## Visual Acceptance Criteria. Evidence persisted at PRPs/designs/<feature>/raw/; reference screenshots at PRPs/designs/<feature>/refs/. Review log at PRPs/designs/<feature>/design-spec-review.jsonl.
Mode
Interactive, inline-adopted writer/reviewer pair — mirrors /relay-prd's bundling, never Task-dispatched (contrast /relay-design-map's Task-dispatched, MCP-free pair). All Figma MCP querying (node-scoped get_metadata, chunked get_design_context at 6–8 calls per chunk with persist-then-discard evidence capture, get_variable_defs, per-frame get_screenshot at 1x; hard cap max_figma_nodes=20) happens in this session, directed by the adopted design-spec-writer protocol. A bounded batched Q&A round (max 2 rounds, stuck-detection converts remaining ambiguity to explicit ASSUMPTION rows) surfaces only genuinely ambiguous regions. The adopted design-spec-reviewer (invocation_context: main) runs a seven-item, MCP-free rubric and asks "Aprovar o Design Spec?" directly — only the user's own explicit reply flips the status. Exhaustion after max_spec_review_retries=2 offers retry-or-abort, never a silent loop.
Preconditions

Canonical spec shape defined in plugins/relay/resources/design-spec-template.md. Never invoked by /relay-execute. Wiring the Design Spec into plan-writer/prd-writer is a future phase's job. Pillar 3 — Commit, PR & Approval

Pillar 3 commands are triggered by the human after reviewing /relay-execute’s output and running any manual tests. Each command is local and reversible before the next one is run.

/relay-commit [feature-name | target description] implemented

Input
Two modes, resolved from the argument in Phase 0 (dual-mode since v0.16.0). Worktree mode: an argument naming an existing worktree at .worktrees/<arg>/ on branch feature/<arg> with uncommitted changes (produced by /relay-execute). Current-branch mode: no argument, or an argument that does not match a worktree — the argument is then a natural-language target description (e.g. only docs, except lockfile), applied to the current repo/branch.
Output
A single local git commit (no push, no network operation). Worktree mode: message feat(<feature>): <prd-title> sourced from PRPs/reports/<feature>/orchestrator-run.json + the PRD first heading (fallback feat(<feature>): implement via relay); output shows hash, branch, and “Next: /relay:relay-pr <feature>”; clean worktree exits 0 with “Nothing to commit”. Current-branch mode: a conventional-commit message inferred from the staged diff; output shows hash, branch, and file count; clean tree exits 0.
Mode
Worktree mode is a deterministic infra path (no LLM, no agent, no prompts) scoped via git -C .worktrees/<feature>/. Current-branch mode uses inline judgment (no agents): it reviews the diff, interprets the target description to scope staging, and flags files that probably should not be committed (secrets, build artifacts, editor cruft, debug scaffolding) — asking the operator to exclude / commit anyway / abort before committing. Neither mode pushes; neither passes --no-verify; pre-commit hooks run. See plugins/relay/commands/relay-commit.md.
Preconditions
Phase 0 routing: an existing .worktrees/<arg>/ selects worktree mode (then branch must be feature/<arg> — FAILED_WRONG_BRANCH showing actual vs expected); otherwise current-branch mode — a non-matching argument is treated as a target description and does not HALT. Both modes exit 0 on a clean tree.

/relay-pr <feature-name> implemented

Input
Worktree branch with a committed implementation (produced by /relay-commit), green tests, and all reviews APPROVED.
Output
Branch pushed to origin (if not already ahead); pull request opened on GitHub via gh pr create; PRPs/reports/<feature>/final-report.md embedded as the PR description.
Mode
Deterministic infra command (no LLM, no agent, no writer/reviewer split). Pure git + gh operations scoped to the worktree via git -C .worktrees/<feature>/. Idempotent: existing-PR detection via gh pr list --head feature/<feature> --state open --json url exits 0 with the existing URL; non-forced push (never --force) is a no-op when local matches remote. See plugins/relay/commands/relay-pr.md.
Preconditions
P0: argument non-empty; .worktrees/<feature>/ exists (FAILED_MISSING_WORKTREE) on branch feature/<feature> (FAILED_WRONG_BRANCH); clean working tree (FAILED_UNCOMMITTED_CHANGES — run /relay-commit first); test-review gate enforced only when run.json exists (FAILED_TEST_REVIEW_NOT_APPROVED); non-fast-forward push halts (FAILED_BRANCH_DIVERGENCE).

/relay-approve <pr> implemented

Input
PR number or URL (the merged PR from /relay-pr).
Output
PR merged via gh pr merge <pr> --merge; branch + worktree deleted in collision-safe order (git worktree remove → git branch -d → git push origin --delete → git worktree prune, avoiding the cli/cli #13380 trap); docs/ knowledge base updated and committed on the base branch (docs(<feature>): sync knowledge base post-merge) after the Docs Updater + Docs Reviewer agents approve the manifest. The docs cycle self-skips when docs_sync: false in docs/context/methodology.md (the same master switch shared with the implement-time dispatch); when it runs, it is idempotent against a worktree already synced at implement time.
Mode
Deterministic infra command (no LLM, no writer/reviewer split at the command level). All docs interpretation is delegated to the dispatched docs-updater (writer) and docs-reviewer (reviewer) agent pair. Supports --strategy merge|squash|rebase, --admin, --force, --no-docs flags. See plugins/relay/commands/relay-approve.md.
Preconditions
P0: argument non-empty; FAILED_GH_AUTH (gh not authenticated); FAILED_PR_NOT_FOUND (PR does not exist); FAILED_NOT_A_RELAY_FEATURE (PR not associated with a relay feature branch); FAILED_PR_NOT_MERGEABLE (PR not in a mergeable state); FAILED_UNCOMMITTED_CHANGES (worktree has uncommitted changes); FAILED_MERGE (gh pr merge failed); FAILED_DOCS_REVIEW_BUDGET_EXCEEDED (Docs Reviewer retries exhausted); FAILED_DOCS_PUSH_BLOCKED (protected base branch; docs commit kept local).

Preconditions (every command)

Every command validates its input at entry and halts loud with an actionable message if something is missing — never silent failure.

  • Review commands require the target artifact to exist with the expected status in its frontmatter or structure.
  • /relay-implement requires plan APPROVED and a checked-out worktree.
  • /relay-test requires worktree commits plus .claude/settings.json with the allowlist (otherwise the autonomous run would hit permission prompts).
  • /relay-pr requires the last /relay-test-review verdict to be APPROVED.
  • /relay-test-review requires a run.json with outcome: GREEN — running the post-green review on a non-green state is meaningless.

Artifact paths (always)

All command outputs land under PRPs/ at the target-repo root:

PRPs/
├── prds/<feature>.prd.md
├── plans/
│   ├── <feature>-phase-<N>-<slug>.plan.md       # DRAFT or APPROVED
│   ├── <basename>.review.jsonl                  # plan-reviewer audit log
│   ├── <basename>.code-review.jsonl             # code-reviewer audit log
│   ├── <basename>.test-write-review.jsonl        # test-reviewer audit log
│   └── completed/
│       └── <feature>-phase-<N>-<slug>.plan.md   # IMPLEMENTED (archived by /relay-implement)
└── reports/<feature>/
    ├── run.json                                 # /relay-test outcome
    ├── test-review.json                         # /relay-test-review verdict
    ├── final-report.md                          # /relay-pr report (planned)
    ├── orchestrator-run.json                    # /relay-execute audit (v0.9.0)
    ├── test-suite.diff                          # /relay-write-test suite manifest (v0.10.0; universalized v0.19.0)
    ├── attempts/<N>/                          # /relay-test per-attempt
    │   ├── record.json
    │   ├── stdout.log
    │   └── diff.patch
    └── phase-<N>/                             # /relay-implement per-phase (v0.8.0)
        ├── halt.json                            # on D8 partial failure
        └── attempts/<i>/
            ├── record.json
            └── diff.patch                       # cumulative diff vs base commit

Worktrees live at .worktrees/<feature>/ relative to the target-repo root.

Never under .claude/. Claude Code enforces hardcoded permission prompts there; writing pipeline artifacts into that directory would break the autonomous loop. See PRP artifact paths for the full reasoning.
