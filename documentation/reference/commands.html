Commands

The full slash-command surface of the relay plugin. Twelve commands plus one Pillar 3 placeholder, organized by role (writer / reviewer / infra / orchestrator). Each command is invocable on its own for testing or manual intervention; the orchestrator (/relay-execute) composes them into a full run.

The happy path

Day-to-day feature delivery only uses three commands:

/relay-prd     "a short description of the feature"   # interactive — produces approved PRD
/relay-execute PRPs/prds/<feature>.prd.md              # autonomous — drives PRD to PR
# ...review the PR, then:
/relay-approve <pr-number>                              # merge + docs update

Everything else exists for granular invocation — running a single stage for debugging, re-running a reviewer on a hand-edited artifact, or composing a custom flow.

Writers

Produce an artifact. Each writer has a corresponding reviewer (below) except /relay-prd, which merges writer and reviewer into one interactive flow.

/relay-prd — interactive PRD authoring implemented

Input
A short description of the feature, a path to a draft PRD markdown to refine (skips Q&A questions already answered in the draft), or no argument (opens with "What do you want to build?").
Output
PRPs/prds/<feature>.prd.md with status APPROVED. Filename is chosen by the writer in kebab-case from the Phase 1 content; collisions are resolved with a numeric suffix; APPROVED files are never overwritten. A review log is appended at PRPs/prds/<basename>.review.jsonl.
Mode
Interactive. Runs the 6-phase Q&A (Initiate → Foundation → Grounding → Deep dive → optional re-grounding → Decisions → Generate). Research is performed via the research-web and research-codebase subagents during the GROUNDING phase.
Refuses
Operating on a file whose current status is APPROVED. The user is instructed to manually flip the file back to DRAFT (or copy/rename) to start a new authoring session against it.
Agents
Delegates the 6-phase flow to prd-writer; delegates rubric validation and the DRAFT→APPROVED flip to prd-reviewer.
Notes
The only command on the interactive side of the interactivity boundary. Always runs the PRD Reviewer at the end; the PRD is not persisted as APPROVED until the reviewer's 7-item rubric passes and the user explicitly approves in dialogue.

/relay-plan <prd-path>

Input
A PRD file with status APPROVED.
Output
PRPs/plans/<feature>.plan.md with status DRAFT (awaiting /relay-plan-review).
Mode
Autonomous.

/relay-tdd <plan-path> opt-in

Input
An approved plan.
Output
Test files committed to the worktree (framework-native). The suite is red at this stage — the Implementer hasn't written the production code yet.
Mode
Autonomous, opt-in. Activated only when docs/context/methodology.md declares tdd: true. When tdd: false, silently self-skips.
Notes
Reads the PRD's Acceptance Criteria section to derive tests. Never writes production code.

/relay-implement <plan-path> implemented

Input
A plan ending with *Status: APPROVED* whose source PRD's Implementation Phases row N has Status: in-progress. The plan's Step-by-Step Tasks, Validation Commands Levels 1–3, Files to Change, and Acceptance Criteria are the rubric's structural inputs.
Output
Working tree carries the implementation diff against the base commit. On APPROVED rubric: plan trailing block flipped to *Status: IMPLEMENTED*, plan moved to PRPs/plans/completed/<basename>.plan.md, source PRD row N flipped from in-progress to complete. On HALT: structured halt.json with attempt history at PRPs/reports/<feature>/phase-<N>/halt.json.
Mode
Autonomous.
Notes
Internal writer↔reviewer loop dispatching the implementer agent (writes code via Edit/Write directly in the working tree) and the code-reviewer agent (three-layer rubric: structural / static / semantic + R-X universal test-modification guard) once per attempt. Bounded by max_implement_retries=3 (4 attempts total), max_implement_minutes=45 (wall-clock; first-to-expire-wins), max_disputes_per_session=2 (TEST_CONTRACT_DISPUTE escape valve cap; arbitration mode resolves with DISPUTE_REJECTED/DISPUTE_UPHELD_TEST_WRONG/DISPUTE_UPHELD_PRD_AMBIGUOUS). Oscillation detection always-on. Per-attempt cumulative diff.patch at PRPs/reports/<feature>/phase-<N>/attempts/<i>/. D8 post-approval mutations are best-effort atomic with rollback note on partial failure. Name chosen to match prp-implement from the upstream prp-core plugin. See PRPs/prds/implementation-authoring.prd.md.

Reviewers

Validate an existing artifact. Reviewers accept hand-edited artifacts — if you edit a plan manually and want to re-validate, /relay-plan-review is the right tool. Reviewers never modify the artifact; they emit APPROVED or CHANGES_REQUESTED with an actionable list.

/relay-plan-review <plan-path>

Input
A plan in DRAFT status (from /relay-plan or hand-edited).
Output
Plan status flipped to APPROVED, or CHANGES_REQUESTED with a list of concerns.

/relay-tdd-review <suite-path> opt-in

Input
A TDD suite in DRAFT.
Output
APPROVED or CHANGES_REQUESTED. Self-skips when tdd: false.
Notes
Specifically looks for tests that mirror imagined implementation, mocks that hide behavior, trivial asserts, and gaps against the PRD's Acceptance Criteria.

/relay-code-review <plan-path> implemented

Input
A plan path resolving to PRPs/plans/<basename>.plan.md (status *Status: APPROVED*, mid-implementation review) or PRPs/plans/completed/<basename>.plan.md (status *Status: IMPLEMENTED*, post-implementation re-review after a hand-edit). A working-tree diff against the base branch is required (P3 precondition).
Output
APPROVED or CHANGES_REQUESTED appended to PRPs/plans/<basename>.code-review.jsonl. The plan trailing block is byte-identical before and after the command runs, regardless of verdict.
Mode
Autonomous, single-shot.
Notes
Standalone single-shot dispatch of the code-reviewer agent in mode: 'standard'; no internal loop, no retries, no per-attempt diff.patch artifact, no D8 mutations. Critical architectural divergence from /relay-plan-review: this command surfaces the verdict and exits without auto-flipping plan status — D8 mutations (plan trailing-block flip, plan move to completed/, source PRD row N flip) are exclusively /relay-implement's responsibility per source PRD AC-12 + D5 + D8. Read-only counterpart to /relay-implement's mutation-triggering autonomous loop, for hand-invoked review where no automated state transition is desired. Closest external precedent is Cloudflare's AI code review architecture (sub-reviewers emit findings; coordinator alone mutates state) and GitHub's Comment PR review type (verdict without approval signal). See PRPs/prds/implementation-authoring.prd.md.

/relay-test-review <worktree> implemented

Input
A worktree with a green test state (requires run.json with outcome: GREEN).
Output
PRPs/reports/<feature>/test-review.json with verdict (APPROVED or CHANGES_REQUESTED) and concerns list.
Detects
Removed test functions, newly-added skip markers, trivial assertion downgrades, coverage drops > 5% when baseline is available.
Flags
--base <branch> — base branch to diff against (default main or master).

Infra & execution

/relay-worktree <feature-name>

Input
Feature name.
Output
Worktree at .worktrees/<feature>/ + branch feature/<name>.

/relay-test <worktree> implemented

Input
A worktree with pending code changes.
Output
Green state, or one of: FAILED_AFTER_N_RETRIES, FAILED_TIME_BUDGET_EXCEEDED, FAILED_OSCILLATION, FAILED_INFRA_UNRECOVERABLE.
Produces PRPs/reports/<feature>/run.json plus per-attempt record.json and stdout.log.
Encapsulates
B1 (Test Runner agent), B2 (structured output), B3 (failure classification), B4 (auto-correction loop with retry and oscillation detection).
Flags
--max-retries N override retry budget (default 3).
--max-minutes M override time budget (default 30).
--tier unit|integration|e2e force a layer.
--feature <name> override feature slug (defaults to current branch).
Agent
Delegates per-attempt execution to the test-runner agent.

/relay-pr <feature-name>

Input
A worktree with green tests and all reviews APPROVED.
Output
Pull request opened on GitHub. PRPs/reports/<feature>/final-report.md embedded as the PR description.
Notes
Invokes scripts/generate-final-report.mjs to produce the report Markdown. Uses gh CLI under the hood.

Orchestrator

/relay-execute <prd-path> implemented

Input
An approved PRD.
Output
Opened PR, or a HALT code with diagnostic. Audit artifact at PRPs/reports/<feature>/orchestrator-run.json.
Composes
/relay-plan → /relay-plan-review → /relay-worktree → /relay-tdd → /relay-tdd-review → /relay-implement → /relay-code-review → /relay-test → /relay-test-review → /relay-pr.
Loop behavior
Each writer/reviewer pair loops on CHANGES_REQUESTED until approved or the stage's retry budget is exhausted. Any unrecoverable abort is surfaced with the underlying command's exit reason.
Notes
Dispatch model (D7): inline Read-based command-protocol adoption — the LLM reads each downstream command file and executes its protocol in the same conversation context. No sub-agents spawned at the orchestration layer; zero logic duplication.

State machine (D6): the source PRD's Implementation Phases table is the canonical state machine. Row Status cells (pending / in-progress / complete) are the authoritative phase-state. Re-invocation after a halt is idempotent — the table is re-read on every invocation; complete rows are skipped automatically.

Orchestration budgets (D3): two session-level budgets: max_plan_review_retries (caps the plan→plan-review loop on repeated CHANGES_REQUESTED) and max_orchestrator_minutes (wall-clock; first-to-expire wins). Each downstream command retains its own internal loop budget unchanged.

HALT outcome codes (7): FAILED_PLAN_REVIEW_BUDGET_EXCEEDED, FAILED_ORCHESTRATOR_TIME_BUDGET_EXCEEDED, FAILED_TEST_REVIEW_REJECTED, plus four propagated from /relay-implement (FAILED_AFTER_N_RETRIES, FAILED_TIME_BUDGET_EXCEEDED, FAILED_OSCILLATION_DETECTED, FAILED_DISPUTE_CAP_EXCEEDED) and one from /relay-test (FAILED_INFRA_UNRECOVERABLE).

TDD routing: B7/B8 TDD pair is dead-code in MVP — D5 routing decision reserved; /relay-tdd and /relay-tdd-review self-skip when tdd: false.

Name deliberately distinct from /relay-implement (which is the code-writing stage) to avoid collision.

Pillar 3 — Approval

/relay-approve <pr>

Input
PR number or URL.
Output
PR merged, branch + worktree deleted, docs/context/ and docs/domain/ updated by the Docs Updater, ambiguities flagged by the Docs Reviewer.
Status
Placeholder — not yet implemented. Name is subject to change when Pillar 3 lands.

Preconditions (every command)

Every command validates its input at entry and halts loud with an actionable message if something is missing — never silent failure.

  • Review commands require the target artifact to exist with the expected status in its frontmatter or structure.
  • /relay-implement requires plan APPROVED and a checked-out worktree.
  • /relay-test requires worktree commits plus .claude/settings.json with the allowlist (otherwise the autonomous run would hit permission prompts).
  • /relay-pr requires the last /relay-test-review verdict to be APPROVED.
  • /relay-test-review requires a run.json with outcome: GREEN — running the post-green review on a non-green state is meaningless.

Artifact paths (always)

All command outputs land under PRPs/ at the target-repo root:

PRPs/
├── prds/<feature>.prd.md
├── plans/<feature>.plan.md
└── reports/<feature>/
    ├── run.json
    ├── test-review.json
    ├── final-report.md
    └── attempts/<N>/
        ├── record.json
        ├── stdout.log
        └── diff.patch

Worktrees live at .worktrees/<feature>/ relative to the target-repo root.

Never under .claude/. Claude Code enforces hardcoded permission prompts there; writing pipeline artifacts into that directory would break the autonomous loop. See PRP artifact paths for the full reasoning.
