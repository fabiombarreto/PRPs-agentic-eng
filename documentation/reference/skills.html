Skills

Claude Code skills are loaded on demand — they're reusable capabilities that agents can invoke when a task matches their description. relay ships one foundational skill: context-builder. This page documents it in detail.

context-builder

Path
plugins/relay/skills/context-builder/SKILL.md
Invocation
Typed by the user in a Claude Code session as a skill — typical pattern: *init, *update, *validate, *domain, *libs, or *gate.
Role
Initialize (or update) a target project's documentation tree — the docs/ hierarchy, the CLAUDE.md context file, the .claude/settings.json permission list, and the PRPs/redaction-extensions.txt.
Status
shipped

Invocation modes

ModeTriggerWhat it does
Init*initFull setup: validate MCP Context7 → scan project → generate all tiers + docs/context + docs/domain + docs/libs + .claude/settings.json + PRPs/redaction-extensions.txt.
Update*updateRe-scan; preserve human-validated content; add missing files only. Safe to re-run.
Validate*validateCheck size limits and anti-pattern violations only. No file writes.
Domain*domainRe-scan and rebuild docs/domain/ only.
Libs*libsRe-fetch library docs via Context7 MCP and rebuild docs/libs/.
Gate*gateRegenerate docs/decision-gate.md and its satellite files.

Phases

The skill runs in ordered phases. Each phase has explicit Init behavior and Update behavior.

Phase 0 — Validate mode and environment

  • Check Context7 MCP availability. If absent, set SKIP_LIBS=true and warn.
  • Init only: if artifacts already exist, prompt [R] Recreate | [U] Switch to update | [S] Skip.
  • Update mode: no prompt — the mode itself signals preservation intent.

Phase 1 — Project scan

Reads package manifests (package.json, pyproject.toml, Gemfile, Cargo.toml), README, folder structure 2 levels deep, config files (docker-compose.yml, CI configs), 3–5 representative code files per layer, migration files or DB schema, route files. Identifies: project type, stack, main domain areas, integrations, test patterns.

Phase 1.5 — Generate .claude/settings.json

Reads the canonical allow/deny catalog (docs/context/settings-allowlist.md in the relay plugin repo via ${CLAUDE_PLUGIN_ROOT}), emits narrow allow patterns matched to Phase 1's stack signals, plus the invariant denylist. Refuses to emit broad patterns (Bash(*), Bash(git *), etc.).

Phase 1.75 — Create PRPs/redaction-extensions.txt

Always-created empty template with a header comment explaining the format. Teams add per-project secret name patterns or value regex here. Never overwritten in *update mode.

Phase 2 — Create docs/context

Generates 5 files: architecture.md, conventions.md, integrations.md, constraints.md, methodology.md. Each inferred from the Phase 1 scan with [INFERRED - VALIDATE] markers where the skill couldn't be confident. methodology.md defaults to tdd: false regardless of signals — heuristic activation is an anti-pattern.

Phase 3 — Create docs/domain

The most critical inference phase. Produces glossary.md, flows.md, and one areas/<area>.md per business area detected. Every inferred rule gets a [INFERRED - VALIDATE] marker; all uncertain items collect into an "Open Questions" section at the bottom of each area file.

Phase 4 — Create docs/libs

Via Context7 MCP. For each main project dependency, fetches version-specific usage patterns and gotchas. Skipped when Context7 is unavailable (SKIP_LIBS=true).

Phase 4.5 — Create docs/decision-gate.md and satellites

Three files with strict update semantics:

  • decision-gate.md — fixed template; dynamic area-row inserts.
  • decisions.md — populated with inferred decisions marked [INFERRED - VALIDATE]. In update mode: preserved entirely if file has substantive entries.
  • anti-patterns.md — same protocol as decisions.md.

Phase 5 — Tier 3 developer docs

Generates docs/architecture.md, development.md, api-reference.md, troubleshooting.md. Update-mode: preserved if exist.

Phase 6 — Tier 2 KNOWLEDGE_BASE.md

TOC with one entry per doc file. Update-mode: scans existing KB, appends missing required entries, preserves existing summaries (which may be hand-edited).

Phase 7 — Tier 1 CLAUDE.md

Project summary + stack list + essential commands + top 3 patterns + Context & Domain section. Hard size limit: < 95 lines, < 2000 tokens. Update-mode: preserves hand-edited commands/patterns/stack; only appends missing Context & Domain pointers.

Phase 8 — Final Report

Structured report printed to the user with:

  • Files created / updated / preserved
  • Domain areas identified
  • Methodology declaration state
  • Autonomous-pipeline permissions summary
  • Items requiring human validation (all [INFERRED - VALIDATE] markers)
  • Open questions from domain area files
  • Detected drift (update mode only)
  • Skipped stages with reasons
  • .gitignore follow-ups (for first-run)

Invariants

  • Size limits on Tier 1 (< 95 lines, < 2000 tokens) and Tier 2 (< 100 lines, < 1500 tokens). Tier 3 is unbounded.
  • Plain text paths only in Tier 1 and 2 — no @ triggers that bloat the context window.
  • No [INFERRED - VALIDATE] markers in Tier 1 or 2 — they belong only in Tier 3 and domain area files.
  • Never activate TDD heuristically. methodology.md defaults to tdd: false.
  • Business rules belong in docs/domain/areas/, not in CLAUDE.md.

Extending the skill

The skill is a single Markdown file with a YAML frontmatter and a long body. Editing it requires care:

  • Every phase must declare explicit Init behavior and Update behavior subsections.
  • Any new artifact path must be added to the Extended Folder Structure at the top of the file.
  • Any new catalog referenced in ${CLAUDE_PLUGIN_ROOT} must be documented in the "Relay catalog discovery" section.

If a change to the skill breaks the update-mode protocol (e.g., overwrites human-validated content), it's a critical bug — the skill's value depends on being safe to re-run.
