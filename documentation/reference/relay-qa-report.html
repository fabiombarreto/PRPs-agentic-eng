QA report

/relay-qa-report is the human-facing QA / Support command that sits in the validation gate between Pillar 2 (/relay-execute) and Pillar 3. It enumerates test cases — automated, manual, or missing coverage — so a human can drive manual testing before committing and opening a PR. It is a single LLM-judgment tool with no writer/reviewer pair and is never called by the autonomous orchestrator.

/relay-qa-report [<prd-path> | <plan-path> | <description>] (blank = uncommitted diff) implemented

Input
Four-way argument router (Phase 0): a .prd.md path enters PRD mode (cases derived from the PRD's Acceptance Criteria section); a .plan.md path enters plan mode (cases derived from the plan's Step-by-Step Tasks + Validation Commands); non-empty free text enters description mode (cases derived from the uncommitted diff read through the description as scope, or from the description itself on a clean tree); blank enters diff mode (cases derived from git status --porcelain plus git diff on the current branch). <feature> is derived per mode — the PRD basename, the plan filename's <feature> segment (everything before -phase-<N>-, or the full slug for a flat description-mode plan), or the current branch slug with any feature/ prefix stripped, falling back to a kebab-cased slug of the description.
Output
PRPs/reports/<feature>/qa-report.md — the only file this command ever writes. One entry per case, each carrying all seven fields of the report schema below; uncovered cases are listed explicitly, never omitted.
Mode
Single LLM-judgment command with no writer/reviewer pair — the human performing manual QA is the validator, not a reviewer agent. Read-only over the repository except for the one report it writes. Never invoked by /relay-execute; it lives in the human validation gate between Pillar 2 and Pillar 3, not inside the autonomous loop.
Report schema
Seven fields per case: title; risk level (Critical / High / Medium / Low, probability × severity); required state (the DB entities and values needed to exercise the case, or "none"); coverage (automated / manual / none); automated test path (every cited path verified with test -f before citing — never invented; unconfirmed coverage marked unverified); manual status (pending on first generation, updated only conversationally afterward); and a manual step-by-step (setup, action, expected result). A single automated or manual test MAY cover several cases — there is no forced 1:1 mapping.
Refuses
Silently overwriting an existing qa-report.md — an anti-overwrite HALT requires explicit operator confirmation before regenerating, so manual statuses already recorded are never silently discarded. In diff mode, a clean working tree HALTs with FAILED_NOTHING_TO_REPORT and writes no file.
Notes
Grounds the automated-coverage column in PRPs/reports/<feature>/record.json (or the latest per-attempt attempts/<N>/record.json) — the Test Runner's schema v1 — when present, citing its file/line fields directly. When absent, infers coverage by searching the repo's test files and marks entries that cannot be confirmed unverified. Never runs, authors, or modifies a test; never writes under .claude/. See PRPs/prds/relay-qa-report-command.prd.md.

Argument router in detail

Phase 0 of the command trims $ARGUMENTS and routes on its shape — mirroring, and extending to four branches, the suffix-based mode detection /relay-plan uses for its two-way PRD/description split.

PRD mode
Argument ends with .prd.md. Cases come from the PRD's ## Acceptance Criteria section — each Acceptance Criterion becomes at least one report entry. <feature> is the PRD basename with the extension stripped.
Plan mode
Argument ends with .plan.md. Cases come from the plan's ## Step-by-Step Tasks (each task's ACTION + VALIDATE) and ## Validation Commands sections. <feature> is the filename segment before -phase-<N>-, or the full slug for a flat description-mode plan filename.
Description mode
Any other non-empty argument. Treated as scope: on a dirty working tree, cases come from git diff (and git diff --staged) interpreted through the description; on a clean tree, cases come directly from the description as a freeform list. There is no clean-tree HALT here — FAILED_NOTHING_TO_REPORT is diff-mode-only.
Diff mode
Blank argument. Cases come from git status --porcelain plus git diff (unstaged) and git diff --staged (staged) on the current branch — everything uncommitted. A clean tree HALTs with FAILED_NOTHING_TO_REPORT and creates no file.

Honesty guarantee and coverage grounding

Any case covered by neither an automated nor a manual test still appears in the report, explicitly marked coverage: none. The entry is never silently dropped to make the report look complete — hiding a coverage gap is the exact anti-pattern this command exists to counter.

Before inferring coverage from repo test files, the command checks whether PRPs/reports/<feature>/record.json exists. When it does, coverage and automated-test-path fields are grounded in its failures[] entries and counts rather than re-derived. When it is absent — for example a project with test_frameworks: [], or a manual-only implementation — the command infers coverage from the repo's test files and marks anything it cannot confirm unverified rather than asserting confident coverage it does not have.

HALT conditions

FAILED_NOTHING_TO_REPORT
Diff mode only. The working tree is clean — there is nothing uncommitted to report on. Creates no file. Re-run after making changes, or pass an explicit .prd.md path, .plan.md path, or free-text description.
Anti-overwrite HALT
All modes. Fires when PRPs/reports/<feature>/qa-report.md already exists. Regenerating without confirmation would silently discard any manual statuses already recorded there; the command waits for explicit operator confirmation before overwriting within the same invocation.
Feature-slug derivation HALT
Description and diff modes. Fires when neither the current branch nor the description text yields a usable slug (detached HEAD, a generic branch name, and no alphanumeric description text).
Not part of the autonomous loop

/relay-qa-report is invoked by the human, standalone, after /relay-execute completes and before Pillar 3 (/relay-commit → /relay-pr → /relay-approve). See the Commands reference for the full pipeline surface.
